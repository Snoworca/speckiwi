# v2.3.0 Tool Improvement Implementation Plan

## §1 개요

### 1.1 목표

Make SpecKiwi v2.3.0 reliable enough that agents prefer official CLI and MCP tools over raw Markdown or JSONL edits for SRS reads, mutations, diagnostics, workflow artifacts, and Kiwi execution state.

### 1.2 범위 (in_scope[])

- Active target v2.3.0 active REQs: 54.
- Included statuses: planned and verified research anchor.
- Included Stability values: evolving and stable.
- Tool surfaces: core parser/query/mutation/workflow services, CLI commands, MCP tools/resources, package doctor gates, managed instructions, and Kiwi skill migration.
- Current plan expands the first draft from 9 broad phases to 18 smaller phases so kiwi-coder/PM can execute each cluster without hidden cross-phase blockers.

### 1.3 제외사항 (out_of_scope[], excluded_reqs 포함)

- Discarded requirements are excluded from execution: FR-MCP-025, FR-MCP-026, FR-MCP-027, FR-MCP-028, FR-MCP-029, FR-MCP-033, FR-MCP-036, FR-NODE-022, FR-NODE-023, FR-NODE-024, FR-NODE-025, FR-PARSE-020, IR-CLI-033, IR-CLI-034, IR-CLI-035, IR-CLI-036, IR-CLI-039, REL-NODE-004.
- General Requirement ID beautification, gap filling, arbitrary renumbering, bulk archive, bulk finalize, physical JSONL deletion, restore/undelete, and non-tool product expansion are out of scope.

### 1.4 전제조건 / 가정

- docs/spec remains the only canonical requirements source.
- kiwi/.status.json is a disposable derived cache and never releases kiwi/.srs.lock.
- MCP is the normal SRS mutation path; CLI parity is implemented for fallback and user workflows.
- REL-FLOW-002 signature parity lands before duplicate-ID repair workflow documentation or skill migration references new runtime tools.
