## 2. `_shared/kiwi/waves-event.md` (4사본) — v1.3.0

### 2.1 제목 / 버전

- 1행 `# kiwi waves event v1.2.0` → `# kiwi waves event v1.3.0`
- §5 Emit 패턴의 모든 JSON 예시 `"schema_version":"1.2.0"` → `"1.3.0"`
- 그 밖에 `"schema_version":"1.0.0"` / `"1.1.0"` / `"1.2.0"` 리터럴이 남아 있으면 안 된다.

### 2.2 §2.2 선택 필드 — 신규 2행 (R2-M1 · R2-M4)

기존 행은 전부 유지하고 아래 2행을 **선택 필드 표에만** 추가한다(필수 표로 올리면 breaking).

```
| `diff_window` | object | `{ base_sha, head_sha }` — 그 wave 의 diff 창을 여는 git ref 쌍 (v1.3.0 신설) |
| `pipeline_run_ids` | string[] | 그 wave 에서 실행한 **모든** `/kiwi-pipeline` run_id 를 순서대로. `pipeline_run_id` 는 그중 최신 값을 그대로 유지한다(하위호환) (v1.3.0 신설) |
```

`pipeline_run_ids` 규칙 문장(같은 절, 1줄. 테스트는 `pipeline_run_ids` 와 `전량|모든` 이 같은 줄에 있고
그 줄이 `pipeline_run_id` 도 언급하기를 요구한다):

> 증거 창은 `pipeline_run_ids` 의 **모든** run 을 합집합으로 연다 — `pipeline_run_id` 하나만 보면 재진입이 만든 새 run 의 산출물이 창 밖으로 떨어져, 수정 전 증거로 재검증하거나 낡은 clean 증거로 통과한다.

### 2.3 §2.3 `verification` object — 신규 3행 + `preservation_layer` 확장

기존 행은 유지하고 아래 3행을 추가한다.

```
| `constraint_layer` | object | `{ expected: n, checked: n, violations: [...] }` — 선언된 사용자 제약 분모 (v1.3.0 신설) |
| `frozen_denominator` | object | `{ round: n, req_ac: n, design_items: n, preservation: n }` — 그 라운드 진입 시 freeze 한 분모 개수 (v1.3.0 신설) |
```

`regression` 행의 **값 셀**에 baseline 키를 추가한다(셀 안에 `baseline_failing_tests` 문자열이 있어야 한다).

```
| `regression` | object | `{ command, exit_code, failing_tests: [...], baseline_failing_tests: [...] }` — 그 wave 의 head 에서 실행한 전체 회귀 스위트와 run 시작 시 pin 한 기준선 |
```

`preservation_layer` 행의 **값 셀**에 `evidence` 를 추가한다(R2-M16).

```
| `preservation_layer` | object | `{ expected: n, checked: n, rows: [{ item, verdict, evidence }] }` — 행마다의 `verdict` ∈ `intended-improvement` / `unapproved-damage`, `evidence` 는 그 판정의 근거 REQ-ID 또는 Task-ID |
```

이어서 아래 규칙 문장들을 **각각 한 줄로** 넣는다(테스트가 줄 단위로 앵커한다).
모든 줄에 헤지 어휘(`수 있다`/`해도 된다`/`권장`/`바람직`/`원칙적으로`/`가능하면`/`되도록`/`경우에 따라`/`가급적`)를 쓰지 않는다.

- **R2-C2 보존 게이트** — `design_layer.unmapped` 규칙 **바로 뒤**에, 같은 형식으로:
  > `preservation_layer.rows` 에 `verdict` 가 `unapproved-damage` 인 행이 **1건이라도** 있으면 `verdict` 를 `pass` 로 기록하지 않는다 — 파손을 정직하게 기록한 것이 통과를 막지 못하면 그 계층은 기록 전용이다.
- **R2-H5 델타 규칙** — 기존 `regression.exit_code` 줄 **앞**에:
  > `regression.failing_tests` 가 `baseline_failing_tests` 의 부분집합이 아니면(`failing_tests ⊆ baseline_failing_tests` 위반, 즉 **신규 실패 0 건**이 아니면) `verdict` 를 `pass` 로 기록하지 않는다.
- **R2-H5 fallback** — 기존 `regression.exit_code` 줄을 아래로 **교체**한다. 기존 단언(`verdict`·`pass` 동반 + 무헤지)은 그대로 만족한다:
  > 기준선 **캡처에 실패**해 `baseline_failing_tests` 가 부재한 라운드에서는 `regression.exit_code` 가 0 이 아니면 `verdict` 를 `pass` 로 기록하지 않는다 — 기준선이 없으면 신규 실패를 분리할 수 없다.
- **R2-H10 제약 게이트**:
  > `constraint_layer.violations` 에 **1건이라도** 항목이 있으면 `axis_a.roll_up` 을 `ALL_MATCH` 로 기록할 수 없다 — 제약 위반은 요구 실현 여부와 별개의 실패다.
- **R2-H10 빈 배열**:
  > 제약이 선언되지 않은 run 도 **빈 배열** 아티팩트를 쓰고 `constraints_path` 를 기록한다 — 빈 배열은 반증 가능한 주장이고 필드 부재는 침묵이다.
- **R2-C3 설계 분모 고정**:
  > `design_layer.expected` 는 그 wave 의 `design_items` 길이로 외부에서 고정하며, 검증자가 스스로 산정하지 않는다.
- **R2-M5 freeze** — 기존 "행 수" 무효 규칙 줄을 아래로 **교체**한다(기존 단언인 `두 검증자 **모두**` · `**무효**` 는 유지):
  > 열거한 **행 수**가 `frozen_denominator` 에 기록된 고정 분모의 개수와 다른 라운드는 두 검증자 **모두**에 대해 **무효**이며, cap 은 소비하되 연속 clean 스트릭은 0 으로 되돌린다.

### 2.5 §3 status 전이 — run-scope 예외와 실패 status (R2-M12 · R2-L4)

기존 검증 게이트 문단은 그대로 두고 그 **끝에** 아래 문장을 붙인다.

> 이 게이트는 `wave="all"` 인 run-scope 이벤트에는 **적용하지 않는다** — run-scope 에는 자기 wave 의 wave-verify 기록이 원리적으로 존재하지 않아 항상 무효가 된다. run-scope 완료의 선행 조건은 §4 의 최종 검증 술어다.

run-scope 문단 뒤에 실패 status 규정 1줄:

> `final-verify` 이벤트가 **통과하지 못한** 경우 그 이벤트의 `status` 는 `failed` 로 쓴다 — `complete` 는 통과한 최종 검증에만 쓴다.

### 2.6 §4 재개 규약 — run 스코프·run 선택·도달불가 탐지 (R2-C1 · R2-M6)

§4 첫 문장을 아래로 **교체**한다.

> `waves.jsonl` 에서 **현재 run 의 `run_id` 와 일치하는 이벤트만**을 골라 각 wave 의 **마지막(latest)** 이벤트 status 를 계산한다. 이 계산에서 `wave="all"` 인 run-scope 최종 검증 이벤트는 **제외**한다(§3) — 그것은 어느 wave 의 상태도 아니다:

(`wave="all"` 제외 문장은 그대로 남겨야 한다 — 기존 단언이 그 문장을 읽는다. 다만 그것을 **유일한 필터**로
서술하는 표현(`필터는 … 하나뿐` / `유일한 필터`)은 쓰지 않는다.)

이어서 아래 3문장을 §4 안에 각각 한 줄로 넣는다.

- **run 선택**:
  > 재개 대상 run 은 `complete` 로 끝나지 않은 **가장 최근 미완료** run_id 이며, 호출자가 `--run-id` 로 **명시**하면 그것이 우선한다.
- **버전 면제 금지**:
  > 본 run 스코프 조항에는 **버전 면제를 두지 않는다** — 면제는 다른 run 의 `complete` 를 자기 것으로 읽는 경로를 그대로 남기고, 그 오독은 구현 0건으로 전체 완료를 보고한다.
- **R2-M6 도달불가 탐지**:
  > 재개 시점에 **남은 라운드** 수(`cap - rounds`)가 그 모드의 연속 clean **스트릭** 요구치보다 작으면 PASS 가 산술적으로 불가능하므로, 라운드를 더 돌지 않고 `verdict` 를 `fail-cap` 으로 기록하고 사용자 결정을 받는다.

**금지**: cap 을 연장하거나 통과 스트릭을 영속시키는 우회를 §4 어디에도 쓰지 않는다
(`cap 을 연장` / `cap 을 늘린다` / `스트릭을 … 영속` 문구 금지). 기존의 `통과 verdict 는 영속되지 않는다`
문단은 그대로 유지한다.

> `run-root-preflight-mismatch` · `wt-delegation-refused` · `unsafe-option-refused` 는 §2.1 이 명령하는 중단을 SSOT 인터페이스로 **전사**한 것이다. 본 표의 **모든** 게이트를 함께 선언하는 이유는, 일부만 선언하면 **선언되지 않은** 나머지 중단이 위원회 판단 대상으로 떨어지기 때문이다.

`본 표의 **모든** 게이트` 를 담기를 요구한다. 위 문장 하나가 두 조건을 동시에 만족한다.)

### 3.4 §2.1 Preflight — 회귀 기준선 캡처 (R2-H5)

기존 문단(run-root 게이트 · work-mode 판독 · 위험 옵션 거부)은 **전부 유지**하고 아래 블록을 추가한다.
`--skip-regression` / `--reviewer-off` 거부 문장은 그대로 둔다.

> **회귀 기준선 캡처**: preflight 에서 전체 회귀 스위트를 **1회** 실행해 실패 목록을 `baseline_failing_tests` 로 캡처하고, 그 값을 이 **run 전체에 pin** 한다 — wave 마다 다시 재면 앞 wave 가 만든 실패가 다음 wave 의 기준선으로 승격된다. 캡처는 kiwi-coder `state.regression_baseline` 과 같은 스위트·같은 명령을 쓰며 두 값은 하나의 SSOT 를 공유한다. 캡처 자체가 실패하면 `baseline_failing_tests` 를 부재로 두고 그 사실을 보고한다.

### 3.5 §3.1 설계 기준선 물질화 — design_items · 발췌 · 제약 · 이월 (R2-C3 · R2-H7 · R2-H8 · R2-H10)

기존 본문은 유지하고 아래를 추가한다.

**(a) design_items 물질화** (한 줄에 필드명과 5개 키를 모두):

> 같은 시점에 그 wave 범위의 설계 항목을 `design_items` 로 **전량** 고정한다 — 각 항목은 `id` · `heading_path` · `line_start` · `line_end` · `statement` 를 갖는다.

**(b) 항목 단위 규칙** (별도 한 줄, 헤지 금지):

> 항목 단위는 **최하위 헤딩 아래 규범 문장 1건 = 1 항목**이며, 예시·근거 문장은 **항목이 아니다** — 단위를 굵게 잡으면 `unmapped=0` 이 공짜가 된다.

**(c) 설계 본문 발췌** (R2-H8):

> wave 별 설계 **본문 발췌**를 `docs/analysis/kiwi-wave-master-{run_id}/design-baseline/wave-{n}.md` 로 함께 물질화하고 그 경로를 `design_baseline.excerpt_path` 에 기록한다 — 증거 번들과 저작 입력이 같은 아티팩트를 가리키게 한다.

**(d) 제약 아티팩트** (R2-H10, 한 줄):

> 사용자 제약은 **제약이 없어도 빈 배열** 아티팩트를 반드시 만들어 그 경로를 `constraints_path` 에 **항상 기록**한다 — 빈 배열은 반증 가능한 주장이고, 필드 부재는 침묵이다.

**(e) 이월 wave 의 대체 분모** (R2-H7, 한 줄):

> 이월(carry-forward)로 신설된 wave 는 입력 문서의 어느 구간에도 대응하지 않으므로, 설계 기준선 대신 **이월 finding 목록**을 그 wave 의 설계 계층 분모로 삼는다.

### 3.6 §3.2 분해 커버리지 게이트 — 대조 단위 (R2-M10)

기존 문장은 유지하고 대조 단위를 명시하는 1줄을 **추가**한다.

> **대조 단위**는 최상위 섹션 **한 겹이 아니라** §3.1 이 고정한 `design_items` **전량**이다 — 하위 절에만 있는 미배정 설계는 최상위 대조를 그대로 통과한다.

### 3.7 §4 target 등록 — 이월 수집 · 발췌 전달 · 제약 전달 · 저작 표식 (R2-H7 · R2-H8 · R2-H9 · R2-H10)

기존 본문은 유지하고 아래를 추가/교체한다.

**(a) 이월 수집** (신규, 한 줄):

> wave 진입 시 `carried_into` 가 이 wave 인 residual 을 **전량** 수집해 증분 **저작 입력**에 포함한다 — 이월된 결함은 이 wave 의 REQ/AC 분모에 들어가지 않으면 다시 검출되지 않고 조용히 종결된다.

**(b) 리서치 문서 인자 교체** (R2-H8) — 기존 `design_baseline.path` 전달 문장을 아래로 교체한다:

> 이때 `/kiwi-srs` 호출의 **리서치 문서** 인자(`--research-doc`)로 그 wave 의 `design_baseline.excerpt_path` 를 전달한다 — 좌표 매핑 JSON(`design-baseline.json`)에는 대조할 산문이 없어 리서치 검증·개선 루프가 갭을 만들지 못한다. 원본 `source_file` 도 함께 넘긴다.

(경로 동일성 문장 `전달하는 경로는 waves.jsonl 에 기록한 것과 **같은** 경로다 …` 는 그대로 유지한다.)

**(c) 제약 전달** (R2-H10, 한 줄):

> 같은 호출에 `constraints_path` 아티팩트도 전달한다 — 저작 입력에 없는 제약은 검증에서 잡혀도 반영할 근거가 없다.

**(d) 저작 표식 판정 교체** (R2-H9) — 기존 "최신 이벤트" 문장을 아래로 교체한다:

> 그 wave 의 이벤트 중 `srs_authored` = `true` 를 실은 줄이 **하나라도** 있으면 본 절과 target 등록을 건너뛰고 곧바로 pipeline 단계(§5)로 들어간다 — 저작은 이미 끝났고, 다시 돌리면 같은 요구를 두 번 저작한다. 저작을 마친 직후 `phase="srs-authoring"` 이벤트에 그 표식을 실어 append 하며, **표식 없는 줄**은 `srs-authoring` **줄만** 저작 진행 중으로 읽는다.

### 3.8 §5 per-wave pipeline — 이월 소비 (R2-H7)

§5 안에 한 줄:

> 그 wave 로 `carried_into` 된 residual 은 pipeline 재진입 범위에도 포함한다 — 저작만으로는 코드 수준 이월이 어느 Task 에도 배정되지 않는다.

### 3.9 §5.5.1 증거 번들 — 신규 3행 + 창 규정 (R2-M1 · R2-M4 · R2-M13)

기존 10행을 유지하고 아래 3행을 추가한다.

| 증거 | 내용 |
|---|---|
| 그 wave 의 **diff 창** | `diff_window` 의 `base_sha` ~ `head_sha` — 대화 상태가 아니라 `waves.jsonl` 에서 해소한다 |
| 그 wave 의 **기존 모듈** 목록 | `design_baseline` 의 `existing_modules` — 교차 wave 회귀 판정의 입력 |
| 그 wave 의 **모든 pipeline run** | `pipeline_run_ids` 전량 — 재진입이 만든 run 도 창 안에 든다 |

창 경계 문단을 아래 문장으로 보강한다.

> 증거 창은 `pipeline_run_ids` 의 **모든** run 과 `in_progress` 타임스탬프로 경계 짓는다 — 단일 `pipeline_run_id` 로 창을 열면 재진입 이후의 수정이 창 밖에 남아, **수정 전 증거**로 재검증하거나 **낡은** clean 증거로 통과한다.

### 3.10 §5.5.2 두 검증자 — 분모 4계층 (R2-C3 · R2-H10 · R2-M5 · R2-M13 · R2-M16)

기존 stance 표와 REQ/AC 분모 문단, 설계 계층 문단은 **그대로 두고** 아래를 추가한다.

- **설계 분모 외부 고정** (한 줄):
  > `design_layer.expected` 는 그 wave 의 `design_items` 길이이며 **검증자가 스스로 산정하지 않는다** — 라운드마다 분모가 갈리면 무효 판정 자체가 성립하지 않는다.
- **제약 계층** (한 줄에 필드명 + 3키):
  > 검증자 1 은 선언된 제약을 세 번째 계층으로 든다 — `constraint_layer` 에 `expected` · `checked` · `violations` 를 싣는다.
- **제약 롤업 금지** (별도 한 줄, 헤지 금지):
  > 제약 위반이 `violations` 에 **1건이라도** 있으면 `ALL_MATCH` 로 롤업할 수 **없다**.
- **기존 모듈 소비** (R2-M13, 한 줄):
  > 검증자 2 는 `existing_modules` 를 **교차 wave** 회귀 위험 판정의 입력으로 쓴다 — 기록만 되고 읽히지 않는 필드는 어떤 verdict 도 바꾸지 못한다.
- **판정 근거 규칙** (R2-M16, `intended-improvement 는` 으로 시작하는 한 줄, 헤지 금지):
  > `intended-improvement` 는 그 변경을 요구하는 **REQ** 또는 계획 **Task** 가 있을 때에만 쓰며, 그 근거를 행의 `evidence` 에 REQ-ID 또는 Task-ID 로 적는다.
- **기본값** (별도 한 줄):
  > 근거를 대지 못한 행은 `unapproved-damage` 다 — 근거 없는 재량을 남겨두면 wave 를 끝내려는 국소 이해가 그대로 verdict 가 된다.
- **분모 freeze** (R2-M5, 한 줄에 필드명 + 4키):
  > 분모는 라운드 진입 시 freeze 하고 그 개수를 `frozen_denominator` 의 `round` · `req_ac` · `design_items` · `preservation` 에 기록한다.
- **freeze 유지** (별도 한 줄):
  > 분모는 **라운드 도중** 늘어나지 않는다 — 증분 저작·수정으로 생긴 항목은 **다음 라운드** 진입에서 다시 freeze 하며, 그 재freeze 라운드는 **무효가 아니다**.

### 3.11 §5.5.4 종료 조건 — Normal 행 교체 (R2-C2 · R2-H5 · R2-M6)

Normal 행을 아래로 **교체**한다(세 사본 동일). `exit_code`=0 토큰은 fallback 절에 남으므로 기존 단언은 유지된다.

> | Normal | 병합 결과 `CRITICAL=0` + `HIGH=0` + 검증자 1 `ALL_MATCH`, **그리고 그 라운드에서 수정이 적용되지 않았을 것**, 그리고 wave head 회귀에 **신규 실패 0 건**(`failing_tests ⊆ baseline_failing_tests`), 그리고 `unapproved-damage` **0 건** |

`--max` 행의 스트릭 값(claude/codex 2, etc 3)은 **바꾸지 않는다**. etc 의 Normal 행 단서 단락도 그대로 둔다.

표 아래에 두 문장을 추가한다.

- **fallback** (한 줄, `exit_code`=0 을 담는다):
  > 기준선 **캡처에 실패**해 `baseline_failing_tests` 가 없으면 이 조건은 `exit_code`=0 으로 격하된다 — 기준선 없이는 신규 실패를 분리할 수 없다.
- **R2-M6 도달불가 탐지** (한 줄):
  > 재개 시점에 **남은 라운드**(`cap - rounds`)가 그 모드의 **스트릭 요구치**보다 작으면 PASS 가 산술적으로 불가능하므로 라운드를 더 돌지 않고 `fail-cap` 으로 기록하고 사용자 결정을 받는다.

**금지**: `cap 을 연장` / `cap 을 늘린다` / `스트릭을 영속` 같은 우회를 §5.5.4 어디에도 쓰지 않는다.

### 3.12 §5.5.5 개선 위임 — 재진입 인자와 근거 교정 (R2-H2 · R2-M3)

기존 라우팅 표와 문장은 유지하고 아래를 고친다.

**(a) 금지 문장의 근거 교정** (R2-M3) — `kiwi-tdd §0.5` 를 `kiwi-coder §0.20` 으로 바꾼다. §2.1 이 wave 사이클에서

(테스트는 `테스트를 약화하거나 삭제` 를 담은 줄에 `kiwi-coder §0.20` 이 있고 `kiwi-tdd` 가 **없기**를 요구한다.)

`phase="pipeline"` 토큰이 이 절 안에 남아야 기존 단언이 유지된다.

> wave 시작 시의 첫 `in_progress` 에는 `phase="srs-authoring"` 을 싣는다 — §4 저작이 §5 pipeline 보다 앞서므로 `pipeline` 라벨은 실제 단계와 어긋난다.
> pipeline 사이클 진입 시 `phase="pipeline"` 인 `in_progress` 를 1줄 append 한다 — 그래야 enum 멤버가 실제 이벤트로 생산된다.

### 3.14 §5.5.7 교차 wave 이월 — 모순 해소 (R2-H4)

`이전 wave 의 **요구사항을 바꿔야** 하는 finding 은 HALT 로 남는다 …` 줄을 아래로 **교체**한다.
`HALT` 토큰과 무헤지 조건은 유지되므로 기존 FR-FLOW-055 AC-2 단언은 계속 통과한다.

> 이전 wave 의 **요구사항을 바꿔야** 하는 finding 도 이월을 먼저 시도하고, 남은 wave 와 신규 wave 양쪽이 **모두 불가능할 때에만** HALT 한다 — 완료된 target 을 되돌리는 일이기 때문이다.

나머지 문장(`코드를 바꿔야` · `남은 wave 가 없으면 … 새 wave 를 추가` · `cross_wave`/`carried_into` 기록 ·
`complete` 불가역 · `첫 대응이 아니다`)은 **그대로 유지**한다.

### 3.15 §5.6 전체 wave 최종 검증 — 라우팅 절 신설 (R2-C2 · R2-C3 · R2-H4)

기존 본문은 유지하고 아래를 추가한다.

- **분모** (한 줄, `design_items` 포함):
  > 최종 패스의 설계 계층 분모는 **모든 wave** 의 `design_items` **전체**이며, 그 합집합을 모든 wave 요구사항의 합집합에 대조한다.
- **보존 조건** (한 줄, 헤지 금지):
  > 최종 패스도 `unapproved-damage` **0 건**을 통과 조건으로 요구한다.
- **회귀 축 치환** (한 줄에 `wave head` 와 `run head` 를 모두):
  > §5.5.4 의 "wave head 회귀"는 최종 패스에서 **run head** 회귀로 읽는다.
- **수정 라우팅** (신규, `run-scope finding` 으로 시작하는 한 줄):
  > run-scope finding — 어느 wave 의 scope 에도 속하지 않아 wave 로 귀속할 수 없는 것 — 은 HALT 가 아니라 §0.5 **예외**에 따라 wave-N+1 을 추가해 처리한다.
- **후속 절차** (별도 문장, `§5.6` 과 `재실행` 을 함께):
  > 추가한 wave 는 §4~§5.5 를 정상 실행하고, 그 wave 가 `complete` 로 기록된 뒤 §5.6 을 **재실행**한다.
- **자동 재진입 근거** (한 줄, `waves-event` 포함):
  > 이 재진입은 별도 장치가 아니다 — `waves-event.md` §4 의 재개 술어가 최종 검증이 통과하지 않은 run 을 이미 최종 검증으로 되돌린다.
- **실패 status** (R2-L4, 한 줄):
  > 최종 검증이 통과하지 못하면 그 이벤트의 `status` 는 `failed` 다.

### 3.16 §6 진행 추적 — run 스코프 재개 (R2-C1)

기존 문장(재개 단위 3단계 · `pipeline_run_id` 의무 · 첫 `in_progress` 필드 생략 2문장)은 **그대로 유지**하고
아래 3문장을 추가한다.

- **run 스코프** (한 줄):
  > 재개 스캔은 **현재 run 의 `run_id` 와 일치하는 이벤트만**을 읽는다 — `waves.jsonl` 은 저장소당 1개 append-only 파일이고 `wave-{n}` 은 run 간 고유하지 않다.
- **run 선택** (한 줄):
  > **재개 대상 run** 은 `complete` 로 끝나지 않은 **가장 최근 미완료** run 이며, `--run-id` 로 명시하면 그것이 우선한다.
- **교차 run 격리** (한 줄, 헤지 금지):
  > **다른 run** 의 `complete` 는 이 run 의 상태로 읽지 않는다 — 앞선 에픽을 완주한 저장소에서 새 에픽의 `wave-1` 이 앞 에픽의 완료를 자기 것으로 읽으면 구현 0 건으로 전체 완료를 보고한다.

### 3.17 §7.1 --auto — 약속 정정 (R2-H1, 분기 (b) 채택)

기존 문단은 유지하고 아래 문장을 추가한다. **`--auto` 가 두 옵션을 자식에게 부여한다고 쓰지 않는다**
(`부여한다` / `자동 활성` / `자동으로 부여` 표현 금지).

**분기 선택 사유**: findings H1 은 (a) `--auto` 가 두 옵션을 자식 체인에 부여 / (b) 옵션을 노출하고 §7.1 의
약속을 정정, 두 갈래를 제시했다. **(b) 를 채택**한다. (a) 는 사용자가 한 번도 동의하지 않은 통합 테스트 실행과
장시간 비용 소모를, 무인 실행 중에 wave 수만큼 반복 승인하는 것과 같다 — 두 게이트가 존재하는 이유 자체를
상위 계층이 조용히 무효화한다. (b) 는 무인 완주 범위를 좁히는 대신, 사용자가 위험을 알고 **명시적으로**

### 3.18 §7.2 --max — §4 직접 호출 포함 (R2-M8)

## 10. 두 갈래 제안에서 고른 쪽과 사유

findings 가 두 갈래를 제시한 것은 H1 하나다. 나머지 CRITICAL/HIGH 는 제안이 단일했고,
MEDIUM/LOW 표에는 제안 열이 없어 본 계약이 방향을 확정했다. 확정이 필요했던 지점만 적는다.

| 항목 | 고른 쪽 | 사유 |
|---|---|---|
| H1 (a) 자동 부여 / **(b) 옵션 노출 + 약속 정정** | **(b)** | (a) 는 사용자가 한 번도 동의하지 않은 통합 테스트 실행과 ≥10분 비용을 wave 수만큼 자동 승인한다. 게이트가 존재하는 이유를 상위 계층이 무효화하는 쪽이므로 채택하지 않았다 |
| H5 회귀 조건 | **델타 우선, `exit_code`=0 은 fallback** | 기준선 캡처가 성공한 정상 경로에서는 델타가 더 엄격하다(신규 실패 0건). 캡처 실패 시에만 현행 절대 조건으로 격하해 판정 불능 상태를 만들지 않는다 |
| M6 cap 근처 재개 | **`fail-cap` 즉시 기록 + 사용자 결정** | cap 연장은 무한 에스컬레이션 방지를 무력화하고, 스트릭 영속은 waves-event 가 명시한 "승인은 영속시키지 않는다"와 정면 충돌한다. 도달 불가를 **탐지해서 올리는** 것이 두 규칙을 모두 지킨다 |
| M7 stale lock | **`--force` 명시 pass-through only** | 자동 부여는 살아 있는 다른 PM 인스턴스를 밟는다. 자식 실패는 이미 선언된 `child-pipeline-needs-user-or-failed` 로 올린다 |
| M9 canonical 집합 | **합집합 − `lifecycle-gate-draft`** | 합집합은 어느 변형도 HALT 를 잃지 않는 유일한 선택이다. 단 하나의 제외는 이미 상위 계층에서 철회된 정책을 되살리지 않기 위한 것이며 §9.1-3 에 근거를 명시했다 |
| M11 phase 라벨 | **첫 줄을 `srs-authoring` 으로 + `pipeline` 줄 신설** | 첫 줄만 개명하면 `pipeline` enum 멤버가 어느 이벤트에도 실리지 않아 고아가 된다(기존 단언도 그것을 고정한다). 두 줄로 나누면 라벨이 실제 단계와 맞으면서 enum 도 생산된다 |
| C1 버전 면제 | **면제 없음** | §3/§4 의 두 기존 grandfather 와 달리, 이 조항은 면제하면 취약점이 기존 저널에 그대로 남는다. 그 오독의 귀결이 "구현 0건 완료 보고"이므로 소급 적용이 정당하다 |
| L1 사이클 종료 | **review-fix-loop 에서 종료, push 미연결** | 자동 push 는 wave 마다 반복되는 되돌릴 수 없는 외부 부작용이다 |
