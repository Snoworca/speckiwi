#### 구현 가이드

1. Extend `TargetSummary` with `countsByType`, `blocked`, `diagnosticsSummary`, and release-aligned missing evidence fields.
2. Add a shared read envelope helper with `diagnostics`, `errors`, `warnings`, and `diagnosticsSummary`.
3. `validate --json` returns `{ diagnostics, errors, warnings, summary }`.
4. `targets --json` includes target metadata plus requirement counts by target.
5. `summary --json` and `active-target --json` return expanded summary without active target fallback.

#### Rationale

Agents should not need a separate validate call to know whether read output was produced from a clean workspace.

#### 함정 / 주의사항

- Human output can remain concise; JSON contract is the hard requirement.
- Empty Active Target must not fallback.
- Shared helper should not force MCP-specific resource envelope policy into CLI names.

#### 테스트 작성 지침

- 성공: every read-oriented CLI JSON output parses and includes diagnostics summary.
- 성공: targets output includes counts by target.
- 성공: summary output includes countsByType, blocked, implementedNotVerified, missingEvidence.
- 경계: active-target empty value reports empty without fallback.

### TASK-P5-002 — MCP read parity and envelope-all resources

| Field | Value |
|---|---|
| 관련 SRS 참조 | `FR-MCP-013`, `FR-MCP-014` |
| 파일 경로 | 수정: `src/mcp/tools/read-tools.ts`, `src/mcp/resources.ts`, `src/mcp/server.ts`, `src/mcp/schemas.ts`, `test/mcp/read-tools-resources.test.ts`, `test/mcp/stdio-purity.test.ts`, `test/integration/cli-mcp-parity.test.ts`, `docs/spec/90.appendix.md` |
| 메서드/함수 시그니처 | `function registerReadTools(server: McpServerHandle, deps: McpDependencies): void`; `function registerResources(server: McpServerHandle, deps: McpDependencies): void`; `function resourceEnvelope<T>(workspace: ParsedWorkspace, value: T): ResourceEnvelope<T>` |
| 참고 패턴 | `src/mcp/tools/read-tools.ts:14-29` and `src/mcp/resources.ts:8-35` currently return mixed tool/resource shapes. |
| source_anchors | `["src/mcp/tools/read-tools.ts:14-29", "src/mcp/resources.ts:8-35", "src/mcp/server.ts:95-180", "src/mcp/schemas.ts:1-16", "test/mcp/read-tools-resources.test.ts:7-36", "test/mcp/stdio-purity.test.ts:13-63", "test/integration/cli-mcp-parity.test.ts:6-16", "docs/spec/40.mcp-stdio-interface.srs.md:1016-1132", "docs/spec/90.appendix.md:510-542"]` |
| 예상 소요 | 7시간 |

#### 구현 가이드

1. MCP read tools use the same core read envelope or summary builders as CLI.
2. `validate_spec` returns standardized `{ diagnostics, errors, warnings, summary }` payload.
3. `summarize_target`, `get_active_target`, and `list_completed_work` align with CLI semantics.
4. Add `resourceEnvelope()` with `{ ok, value, diagnostics, diagnosticsSummary }`.
5. Apply envelope-all to index, active-target, completed-work, requirement, target, and scope resources.
6. Real stdio bridge stops unwrapping completed-work resource value except through documented legacy mode if one is added.
7. Appendix documents compatibility impact and window.

#### Rationale

Coding agents should receive the same governance signals over MCP as humans see in CLI JSON. Mixed raw/wrapped resources hide diagnostics and force per-resource special cases.

#### 함정 / 주의사항

- Existing stdio test expects raw completed-work; update it intentionally with compatibility note.
- Read tools remain read-only; mutation tools do not receive readOnlyHint.
- Resource envelope should not duplicate large markdown by default unless resource-specific value requested it.

#### 테스트 작성 지침

- 성공: MCP read tool payloads match CLI meaning for overlapping fields.
- 성공: every MCP resource returns `ok`, `value`, `diagnostics`, `diagnosticsSummary`.
- 성공: `get_active_target` returns empty active target without fallback.
- 성공: completed-work target resource uses latest ordering and filters.
