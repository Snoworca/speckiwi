#### 구현 가이드

1. Target Map duplicate target values와 multiple active rows를 diagnostic으로 보고한다.
2. Scope Map duplicate prefixes와 missing primary document file을 diagnostic으로 보고한다.
3. `docs/spec/**/*.srs.md` 중 Scope Map에 등록되지 않은 document를 diagnostic으로 보고한다.
4. Parsed requirements에서 Status Summary count와 Requirement Type Summary count를 계산한다.
5. Index table count와 computed count가 다르면 drift diagnostic을 낸다.

#### Rationale

Index는 target, scope, release control plane이다. Rollup drift를 방치하면 release readiness와 agent status query가 잘못된 판단을 하게 된다.

#### 함정 / 주의사항

- `.srs.md` discovery는 index file과 scope files를 구분해야 한다.
- `released` target status는 rules doc enum과 일치시킨 뒤 validation한다.
- Rollup table이 없는 legacy fixture는 missing table diagnostic과 drift diagnostic을 중복으로 내지 않게 분리한다.

#### 테스트 작성 지침

- 성공: duplicate target, duplicate scope, multiple active row fixture가 expected code를 낸다.
- 성공: missing scope document와 unregistered SRS document를 구분한다.
- 성공: stale Status Summary와 stale Requirement Type Summary drift를 잡는다.
- 경계: valid-basic fixture는 errors 0을 유지한다.

### TASK-P6-002 — Completed Work Log latest ordering, prevalidation, and override

| Field | Value |
|---|---|
| 관련 SRS 참조 | `IR-CLI-022` |
| 파일 경로 | 수정: `src/core/query/completed-work.ts`, `src/core/mutation/add-completed-work.ts`, `src/cli/commands/read.ts`, `src/cli/commands/mutations.ts`, completed-work tests |
| 메서드/함수 시그니처 | `interface CompletedWorkFilter { order?: "latest" | "file" }`; `interface AddCompletedWorkInput { allowIncomplete?: boolean }`; `function validateCompletedWorkInput(workspace: ParsedWorkspace, input: AddCompletedWorkInput): Diagnostic[]` |
| 참고 패턴 | `src/core/query/completed-work.ts:32-34` currently returns file order, and `src/core/mutation/add-completed-work.ts:111-133` writes without reference prevalidation. |
| source_anchors | `["src/core/query/completed-work.ts:3-34", "src/core/mutation/add-completed-work.ts:111-133", "src/cli/commands/read.ts:22-35", "src/cli/commands/mutations.ts:13-99", "test/core/query/completed-work.test.ts:1-29", "test/core/mutation/add-completed-work.test.ts:8-107", "docs/spec/30.cli-interface.srs.md:1344-1400"]` |
| 예상 소요 | 6시간 |

#### 구현 가이드

1. Default `listCompletedWork()` ordering becomes Date descending, then source line descending.
2. Add optional `order: "file"` for current file order.
3. `addCompletedWork()` parses workspace before write and validates target, scope tokens, requirement IDs.
4. Requirement IDs must exist and have status `implemented` or `verified` unless explicit override is set.
5. CLI adds documented override flag for historical/incomplete rows.

#### Rationale

Recent work requests need predictable latest ordering, and new completed rows should not point at unknown or incomplete requirements by default.

#### 함정 / 주의사항

- Target may be intentionally empty for cross-target rows.
- Prevalidation should reject new bad rows before table safety or patch write.
- Existing fixture historical rows are not rewritten.

#### 테스트 작성 지침

- 성공: default limit returns latest rows by date and line.
- 성공: `--order file` preserves document order.
- 실패: unknown target/scope/requirement ID is rejected for new row.
- 실패: requirement not implemented or verified is rejected without override.
- 성공: override allows intentional historical or incomplete row.
