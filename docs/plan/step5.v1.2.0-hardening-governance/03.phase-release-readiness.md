#### 구현 가이드

1. Change `summarizeReleaseReadiness()` input to accept explicit target option.
2. If target option exists, set `targetSource` to `explicit`; otherwise use `workspace.index.activeTarget`.
3. If both explicit target and active target are empty, return `ready=false` and add a blocker.
4. Expand summary fields required by `FR-FLOW-007`.
5. `scripts/release-check.mjs` calls core summary without hard-coded `v1.0.0` fallback.

#### Rationale

Release readiness should explain why a target is blocked. Hard-coded target defaults can make the wrong target look release-ready.

#### 함정 / 주의사항

- Empty Active Target is a real state and must not fallback to first Target Map row.
- `ready` should be false if validation errors exist.
- The script exit code must continue to respect `--strict`.

#### 테스트 작성 지침

- 성공: explicit target wins over active target.
- 성공: no explicit target uses active target.
- 실패: empty active target with no explicit target returns ready false and blocker.
- 성공: release-check script output includes `targetSource`.

### TASK-P3-002 — Evidence, AC coverage, trace, and command policy release gate

| Field | Value |
|---|---|
| 관련 SRS 참조 | `FR-FLOW-008` |
| 파일 경로 | 수정: `src/core/workflow/release-readiness.ts`, `src/core/parser/evidence-parser.ts`, `src/core/parser/trace-parser.ts`, `src/core/validator/rules.ts`, release tests; 신규 fixtures under `test/fixtures/workspaces/release-*` |
| 메서드/함수 시그니처 | `function collectAcCoverageGaps(records: RequirementRecord[]): AcCoverageGap[]`; `function collectMissingEvidenceReferences(workspace: ParsedWorkspace): EvidenceReferenceIssue[]`; `function collectCommandEvidencePolicyViolations(records: RequirementRecord[]): CommandEvidencePolicyViolation[]` |
| 참고 패턴 | `src/core/validator/rules.ts:25-30` only checks checked AC and non-empty evidence; `src/core/parser/evidence-parser.ts:7-15` already stores `covers`. |
| source_anchors | `["src/core/validator/rules.ts:25-30", "src/core/parser/evidence-parser.ts:7-15", "src/core/parser/trace-parser.ts:1-17", "src/core/workflow/release-readiness.ts:36-67", "test/release/srs-traceability.test.ts:4-8", "docs/spec/60.workflow-release.srs.md:468-530"]` |
| 예상 소요 | 8시간 |

#### 구현 가이드

1. For each verified requirement, require all AC checked.
2. For each checked AC, require evidence row with `Covers = all` or matching AC ID.
3. Classify evidence references as local path, URL, command, or opaque.
4. Local path evidence must resolve under project root; URL evidence is syntax-checked only.
5. Command evidence is reported in `commandEvidencePolicyViolations` unless it satisfies policy.
6. Requirement trace links must resolve to existing requirement IDs.

#### Rationale

`verified` must mean the tool can prove coverage and evidence validity. A non-empty evidence row is not enough for release governance.

#### 함정 / 주의사항

- Do not perform network calls for URL evidence.
- Command evidence classification must not execute the command.
- Local evidence must stay inside project root.

#### 테스트 작성 지침

- 성공: AC covered by `all` passes.
- 성공: explicit AC coverage passes only for matching AC IDs.
- 실패: missing local evidence path appears in `missingEvidenceReferences`.
- 실패: invalid URL and command evidence policy violation appear in separate fields.
- 실패: broken trace link appears in `brokenTraceLinks`.
