## 1. 목표

Concurrent CLI/MCP mutations가 같은 ID나 stale insertion point를 조용히 쓰지 못하게 optimistic freshness checks를 patch layer에 추가한다.

#### 구현 가이드

1. Add `TextFileSnapshot` with hash plus optional mtime/size from `readUtf8File()`.
2. `applyPatchPlan()` re-reads current file snapshot before write when dryRun is false.
3. On mismatch, throw or return structured `STALE_PATCH`; mutation guards convert it consistently.
4. Insert operations validate nearby expected lines or table/section end preconditions before write.
5. `addRequirement()` reparses once before generated ID insertion, then refuses if the generated ID is no longer free.
6. Evidence and completed-work generated IDs/insert lines use the same stale guard.

#### Rationale

Concurrent CLI/MCP calls can compute the same next ID or insert against an outdated boundary. Optimistic checks are enough for local-first files and avoid lock-file complexity.

#### 함정 / 주의사항

- Dry-run must preview against the read snapshot and not fail because the file later changed.
- Atomic temp write and rename behavior stays.
- Do not introduce lock files in this target.

#### 테스트 작성 지침

- 성공: file changed between read and write returns stale error.
- 성공: generated requirement ID collision after reparse is retried once or returns retry guidance.
- 성공: stale table insertion does not corrupt target file.
