### TASK-P1-001 — UTF-8 read와 SRS discovery root boundary 강화

| Field | Value |
|---|---|
| 관련 SRS 참조 | `SEC-MCP-001` |
| supporting SRS | `FR-PARSE-001` |
| 파일 경로 | 수정: `src/core/fs/read-text.ts`, `src/core/parser/discover.ts`, `test/core/fs/root-path.test.ts`, `test/core/parser/workspace-records.test.ts` |
| 메서드/함수 시그니처 | `async function readUtf8File(filePath: string, root?: string): Promise<TextFile>`; `async function discoverSrsFiles(root: ProjectRoot): Promise<SrsFileSet>` |
| 참고 패턴 | `src/core/fs/safe-path.ts:4-19`의 `resolveInsideRoot` realpath boundary check를 사용한다. |
| source_anchors | `["src/core/fs/read-text.ts:6-14", "src/core/fs/safe-path.ts:4-19", "src/core/parser/discover.ts:26-39", "test/core/fs/root-path.test.ts:29-51"]` |
| 예상 소요 | 2시간 |
| turn_estimate | 4 |
| TDD order | Red: symlink escape fixture와 parser rejection test 작성. Green: `readUtf8File(filePath, root)`가 `resolveInsideRoot`를 호출하게 수정. Refactor: root-relative path 계산을 safe-path helper와 중복 없이 정리하고 기존 UTF-8 tests 유지. |

#### 구현 가이드

1. Red: root 내부 `docs/spec/10.escape.srs.md` symlink가 root 밖 `.srs.md` 파일을 가리키는 fixture를 만든다.
2. `parseWorkspace(await resolveProjectRoot(root))`가 symlink target을 읽지 않고 `ROOT_BOUNDARY` code를 가진 Error로 reject하는 테스트를 먼저 추가한다.
3. `readUtf8File(filePath, root)`에서 `root`가 있으면 `resolveInsideRoot(root, filePath)`를 먼저 호출하고, 반환된 realpath를 읽는다.
4. `relativePath`는 resolved realpath가 root 내부일 때만 계산한다.
5. `discoverSrsFiles()`는 index와 scope file read에 root-aware `readUtf8File`을 계속 전달한다.
6. Windows에서 symlink 권한이 없으면 테스트는 `try/catch`로 skip하지 말고 `return` 처리한 현재 root-path test 패턴을 따른다.

#### Rationale

MCP read tools와 resources는 parser를 통해 파일을 읽는다. parser read path가 symlink realpath를 검사하지 않으면 MCP root boundary가 무력화된다.

#### 함정 / 주의사항

- `resolveInsideRoot()`는 존재하는 파일의 realpath escape를 이미 잡는다. 이 TASK는 read path가 해당 helper를 호출하도록 연결하는 작업이다.
- root가 없는 `readUtf8File(filePath)` 호출은 기존 테스트 helper 호환을 위해 기존 동작을 유지한다.
- root boundary 위반은 core에서 `ROOT_BOUNDARY` code를 가진 Error reject로 고정한다. parser records에는 root 밖 내용이 포함되지 않아야 하고, P3의 MCP mapper가 이 code를 `access_denied`로 변환한다.

#### 테스트 작성 지침

- 성공: root 내부 정상 `.srs.md`는 UTF-8로 읽힌다.
- 실패: symlink `.srs.md`가 root 밖을 가리키면 parser가 `ROOT_BOUNDARY` Error로 reject하고 root 밖 내용을 records에 포함하지 않는다.
- 경계: symlink 생성 권한이 없는 플랫폼에서는 테스트가 조용히 종료된다.

### TASK-P1-002 — init_project write boundary와 safe writable path 추가

| Field | Value |
|---|---|
| 관련 SRS 참조 | `SEC-MCP-001`, `FR-MCP-011` |
| supporting SRS | `IR-CLI-003`, `FR-NODE-009` |

| 메서드/함수 시그니처 | `async function resolveWritableInsideRoot(root: string, candidate: string): Promise<string>`; `async function initProject(root: ProjectRoot, input: InitProjectInput): Promise<MutationResult<InitProjectOutput>>` |
| 참고 패턴 | `src/core/fs/safe-path.ts:4-19`의 root realpath 계산을 확장한다. |
| source_anchors | `["src/core/fs/safe-path.ts:4-19", "src/core/bootstrap/init-project.ts:30-70", "test/core/bootstrap/init-project.test.ts:15-45"]` |
| 예상 소요 | 3시간 |
| turn_estimate | 5 |
| TDD order | Red: symlink parent write escape tests 작성. Green: `resolveWritableInsideRoot`와 init write call-site 보호 구현. Refactor: read/write boundary helper의 root-realpath 계산을 공유하고 init idempotency tests 유지. |

#### 구현 가이드

1. Red: root 내부 `docs` 또는 `AGENTS.md` path가 symlink로 root 밖을 가리키는 fixture를 만든다.
2. `initProject(root, { agentFiles: ["AGENTS.md"] })`가 root 밖 파일을 쓰지 않고 `ok:false` structured result를 반환해야 한다는 테스트를 추가한다.
3. Red: init core service가 `docs/`, `docs/spec/`, `docs/rule/`, `docs/spec/00.index.md`, `docs/spec/90.appendix.md`, `docs/rule/SRS-MD-Rules-v1.0.0.md` 생성과 대문자 `AGENTS.md`/`CLAUDE.md` 갱신을 모두 검증한다.
4. Red: 기존 파일은 `force:false`에서 덮어쓰지 않고 `skipped`로 보고하며, 같은 agent snippet은 중복 삽입하지 않는다.
5. `resolveWritableInsideRoot(root, candidate)`를 구현한다.
6. writable helper는 candidate가 없을 때 nearest existing parent의 realpath를 확인한 뒤 leaf path를 조합한다.
7. `initProject()`의 `mkdir`, `writeIfMissing`, `upsertAgentInstruction`에서 path join 결과를 helper로 검증한다.
8. 실패 code는 core에서는 `MUTATION_DENIED`, MCP outward mapping에서는 P3의 lower-case taxonomy가 처리한다.

#### Rationale

init은 새 파일을 생성하므로 read-only realpath helper만으로는 parent symlink escape를 잡기 어렵다. write 전용 helper가 필요하다.

#### 함정 / 주의사항

- non-existing leaf는 realpath가 없으므로 parent realpath 검사가 핵심이다.
- `force`가 true여도 root 밖 write는 허용하지 않는다.
- Windows symlink 권한 차이를 테스트에서 처리한다.

#### 테스트 작성 지침

- 성공: 빈 temp root에 `docs/spec`, `docs/rule`, agent file이 생성된다.
- 실패: root 내부 symlink parent를 통한 outside write는 거부된다.
- 경계: `force:true`에서도 outside write가 거부된다.
- 경계: `force:false`는 기존 index/rules/agent files를 덮어쓰지 않고 `skipped` 또는 `updated`를 정확히 보고한다.

| source_anchors | `["src/core/types.ts:167-173", "src/core/query/summary.ts:7-20", "test/core/query/query-summary-links.test.ts:10-19"]` |

#### 구현 가이드

1. Red: summary test에서 `countsByType.functional`, `blocked`, `implementedNotVerified`, `missingEvidence`를 모두 assert한다.
2. `TargetSummary`에 `countsByType: Record<string, number>`와 `blocked: string[]`를 추가한다.
3. `summarizeTarget()` loop에서 `record.type` count를 누적한다.
4. `record.status === "blocked"`이면 `blocked`에 requirement ID를 push한다.
5. 기존 필드 `countsByStatus`, `total`, `implementedNotVerified`, `missingEvidence`는 유지한다.
6. CLI/MCP output은 P2/P3에서 이 확장 payload를 그대로 사용한다.

#### Rationale

CLI summary와 MCP summarize_target이 같은 core summary를 공유하므로 core payload를 먼저 확장해야 두 adapter가 같은 계약을 만족한다.

#### 함정 / 주의사항

- 기존 JSON consumer가 깨지지 않도록 필드를 제거하지 않는다.
- type key는 SRS type value인 `functional`, `interface` 같은 lower-case 문자열을 사용한다.
- blocked 목록은 ID 배열로 둔다.

#### 테스트 작성 지침

- 성공: valid-basic target summary가 type count를 포함한다.
- 실패: blocked fixture를 만들어 blocked ID 목록이 비어 있지 않음을 확인한다.
- 경계: target에 record가 없으면 total 0과 빈 count object를 반환한다.
