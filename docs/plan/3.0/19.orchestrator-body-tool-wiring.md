# 19. `kiwi-orchestrator` 본문이 받는 다섯 도구를 배선한다

| Field | Value |
|---|---|
| 우선순위 | CRITICAL — 정확도 |
| 근거 | `docs/research/28.skills-mcp-end-to-end-audit.md` §3.6, 계획 [17번](17.orchestrate-tool-triage.md) §7 7번 |
| 선행 항목 | **17 번.** 판정 표가 요구 `FR-FLOW-167` 에 실린 뒤에만 착수한다. 이 항목은 조사를 다시 하지 않고 그 표를 입력으로 받는다 |
| 대상 | `skills/{claude,codex,etc}/kiwi-orchestrator/SKILL.md` 와 그 미러 |

## 0. 이 항목이 생긴 경위

17 번이 `orchestrate_*` 18종의 처분을 판정해 **배선 10 · 코드가 이미 수행 1 · 다른 도구가 소유 4 · 이연 3** 으로 갈랐다. 배선 10 가운데 셋(`orchestrate_route_probe` · `orchestrate_route_freeze` · `orchestrate_readiness_check`)은 17 번이 직접 수행했고, 나머지 일곱은 17 번 §7 7번이 정한 대로 후속으로 나뉘었다 — "배선 대상이 서너 개를 넘거나 서로 다른 스킬에 흩어져 있으면, 판정 표를 먼저 닫고 배선을 도구 가족별 후속 항목으로 나눈다."

일곱은 착지할 파일이 셋으로 갈린다. **이 항목은 `kiwi-orchestrator` 본문에 착지하는 다섯을 받는다.** 나머지 둘은 공용 계약 파일에 착지하므로 [20번](20.shared-contract-tool-wiring.md)이 받는다.

17 번의 검증 라운드 1 이 이 분리를 지목했다. 그때 일곱을 받을 항목이 없었고, 그것이 04 번이 이연을 남기고 받을 항목을 만들지 않아 이 계열 전체가 겪은 것과 같은 상태다.

## 1. 이 항목이 받는 다섯

값은 전부 `FR-FLOW-167` 의 Implementation Notes 에 실린 판정 행에서 온다. **다시 조사하지 않는다. 다만 착수 시점에 (a0) 를 한 번 재측정한다** — 17 번 이후 코드가 움직였으면 처분이 달라질 수 있고, 그것을 재는 명령은 17 번 §2 의 두 `grep` 이다.

| 도구 | 판정 행 | 착지 자리 | (d) 가 적어 둔 남은 경로 |
|---|---|---|---|
| `orchestrate_run_lock` | 4/18, (a0) 있음(부분) | `§3` P.5 | 취득 전체와 abort 아닌 종료의 해제 |
| `orchestrate_run_abort` | 5/18 정정, (a0) 없음 | `§15` · `§V.abort-run` | — |
| `orchestrate_freeze` | 6/18, (a0) 없음 | 여섯 target 의 자리, 3.k activity (0) 포함 | 기존 접두 없는 철자 `freeze handoff` 와 갈리지 않게 여섯 target 을 함께 정규화 |
| `orchestrate_handoff_validate` | 10/18, (a0) 없음 | 3.f loop H 의 lane handoff, 3.k activity (0) | 3.f 의 lane handoff 전부 |
| `orchestrate_issue_open` | 12/18 정정, (a0) 없음 | `§13.2` 이슈 저작 절 | 중복 id 한 축뿐 |

**`orchestrate_freeze` 와 `orchestrate_handoff_validate` 는 이미 접두 없는 leaf 철자로 불린다.** 3.k activity (0) 한 줄이 `handoff validate --lane epilogue` 와 `freeze handoff` 를 적는다(네 렌더링에 각 4회). `speckiwi` 도 `orchestrate` 도 붙지 않아 MCP 이름 축에도 CLI 경로 축에도 잡히지 않는다. **그 두 자리의 철자 정규화를 새 배선과 같은 라운드에 한다** — 두 철자가 공존하면 다음 계수가 다시 갈린다.

## 2. 목표 상태

다섯 각각에 대해, 그 판정을 수행하는 명령이 `kiwi-orchestrator` 네 렌더링 전부에서 이름으로 불리고, 그 판정 결과를 받는 게이트 이름이 같은 절 안에 있다. 형식은 17 번이 확정한 것을 그대로 쓴다 — MCP 도구 이름과 CLI 대체 명령을 함께 적고, CLI 인용은 `FR-NODE-128` 의 열세 형식 placeholder 로 적는다.

## 3. 작업 단계

1. **`FR-FLOW-167` 의 판정 행 다섯을 읽고 (a0) 를 재측정한다.** 값이 달라졌으면 처분부터 다시 정한다.
2. **요구를 등록한다.** 분모는 다섯이고, AC 는 "다섯 각각의 실행 지시가 네 사본에 있고 하나만 지워도 스위트가 붉어진다"와 "각 게이트가 그 도구의 핸들러 경로에서 실제로 발화한다"를 포함한다.
3. **게이트 이름을 먼저 소스에서 파생시킨다.** 17 번 라운드 1 이 발화하지 않는 게이트를 배선 지도에 적었고, `FR-FLOW-167` 의 스위트가 그 검사를 갖고 있으므로 그것을 재사용한다 — 핸들러 본문의 `refuse("<gate>"` 또는 그 핸들러가 부르는 커널 모듈의 정의.
4. **실패 테스트를 먼저 쓴다.** 새 문구가 착수 전 0회임을 먼저 세어 기록한다.
5. red 확인 → 세 변형 편집 → `speckiwi skills mirror --write` → green 확인.
6. **접두 없는 철자 두 자리를 같은 라운드에 정규화한다.**
7. 뮤테이션을 다섯 × 두 형태로 심어 red 를 재고, 그때의 스위트 크기와 함께 기록한다.

## 4. 완료 조건

- 다섯 각각의 실행 지시가 네 사본에 있고, 하나만 지워도 스위트가 붉어진다.
- 각 게이트가 그 도구의 핸들러 경로에서 발화함이 소스에서 파생된다.
- 접두 없는 leaf 철자가 새 철자와 갈리지 않는다 — 두 철자를 함께 세어 값이 하나임을 보인다.
- `speckiwi skills mirror --check` 가 divergence 0 을 보고한다.
- 대응 요구가 `verified` 이고 검증 증거가 붙어 있다.

## 5. 건드리지 말아야 할 것

1. **`FR-FLOW-167` 이 배선한 세 절.** `§V.probe-route` · `§V.freeze-route` · `§V.derive-readiness` 는 그 요구가 소유한다.
2. **판정 표의 처분을 다시 정하는 것.** (a0) 재측정으로 값이 바뀐 행이 아니면 처분은 17 번의 것이다.
3. **`GATE_IDS` 에 새 이름을 추가하는 것.** 17 번 §7 3번과 같은 이유다.
4. **`ORCHESTRATE_TOOL_BINDINGS` 와 `ORCHESTRATE_MCP_TOOLS`.** 이 항목도 두 표를 읽기만 한다.
5. **공용 계약 파일.** `_shared/kiwi/verify-loop.md` 와 `_shared/kiwi/auto-option.md` 는 20 번이 소유한다.
