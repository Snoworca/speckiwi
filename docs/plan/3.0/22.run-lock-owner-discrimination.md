# 22. 자기 run 의 lease 를 판별할 수단을 준다

| Field | Value |
|---|---|
| 우선순위 | HIGH — 정확도 |
| 근거 | 계획 [19번](19.orchestrator-body-tool-wiring.md) 검증 라운드 3 이 낸 LOW-1 |
| 선행 항목 | 없음. 대상 파일이 그룹 A 의 다른 항목과 겹치지 않는다 |
| 대상 | `src/cli/commands/orchestrate.ts` 의 `run lock` 옵션 기본값, `skills/{claude,codex,etc}/kiwi-orchestrator/SKILL.md` `§3.1` 과 그 미러 |

## 0. 이 항목이 생긴 경위

19 번이 `§3.1` 의 거짓 일반화를 고치면서 지시 하나를 새로 넣었다 — **"종료 해제는 이 run 이 취득한 lease 에 대해서만 부른다."** `unlock` 이 살아 있는 남의 lease 도 거절 없이 해제하기 때문에 필요한 가드다.

검증이 그 지시에 **판별 수단이 없는 경우**를 찾았다. 정상 흐름은 따라 할 수 있다 — `§3.1` 356행이 P.5 취득을 재개 체크포인트로 적으므로, 이 run 이 취득했는지를 그 기록으로 안다. 그러나 **재개된 run 의 lease 가 stale 회수로 교체된 경우**에는 그 기록이 가리키는 lease 가 이미 남의 것이다.

그때 `status` 의 `holder.owner` 로는 구별할 수 없다. **`--owner` 의 기본값이 모든 run 에서 `kiwi-orchestrator` 로 같고, 스킬은 `--owner` 를 0회 쓴다.** 그래서 어느 run 이 그 lease 를 쥐었는지가 응답에 실리지 않는다.

19 번에서 고치지 않은 이유는 그 요구의 범위가 아니고, 새 지시가 없던 것보다 안전하기 때문이다. 거짓 진술이 아니라 **따라 하기 어려운 지시**다.

## 1. 목표 상태

에이전트가 `status` 응답만으로 그 lease 가 자기 것인지 판별할 수 있고, `§3.1` 의 가드가 재개 경로에서도 따라 할 수 있다.

## 2. 확인해야 할 것

착수 시점에 먼저 재야 한다. 아래는 19 번 검증이 관측한 것이고, 그 뒤 코드가 움직였을 수 있다.

- `--owner` 의 기본값이 정말 모든 run 에서 같은가. 어디서 오는가.
- 스킬이 `--owner` 를 쓰는 자리가 정말 0 인가(네 렌더링).
- `status` 응답이 run 을 식별할 다른 필드를 이미 싣는가 — `runId` · `acquiredAt` · `pid` 로 판별이 가능한지 먼저 본다. **가능하면 코드를 고치지 않고 지시만 고치는 것이 옳다.**
- stale 회수로 lease 가 교체되는 경로가 실제로 어떤 것인지.

## 3. 작업 단계

1. 위 넷을 재고, **코드 변경 없이 닫을 수 있는지 먼저 판정한다.**
2. 요구를 등록한다. 닫는 방식에 따라 scope 가 갈린다 — 지시만 고치면 FLOW, CLI 기본값을 고치면 CLI 도 받는다.
3. 실패 테스트를 먼저 쓴다. **판별 가능성을 재는 테스트여야 한다** — "응답에 필드가 있다" 가 아니라 "두 run 이 같은 lease 를 두고 자기 것인지를 갈라 판정할 수 있다" 를 재야 그 지시가 따라 할 수 있게 된 것이 증거로 남는다.
4. red 확인 → 구현 → green → 회귀.

## 4. 완료 조건

- 재개된 run 이 stale 회수로 교체된 lease 를 만났을 때, `§3.1` 의 가드를 따라 할 수 있음을 테스트가 잡는다.
- 그 판별 수단을 없애면 붉어진다.
- `§3.1` 의 문면이 실측과 일치한다 — 19 번이 그 절에서 겪은 것이 **재지 않고 적은 일반화**였으므로, 새로 적는 문장도 심어서 확인한 뒤 적는다.

## 5. 건드리지 말아야 할 것

- **`unlock` 이 남의 lease 를 해제하는 거동 자체를 고치지 않는다.** `releaseHeldRunLock` 의 doc 이 그것을 의도라고 적고 있으므로, 바꾸려면 그 계약부터 다루어야 한다. 이 항목은 **판별 수단을 주는 것**이지 거동을 바꾸는 것이 아니다.
- `FR-FLOW-168` 의 스위트는 verified 다. 공유 헬퍼를 고쳐야 하면 그 값이 불변인지 재고 보고한다.
