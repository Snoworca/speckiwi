# 26. 테스트가 임시 디렉터리를 남기지 않게 한다

| Field | Value |
|---|---|
| 우선순위 | MEDIUM — 비용 |
| 근거 | 계획 [22번](22.run-lock-owner-discrimination.md) 작업 중 발견, [21번](21.exclusive-lock-transient-error.md) 검증 라운드 1 의 F4 |
| 선행 항목 | 없음 |
| 대상 | `test/**` 의 임시 루트를 만드는 자리들 |

## 0. 이 항목이 생긴 경위

22번 작업 중 `%TEMP%` 에 테스트 픽스처 `speckiwi-*` 가 **184,084 개** 쌓여 있는 것이 발견됐다. 가장 오래된 것이 2026-08-25 다.

같은 형태가 21번 검증에서도 나왔다 — 새 테스트 일곱 선언 가운데 여럿이 `rm(root)` 를 `finally` 밖에 두어, 본문이 실패하면 정리가 건너뛰어졌다.

## 1. 무엇이 문제인가

**디스크만의 문제가 아니다.** 이 저장소는 hermeticity 가드를 갖고 있고, 테스트가 남긴 잔재로 판정이 두 번 헛돌았다 — 한 번은 동시 실행이 가드를 건드렸고, 한 번은 다른 프로세스의 임시 파일이 관측됐다.

그리고 **18만 개는 그 자체로 다음 테스트를 느리게 한다.** `%TEMP%` 의 디렉터리 열거가 비싸진다.

## 2. 확인해야 할 것

- **분모.** 임시 루트를 만드는 테스트가 몇이고, 그중 정리를 `finally` 밖에 두거나 아예 안 하는 것이 몇인지. **"정리를 안 하는 테스트" 를 세지 말고 "임시 루트를 만드는 테스트" 를 먼저 세어야 한다** — 이 계획에서 술어로 분모를 거른 사례가 다섯 번 나왔다.
- **접두사가 몇 가지인지.** `speckiwi-*` 하나가 아닐 수 있다.
- **공용 헬퍼가 있는지.** 있으면 그것을 고치는 것으로 대부분이 닫힌다.
- **실패한 테스트의 잔재를 남겨야 하는 경우가 있는지.** 디버깅에 쓰이는 관례가 있으면 그것을 없애면 안 된다.

## 3. 목표 상태

테스트가 성공하든 실패하든 자기가 만든 임시 루트를 지운다.

## 4. 작업 단계

1. **§2 의 넷을 재고 방향을 정한다.** 공용 헬퍼로 닫히면 그쪽이 훨씬 싸다.
2. **요구를 등록한다.**
3. **실패 테스트를 먼저 쓴다.** **"정리하지 않는 테스트가 없다" 를 재는 검사여야 한다** — 개별 테스트를 고치는 것만으로는 다음에 추가되는 테스트가 같은 실수를 반복한다.
4. red 확인 → 구현 → green → 회귀.
5. **쌓인 것을 지운다.** 이것은 저장소 밖 정리이므로 요구의 범위가 아니지만, 하지 않으면 다음 측정이 오염된다.

## 5. 완료 조건

- 임시 루트를 만들고 정리하지 않는 테스트를 검사가 잡는다. **하나를 심으면 붉어진다.**
- **전체 회귀를 한 번 돌린 뒤 `%TEMP%` 의 증가분이 0 인 것**을 잰다. 이것이 실질적인 증거다.
- 검사가 못 잡는 형태가 요구에 실측과 함께 적힌다.

## 6. 건드리지 말아야 할 것

- **테스트가 무엇을 검사하는지는 바꾸지 않는다.** 정리 자리만 옮긴다.
- **`%TEMP%` 밖을 지우지 않는다.**
