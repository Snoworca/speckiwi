## 3. 이 세션이 세운 작업 규율

계획 항목 문서마다 흩어져 있으므로 여기에 모아 둔다. **다음 항목에 그대로 적용한다.**

- **부류를 주어로 삼지 않는다.** "이 검사가 막는 것은 아래 N 이며 하나씩 심어 실측했다" 로 열거하고, **전수가 아니라는 헤지는 잔여로 읽히는 쪽**(막지 못하는 목록)에 붙인다. 09·11·29·13 이 각각 이것으로 여러 라운드를 태웠다.
- **정규식은 산문의 뜻을 판정할 수 없다.** 어휘를 열거하면 열거 밖이 지나가고, 좁히면 옳은 것을 막는다. **판정이 필요하면 구조(표·선언·필드)로 옮긴다.**
- **소스 스캔은 실행을 단언하지 않는다.** MCP 는 **실제 SDK 클라이언트로 왕복**시켜 재고, 스킬은 배포 트리를 걷는다.
- **하네스가 죽은 뮤테이션을 red 로 세지 않게 한다.** `no tests`·수집 실패·총계 0 은 `INVALID`, **앵커가 정확히 1회 매치되지 않으면 실패.**
- **하한을 실제로 도는 집합 위에 걸고**, 요구 문서의 숫자와 대조할 때는 **등호로** 건다(부등호는 양쪽을 같은 맵에서 읽으면 항진명제가 된다).
- **동작-보존 뮤테이션**(파생을 리터럴로 인라인, 술어를 등가로)도 심는다.
- **옳은 재서술을 여덟 이상 지어 통과를 확인한다.** 옳은 것을 막는 검사는 검사가 아니다.
- **회귀 순서**: 코드·테스트 → 요구 문면 → **전체 회귀** → 증거 Notes. **닫는 실행의 로그 경로를 증거에 미리 이름하면** 사후 편집 없이 순서가 참이 된다.
- **verified 요구의 AC 를 거짓으로 만들면** 하향 → AC 수정 → 재승격(선례 `FR-PARSE-033`·`FR-NODE-177`·`FR-PARSE-040`). **status 는 착수 전에 내리고 문면은 코드 뒤에 고친다** — 나중에 내리면 그 사이 트리는 verified 라고 적힌 요구가 자기 테스트를 붉히는 상태이고, 그때 세션이 끊기면 SSOT 가 조용히 거짓말을 한다.
- **소스를 고치는 검증 축과 읽는 축을 같은 워킹트리에서 병렬로 돌리지 않는다.** 32번에서 뮤테이션 축의 in-flight 변종을 다른 세 축이 읽어, 옳은 재서술 14건이 전부 붉고 한 도구가 CRITICAL 로 오인될 뻔했다. 소스를 고치는 축은 `git archive HEAD` + 미커밋 diff 로 만든 **격리 사본**에서만 돌린다(`.gitattributes` 가 `eol=lf` 이므로 archive 의 CRLF 를 되돌려야 blob 이 맞는다).
- **수를 요구 문면에 등호로 박지 않는다.** 그 요구가 다스리지 않는 변경에 낡는다. **이름으로 잡는다** — 다만 **살아 있는 레지스트리에서 세어 대조하는 수는 그대로 둔다**(README 의 `doc-lint` 가 그렇다). 나쁜 것은 수가 아니라 **대조되지 않는 수**다.

## 4. 알려진 함정

- **`REL-NODE-005`** (`test/core/mutation/srs-lock-status-cache.test.ts`) 는 HEAD 에서도 7회 중 4회 붉는 **선재 취약 테스트**다(계획 33번). 발화하지 않아도 **초록으로 보고하지 않는다.**
- **`REL-NODE-007`** 은 `test/docs` 와 `test/release` 를 파일 병렬로 돌릴 때 프로브 파일 수명 경합으로 붉는다(계획 33번 §5). `npm test` 는 `--no-file-parallelism` 이라 발화하지 않는다.
- **폴링 루프를 여러 개 띄우면** 전체 스위트가 제한값에서 타임아웃 거짓 실패를 낸다. **한 번에 하나만.**
- **`typecheck:test` 의 EXIT 0** 은 대부분의 테스트 파일에 대한 타입 보증이 아니다 — `tsconfig.test.json` 의 `include` 가 `src` 와 오케스트레이터 테스트만 담는다.
- **heredoc 은 `<<'EOF'` 안에서도 `\\` 를 `\` 로 접는다** — 정규식 스크립트는 파일로 쓰고 `String.raw` 를 쓴다. (이 자리에 있던 "Git Bash `grep -i` 가 `docs/spec/**` 에서 조용히 0건을 돌려준다"는 **2026-09-07 에 철회했다** — GNU grep 3.0 으로 여섯 패턴을 `-i` 유무로 대조했으나 전부 같은 결과였고 대상 파일에 NUL 바이트도 없다.)
- **`%TEMP%`** 에 선재 누적물이 많다(계획 26번 소관). 자기가 만든 것만 정리한다.
- **`git diff --numstat` 은 워킹트리가 깨끗하다는 증거가 못 된다.** 뮤테이션이 같은 길이로 치환하면 합계가 그대로다 — 32번에서 **변종이면서 452/83 인 경우가 두 번** 관측되었다. **판별은 `git hash-object` 나 md5 로 한다.**
- **`workspace-root-docs.rel-mcp-005.test.ts` 의 단언은 산문의 뜻을 판정하지 못한다** — 절 안에 `refus`/`거부` 부분 문자열이 하나라도 남으면 통과한다. 그 초록을 README 수정의 근거로 삼지 않는다.

## 5. 별건으로 남긴 선재 결함

- **`AGENTS.md` 와 `agents.md` 가 인덱스에 둘 다 등록되어 있다.** Windows 는 대소문자를 구분하지 않아 파일이 하나이므로 여기서는 드러나지 않으나, **대소문자를 구분하는 파일시스템에서 체크아웃하면 두 파일이 생기고 하나는 낡은 내용**이다. 2026-09-06 실측: `agents.md` 엔트리는 최신이고 `AGENTS.md` 엔트리는 `a849d12` 이후 멈춰 있다. `git add AGENTS.md` 가 조용히 아무것도 하지 않는 것이 그 증상이다.
