### Reference Pattern

Use the existing managed block version, heading prefix, and suffix marker logic. The updater already replaces older versioned blocks when the current version differs.

### Implementation Guide

1. Bump `AGENT_INSTRUCTION_VERSION` from `1.1` to `1.2`.
2. Add text explaining `Status` versus `Stability`.
3. Extend current-work workflow to read stability counts and blocker fields from MCP `get_active_target` or CLI `speckiwi active-target --json`.
4. State that agents stop before implementing non-discarded `draft` or `deprecated` requirements unless the user explicitly overrides.
5. Run init tests proving older v1.1 blocks are replaced with v1.2 blocks and unrelated content is preserved.
6. Update root `AGENTS.md` and `CLAUDE.md` through the same managed block content.

### Rationale

Agents cannot enforce SRS workflow if they only read `Status`; they need explicit maturity guidance.

### Pitfalls

- Do not append a second managed block.
- Do not remove the suffix marker.
- Do not make Completed Work Log the source of truth.

- Boundary: files already containing v1.2 block are skipped.
