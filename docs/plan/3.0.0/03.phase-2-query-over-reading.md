선행: **P0-2**(플래그 검색 결함). 그것 없이 P2-2 의 문안만 넣으면 지시가 절반만 작동한다.

근거: 연구 26 §1·§4, 연구 27 §1·§3·§5.

## 왜 이 페이즈인가 — 한 표로

| 호출 | 출력 | `search` 대비 |
|---|---|---|
| `list --format full --json` | 3,277,697자 | 845배 |
| `docs/spec/*.md` 전량 | 2,874,213자 | 741배 |

원인은 두 줄이다. `CLAUDE.md` 워크플로 2번이 "scope SRS 파일에서 찾아라"고 지시하고, `search_requirements` 는 스킬 130개 파일 어디에도 없다(`README.md` 에만 있다).

## P2-1 — 질의 정규화 (용어집 불필요)

### 문제

`src/core/query/discovery.ts:161-172` 의 `snippetsFor` 가 매칭의 전부다.

```ts
const needle = query.trim().toLowerCase();
const haystack = entry.text.toLowerCase();
... haystack.indexOf(needle) ...
```

대소문자 무시 부분 문자열 일치다. 그래서 표기 하나에 갈린다. 후보 42쌍을 양쪽으로 검색한 실측에서 **42쌍 전부가 서로를 놓쳤고 안전한 쌍은 0**이었으며, 568개 중 409개(72%)가 걸려 있다.

| A | 히트 | B | 히트 |
|---|---|---|---|
| `dry run` | 8 | `dry-run` | **98** |
| `worktree` | 35 | `work tree` | **0** |
| `acceptance criteria` | 89 | `acceptance criterion` | 70 |

**하이픈 하나가 92개 요구를 갈랐다.**

### 할 일

`snippetsFor` 에 정규화를 넣는다. 하이픈·공백·밑줄을 접고, camelCase 를 분해하고, 단복수 어간을 맞춘다. **함수 하나, 호출부 변경 없음.**

이것으로 42쌍 중 13쌍(31%, 놓치는 요구 연 484건)이 판단 없이 해결된다.

### 깨질 테스트 — 세어 봤다

**정규화는 히트를 늘리므로 히트 수나 ID 집합을 단언하는 테스트가 깨진다.** 초판은 이것을 미확인으로 남겼다. 검토에서 셌다.

| 파일 | 개수 단언 | ID 집합 단언 |
|---|---|---|
| `test/cli/read-commands.test.ts` | 2 | 3 |
| `test/integration/todo-installable-workflow.test.ts` | 5 | 0 |

**2개 파일뿐이다. 진행 가능하다.**

### 틀렸을 때

과도한 정규화가 위험하다. `FR-NODE-021` 과 `FR-NODE-0021` 을 같게 만들면 안 된다. **식별자(진단 코드·REQ-ID·파일 경로)는 정규화 대상에서 제외한다.**

### 검증

연구 27 §3.2 의 42쌍 측정을 재실행해 **위험 쌍이 줄어든다.** 표기적 12쌍 + 어간 1쌍이 안전으로 넘어가야 한다. 줄지 않으면 정규화가 겨냥을 잘못한 것이다.

## P2-3 — 용어집과 별칭 확장

선행: P2-1.

### 근거 — 이유가 검색 편의가 아니다

**ISO/IEC/IEEE 29148 의 집합 수준 "Consistent" 정의가 "모든 요구에서 같은 대상에 같은 용어를 쓴다"를 이미 포함한다.** `trailing-LF` 대 `trailing newline` 은 검색 실패가 아니라 표준 조항 위반이다.

그리고 자동 모순 검출을 실제로 하는 네 계열(형식 논리·형식 검증·온톨로지·임베딩)이 **전부 통일된 어휘를 입력으로 요구한다.** 상용 벤더조차 의미 유사도 검색 위에 **사람이 관리하는 동의어 사전**을 따로 얹는다(Garantis, Polarion 플러그인).

정확한 명제는 이것이다. **어휘 통일은 모순 검출의 충분조건이 아니라 필요조건이다.**

### 구조 — ISO 704 / SKOS 를 그대로

| SKOS | 쓰임 |
|---|---|
| `prefLabel` | 대표어. 개념당 **언어별로 하나** |
| `altLabel` | 두문자어, 약어, 철자 변형 |
| `hiddenLabel` | 표시하지 않고 **검색에만** 쓰이는 라벨 ← `trailing-LF` 가 여기 |

**언어 태그가 개념이 아니라 라벨에 붙는다.** 한국어 요구와 영어 요구가 하나의 개념을 공유하면서 각자의 대표어를 갖는다. 전면 번역(기각됨) 없이 한국어를 수용하는 길이 이것이다.

**ISO 30042(TBX)는 채택하지 않는다.** 교환 형식이며 용어 일관성을 검사하지 않는다.

### 둘 자리 — `docs/rule/`

번들되는 규칙 문서는 상수로 이름 붙은 두 개뿐이다(`BUNDLED_SRS_RULES_FILENAME`, `BUNDLED_SDS_RULES_FILENAME`). 새 파일은 **AC-9 검사에 자동으로 걸리지 않으므로** 상수 하나 + 로더 함수 하나 + `package.json` 의 `files` 항목 하나를 추가한다. 위험은 낮고 배선은 명시적이다.

`docs/spec/` 이 아니라 `docs/rule/` 인 이유: 용어 고정은 **SRS-MD 저작 규칙의 일부**이지 이 프로젝트의 요구가 아니다. 소비자에게도 번들 배포된다.

### 할 일

1. 용어집 파일 신설. **표류가 실제로 발견된 쌍만** 등록한다. 미리 완비하려 들면 그것이 새 산문 부채가 된다.
2. 초기 항목은 연구 27 §3.4 의 **의미적 29쌍**. 큰 순서로 `supersede`/`replaced by`(92), `verification evidence`/`evidence reference`(90), `requirement id`/`REQ-ID`(88), `active target`/`current target`(46), `discarded`/`tombstone`(44).
3. `snippetsFor` 의 `needle` 을 단수에서 복수로 확장한다.

### 요구 문안은 고치지 않는다

**568개 요구를 대표어로 재작성하지 않는다.** `semanticSha` 가 대량 무효화되고, 고쳐 쓴 다음에도 다음 요구가 또 새 이름을 만든다. 검색을 넓히는 쪽이 요구를 한 줄도 안 건드린다.

### 틀렸을 때

별칭이 과하면 히트가 폭증해 좁히기 효과가 사라진다. **한 개념의 별칭 수에 상한을 두고, 등록 시 그 별칭으로 검색했을 때 히트가 몇 개 늘어나는지를 기록한다.**

용어집이 썩는 것을 막는 것은 용어집 자체가 아니라 **저작 시점 검사와 승인 절차의 결합**이다(§4.5 연구 27). P2-5 가 그 절반이다.

### 검증

- `search "trailing newline"` 이 `FR-NODE-021` 을 포함한다(지금은 빠진다).
- 별칭 항목을 지우면 그 쌍의 테스트가 red 가 된다.

## P2-5 — `add_requirement` 자동 검색

선행: P2-3.

### 할 일

입력(요구문·AC)에서 식별자를 뽑아 검색하고 **후보를 결과에 실어 돌려준다. 차단이 아니라 보고다.**

`search_requirements` 는 이미 있다. 없는 것은 호출 시점뿐이다.

### 틀렸을 때

차단으로 만들면 정당한 신규 요구가 막히고, 막히면 우회 경로가 생긴다. 그리고 **판정을 기계에 맡기지 않는다** — Smella 의 정밀도가 59%이고 면담한 실무자 전원이 보조 도구로만 쓸 수 있다고 답했으며, 최선의 하이브리드도 재현율 60%다. 기계는 후보를 좁히는 데까지만 한다.

### 확장 여지 — 확인했다

`MutationResult` 는 선택 필드를 이미 넷 갖고 있다.

```ts
interface MutationResult<T = unknown> {
  ok: boolean;
  value?: T;
  error?: {...};
  diagnostics: Diagnostic[];
  diagnosticsSummary: DiagnosticsSummary;
  patch?: PatchSummary;
  mutation?: MutationEnvelope;
  indexSync?: IndexSyncMutationSummary;
}
```

**후보 목록을 선택 필드 하나로 얹는 것은 기존 패턴 그대로이며 계약 변경이 아니다.**

다만 `add_requirement` 를 다루는 테스트가 **34개 파일**이다. 필드 추가 자체는 안전하지만 표면이 넓다.

`dryRun` 경로에서도 동작해야 한다 — 후보 조회는 읽기이므로 mutation 을 쓰지 않고도 낼 수 있어야 한다.

### 검증

기존 요구와 식별자를 공유하는 신규 요구를 넣으면 후보가 결과에 실린다. 공유하지 않으면 실리지 않는다(빈 결과가 아니라 필드 부재로 구분).

## P2-6 — 도달 불가 표면을 에이전트에 노출

`00.index.md` 의 전제에서 곧바로 나온다. **사람이 README 를 읽지 않으므로, README 에만 있는 표면은 존재하지 않는 것과 같다.**

### 규모

소비자를 `skills/**` + `CLAUDE.md` 로 한정한 실사다.

| 표면 | 전체 | 도달 0 | 그중 README 에만 | 어디에도 없음 |
|---|---|---|---|---|
| CLI | 59 | **33** | 18 | 15 |
| MCP | 73 | **19** | 13 | 6 |

CLI 의 절반 이상이 에이전트에게 보이지 않는다. 그중에는 `search` 도 있다 — **읽기를 질의로 바꾸겠다는 이 페이즈의 주 도구 자체가 도달 불가였다.**

### 왜 폐기가 아니라 노출인가

초판은 이것을 다이어트 대상으로 봤다. 전제가 그 판단을 뒤집는다. 도달 불가 표면은 **뚱뚱한 것이 아니라 배선이 빠진 것**이다. 유지 비용은 내면서 아무것도 돌려주지 않으므로 **지금 상태가 폐기보다도 나쁘다.**

`doctor` · `explain` · `stale` · `history` · `attention` · `coverage` · `rtm` · `release-readiness` 는 사용자가 "지금 상태 어때?"라고 물었을 때 에이전트가 답하는 데 쓰는 것들이다. 에이전트가 그 존재를 모르면 대신 파일을 읽는다. **이 페이즈가 없애려는 바로 그 행동이다.**

### 할 일

1. P3-3 의 판정 순서를 각 표면에 적용해 **노출 / 폐기 후보**로 가른다.
2. 노출 대상을 `CLAUDE.md` 와 관련 스킬에 넣는다. 나열이 아니라 **언제 부르는가**를 함께 적는다. 이름만 나열하면 도달은 되지만 호출되지 않는다.
3. 폐기 후보는 P3-3 으로 넘긴다.

### 틀렸을 때

**전부 노출하면 `CLAUDE.md` 가 비대해지고, 그것은 매 세션 로드된다.** 명령 59개를 다 적으면 그 자체가 토큰 비용이다. 상황별로 묶어서 적고, 세부는 `--help` 로 미룬다 — `--help` 는 에이전트가 필요할 때 부르면 되는 적시 적재다.

### 검증

- 도달 불가 표면을 재측정해 **CLI·MCP 각각 절반 이하**가 된다. Phase 2 게이트가 요구하는 하한이므로 여기 옮겨 적는다 — 방향만 적으면 한 개만 줄어도 통과한다.
- 측정은 소비자를 `skills/**` + `CLAUDE.md` 로 한정한 위 실사와 **같은 방법**으로 한다. 방법을 바꾸면 전후 비교가 성립하지 않는다.
- `CLAUDE.md` 의 증가분을 측정한다. 늘어난 토큰보다 줄어든 읽기가 커야 한다.
