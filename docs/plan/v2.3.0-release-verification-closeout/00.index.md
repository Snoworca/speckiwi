## Objective

Close the real v2.3.0 readiness gap without weakening release gates. The current code and tests are mostly implemented, but `npm run lint` fails and `release:check` remains blocked by 53 `implementedNotVerified` requirements. The plan fixes quality/signature/evidence issues first, then promotes requirements to `verified` only through per-requirement evidence-backed mutations.

## Global Guards

- Do not use bulk-finalize, bulk-archive, or any script that flips many requirements without per-REQ evidence review.
- Do not use `--ignore-lock` unless a stale owned lock is proven and documented.
- Do not treat Completed Work Log rows as verification evidence by themselves.
- Do not bump `package.json` to `2.3.0` in this closeout; do that only in a release-cut task after `release:check` passes.
- All SRS mutations use CLI/MCP tools, not manual Markdown line edits.
