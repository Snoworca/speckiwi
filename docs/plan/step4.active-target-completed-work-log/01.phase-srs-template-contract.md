#### 구현 가이드

1. `SRD.md`의 Active Target section을 "init은 빈 Active Target row를 만든다"로 갱신한다.
2. `docs/spec/00.index.md`에 `## 7. Completed Work Log` section을 `Requirement Type Summary` 뒤에 추가하고 뒤 section 번호를 하나씩 올린다.
3. `docs/spec/20.parser-validation.srs.md`에서 Active Target row가 존재하지만 값이 비어 있는 경우 fallback하지 않는 AC를 추가한다.
4. 같은 문서에 Completed Work Log parser와 warning diagnostics 요구사항을 추가한다.
5. `docs/spec/30.cli-interface.srs.md`의 `IR-CLI-003`과 `IR-CLI-008`을 새 정책으로 수정하고, `IR-CLI-019` 뒤에 `IR-CLI-020 — completed-work와 add-completed-work 명령` Requirement Block을 추가한다.
6. `IR-CLI-020` AC는 `completed-work` filter, JSON output, `add-completed-work` append, dry-run, pipe rejection을 각각 검증 가능하게 쓴다.
7. `docs/spec/40.mcp-stdio-interface.srs.md`의 `FR-MCP-008`과 `FR-MCP-009`를 새 payload/resource로 수정하고, `FR-MCP-011` 뒤에 `FR-MCP-012 — completed work MCP tools` Requirement Block을 추가한다.
8. `FR-MCP-012` AC는 `list_completed_work`, `add_completed_work`, readOnlyHint, dry-run, structured failure를 각각 검증 가능하게 쓴다.
9. `docs/spec/50.nodejs-implementation.srs.md`의 `FR-NODE-009`를 새 init 정책으로 수정하고, `FR-NODE-009` 뒤에 `FR-NODE-010 — Completed Work Log core service` Requirement Block을 추가한다.
10. `FR-NODE-010` AC는 `CompletedWorkEntry`, parser exposure, query filter, append mutation, pipe rejection, newline preservation을 각각 검증 가능하게 쓴다.

#### Rationale

코드 구현보다 SRS contract가 먼저 고정되어야 `snoworca-coder`가 어떤 behavior를 구현해야 하는지 흔들리지 않는다. 특히 `init --target`의 Active Target 값은 현재 구현과 정반대 정책이므로 문서에서 먼저 확정한다.

#### 함정 / 주의사항

- Completed Work Log는 완료 판정의 source of truth가 아니라 summary다.
- unknown target, scope, requirement ID는 historical row를 고려해 warning으로 둔다.
- `docs/spec/00.index.md` parser는 section number가 아니라 heading text regex로 찾아야 하므로 문서에도 exact number dependency를 요구하지 않는다.
- README 한글/영문 section이 둘 다 있는 경우 같은 command 이름을 반영한다.

#### 구현 가이드

1. `AGENT_INSTRUCTION_VERSION`을 `"1.1"`로 올린다.
2. `renderAgentInstructionSnippet()`에 current work status workflow를 추가한다.
3. snippet에는 Active Target이 비어 있으면 target을 만들지 말고 사용자 확인을 받는 규칙을 넣는다.
4. snippet에는 Completed Work Log를 read-only summary로 읽고, 완료 상태 판정은 Requirement Block을 우선한다는 규칙을 넣는다.
5. current work status workflow는 MCP 우선 기준으로 `get_active_target`, `list_requirements` with `status=in_progress`, `status=blocked`, `status=implemented`, `list_completed_work` 순서를 명시한다.
6. CLI fallback 기준으로 `speckiwi active-target --json`, `speckiwi list --status in_progress --json`, `speckiwi list --status blocked --json`, `speckiwi list --status implemented --json`, `speckiwi completed-work --json` 순서를 명시한다.
7. missing evidence는 `summary` 또는 `summarize_target`의 `missingEvidence` field를 확인하도록 명시한다.
8. `renderIndexTemplate()`의 metadata row를 `| Active Target |  |`로 고정한다.
9. `input.target`이 없으면 Target Map table은 header만 생성한다.
10. `input.target`이 있으면 Target Map에 해당 target row를 `planned` status로 생성한다.
11. index template에 empty Completed Work Log table을 추가한다.
12. init 관련 tests에서 `v1.0` expected heading을 `v1.1`로 갱신한다.
13. stale `v1.0` managed block replacement test를 추가하거나 기존 stale version test에 `v1.0` 입력을 포함한다.

#### Rationale

agent instruction 내용이 바뀌면 version도 바뀌어야 한다. 그렇지 않으면 기존 `v1.0` block이 현재 버전으로 간주되어 새 current work status workflow가 AGENTS.md와 CLAUDE.md에 반영되지 않는다.

#### 함정 / 주의사항

- `findAgentInstructionBlock()`의 regex와 suffix marker 정책은 유지한다.
- marker가 없는 top-level heading은 안전하게 보존해야 한다.
- `initProject()`의 MCP startup auto-init은 같은 `renderIndexTemplate()`를 사용하므로 별도 adapter policy를 만들지 않는다.
- `init --target`이 Active Target을 채우는 기존 tests는 모두 바꾼다.

#### 테스트 작성 지침

- 성공: default init index가 `| Active Target |  |`와 Completed Work Log table을 포함한다.
- 성공: `initProject({ target: "v2.0.0" })` index가 target row `planned`를 포함하고 Active Target은 비어 있다.
- 실패: stale `# SpecKiwi SRS 워크플로 v1.0` block은 `v1.1`로 교체된다.
- 경계: marker가 없는 malformed heading은 유지되고 새 `v1.1` block이 append된다.
