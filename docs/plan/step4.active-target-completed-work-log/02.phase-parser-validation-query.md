## 1. 목표

core parser가 `00.index.md`의 Completed Work Log를 정규화하고, Active Target empty row를 fallback 없는 상태로 보존하도록 만든다. validator는 Completed Work Log와 Active Target inconsistency를 diagnostics로 보고하고, query layer는 CLI/MCP가 공유할 completed work filter를 제공한다.

## 2. 선행 조건

- P1의 SRS와 init template contract가 확정되어 있어야 한다.
- `parseMarkdownTable()`은 escaped pipe를 지원하지 않는다는 전제를 유지한다.
- legacy index compatibility는 `Active Target` row가 없는 경우에만 적용한다.

#### 구현 가이드

1. `src/core/types.ts`에 `CompletedWorkEntry`를 추가한다.
2. `IndexDocument`에 `completedWork: CompletedWorkEntry[]`를 추가한다.
3. `TargetEntry`와 `ScopeEntry`는 변경하지 않는다.
4. `index-parser.ts`에 `findHeadingMatching(lines, /^##\s+\d+\.\s+Completed Work Log$/)` helper를 추가한다.
5. Completed Work Log heading이 없으면 `completedWork`를 빈 배열로 둔다.
6. heading은 있지만 table이 없으면 빈 배열로 둔다.
7. table row mapping은 `Date`, `Target`, `Scope`, `Requirement IDs`, `Summary` column을 읽는다.
8. `Requirement IDs`는 comma split, trim, empty drop으로 `requirementIds` 배열을 만든다.
9. row line은 `table.startLine + 2 + index`로 계산한다.
10. Active Target parser는 metadata row 존재 여부를 검사한다.
11. metadata에 `Active Target` key가 있으면 trim 결과를 그대로 `activeTarget`으로 사용한다. 값이 비어 있으면 `""`를 반환한다.
12. metadata에 `Active Target` key가 없으면 legacy fallback으로 active Target Map row, 첫 target 순서로 찾는다.

#### Rationale

row present/empty와 row missing은 다른 의미다. 이 차이를 parser에서 보존해야 query, CLI, MCP가 target을 임의로 선택하지 않는다.

#### 함정 / 주의사항

- `metadata["Active Target"] ?? ""`처럼 nullish fallback 뒤 `|| target`을 붙이면 explicit empty row가 깨진다.
- Completed Work Log가 없는 legacy workspace를 error로 만들지 않는다.
- `line`은 diagnostics 위치를 위한 optional metadata이므로 table parser에 새 row type을 강제하지 않는다.
- fixture index에 Completed Work Log table을 넣으면 기존 test snapshot 성격의 assertion도 같이 갱신한다.

#### 테스트 작성 지침

- 성공: `valid-basic` fixture는 `completedWork` row를 1개 이상 반환한다.
- 성공: empty Completed Work Log table은 빈 배열을 반환한다.
- 성공: explicit `| Active Target |  |`는 `workspace.index.activeTarget === ""`다.
- 경계: Active Target row를 제거한 legacy index는 Target Map active row로 fallback한다.
- 경계: `Requirement IDs` cell이 비어 있으면 `requirementIds: []`다.

#### 구현 가이드

1. `CompletedWorkFilter` interface를 `src/core/query/completed-work.ts`에 둔다.
2. filter field는 `target?: string`, `scope?: string`, `since?: string`, `limit?: number`로 시작한다.
3. `listCompletedWork()`는 `workspace.index.completedWork`를 입력 순서 그대로 사용한다.
4. target filter가 없으면 모든 Completed Work Log row를 반환한다.
5. target filter가 있으면 entry target이 같은 row와 target이 비어 있는 cross-target row를 함께 반환한다.
6. scope filter는 comma-separated `entry.scope` 안의 trimmed token과 비교한다.
7. since filter는 lexicographic `YYYY-MM-DD` 비교를 사용한다.
8. limit는 양수일 때만 slice한다.
9. `TargetSummary`에 `completedWork: CompletedWorkEntry[]`를 추가한다.
10. `summarizeTarget()`은 target이 비어 있으면 current requirement summary는 empty target 기준으로 계산하되 `completedWork`는 unfiltered rows를 반환한다.
11. `summarizeTarget(workspace, "v1.0.0")`은 target-specific rows와 targetless cross-target rows를 함께 반환한다.
12. `resolveActiveTarget()`는 `workspace.index.activeTarget`만 반환한다. legacy fallback은 parser에서 이미 처리한다.
13. validator는 Completed Work Log warning diagnostics를 추가한다.
14. invalid date는 `SRS-W011`, unknown target은 `SRS-W012`, unknown scope token은 `SRS-W013`, unknown requirement ID는 `SRS-W014`, non-completed requirement status는 `SRS-W015`로 둔다.
15. non-empty Active Target unknown target error `SRS-E017`과 inactive row warning `SRS-W010`은 유지한다.
16. empty Active Target은 valid이며 diagnostics를 만들지 않는다.

#### Rationale

Completed Work Log는 historical summary이므로 hard error로 막지 않는다. 단, source-of-truth와 어긋나는 row는 agent가 볼 수 있어야 하므로 warning을 낸다.

#### 함정 / 주의사항

- `resolveActiveTarget()`가 Target Map fallback을 다시 수행하면 P2-001의 row semantics가 무효가 된다.
- scope column은 `CLI, MCP`처럼 여러 값을 가질 수 있으므로 단순 equality만 쓰지 않는다.
- targetless Completed Work Log row는 cross-target summary로 취급한다. target filter가 있어도 이 row를 숨기지 않는다.
- requirement status conflict는 `implemented`와 `verified`만 completed row로 인정한다.
- release readiness는 Completed Work Log warning을 release blocking으로 승격하지 않는다.

#### 테스트 작성 지침

- 성공: target/scope/since/limit filter가 각자 동작한다.
- 성공: target summary가 target-filtered `completedWork`를 포함한다.
- 성공: target filter는 targetless cross-target row를 포함한다.
- 성공: empty Active Target summary는 completed work rows를 숨기지 않는다.
- 실패: invalid date warning이 나온다.
- 실패: unknown requirement ID warning이 나온다.
- 실패: planned 또는 in_progress requirement를 가리키는 row는 conflict warning을 낸다.
- 경계: empty Active Target은 validation errors를 만들지 않는다.
