## 1. 작업 목적

이 계획은 Active Target의 초기화 정책을 명시적 빈 값 모델로 바꾸고, `docs/spec/00.index.md`에 Completed Work Log를 추가하기 위한 구현 계획이다. 구현 후 새 workspace는 Active Target을 자동 선택하지 않고, 완료 작업 요약은 index-level rollup으로 조회와 추가가 가능해야 한다.

완료 후 coding agent는 "현재 작업 진행중인 목록과 상태" 요청에 대해 Active Target, 현재 진행/차단/검증 누락 요구사항, Completed Work Log를 조합해서 답할 수 있어야 한다.

## 3. 프로젝트 온보딩 컨텍스트

SpecKiwi는 Git 저장소 내부의 Markdown SRS를 source of truth로 쓰는 Node.js TypeScript CLI와 stdio MCP server다. 핵심 흐름은 `docs/spec/00.index.md`와 scope SRS 파일을 parser가 읽고, validator/query/mutation core service를 CLI와 MCP adapter가 공유하는 구조다.

주요 디렉토리 맵:

| Path | Role |
|---|---|
| `src/core/types.ts` | parser, query, mutation이 공유하는 normalized type |
| `src/core/parser/` | index와 Requirement Block parser |
| `src/core/validator/` | workspace diagnostics rule registry |
| `src/core/query/` | target summary, requirement lookup, completed work filter 추가 지점 |
| `src/core/mutation/` | Active Target과 Completed Work Log line patch mutation |
| `src/core/bootstrap/` | init template과 AGENTS.md/CLAUDE.md managed block |
| `src/cli/commands/` | Commander 기반 read/mutation command 등록 |
| `src/mcp/` | MCP tools, resources, SDK server bridge, schemas |
| `test/fixtures/workspaces/` | parser/CLI/MCP regression fixture |
| `docs/spec/` | 제품 SRS source of truth |

핵심 규칙:

- Completed Work Log는 완료 상태의 source of truth가 아니다. Requirement Block의 `Status`, Acceptance Criteria, Verification Evidence, Change Notes가 우선한다.
- `Active Target` metadata row가 존재하고 값이 비어 있으면 active target은 비어 있는 상태로 유지한다.
- `Active Target` metadata row가 없는 legacy index에서만 Target Map의 `active` row와 첫 target fallback을 허용한다.
- `init --target`은 Target Map row를 만들 수 있지만 Active Target 값은 비워 둔다.
- target 활성화는 `set-active-target` CLI 또는 MCP `set_active_target`으로만 수행한다.
- `AGENTS.md`와 `CLAUDE.md` managed block은 내용 변경에 맞춰 `v1.1`로 올린다.

## 8. Feasibility 요약

| Area | Feasibility | Risk | Mitigation |
|---|---|---|---|
| Active Target empty semantics | Medium | 현재 interim 구현과 테스트가 fallback을 전제로 한다. | row 존재 여부를 parser에서 분리하고 tests를 먼저 갱신한다. |
| Completed Work Log parser | Low | existing table parser가 pipe escape를 지원하지 않는다. | mutation input의 pipe 문자를 거부한다. |
| Completed Work Log validation | Medium | historical row가 renamed ID를 가리킬 수 있다. | error가 아닌 warning으로 제한한다. |
| CLI/MCP surface | Medium | tool/schema/resource list 변경으로 integration tests가 깨진다. | read/mutation schema와 stdio tests를 같은 Phase에서 갱신한다. |
| Agent instruction v1.1 | Low | stale v1.0 block 교체 회귀 가능성 | version replacement tests를 확장한다. |

이번 구현의 범위는 다음이다.

- `Active Target` metadata row의 빈 값 정책
- Completed Work Log parser, validator, query, append mutation
- CLI `completed-work`, `add-completed-work`
- MCP `list_completed_work`, `add_completed_work`, `speckiwi://completed-work`, `speckiwi://completed-work/{target}`

이번 구현에서 제외하는 범위:

- escaped pipe를 포함한 Markdown table cell round-trip
- separate `work-status` convenience command와 MCP `get_work_status`
- Completed Work Log를 release readiness gate로 승격

## 12. 완료 기준

- init으로 생성한 index는 `| Active Target |  |`와 빈 Completed Work Log table을 포함한다.
- `init --target v1.0.0`은 Target Map row를 만들지만 Active Target 값을 비워 둔다.
- legacy index에 `Active Target` row가 없으면 기존 fallback이 동작한다.
- explicit empty Active Target row는 fallback하지 않는다.
- `workspace.index.completedWork`가 table rows를 정규화한다.
- CLI와 MCP가 completed work read/add 동작을 core service로 처리한다.
- `AGENTS.md`와 `CLAUDE.md` managed block은 `# SpecKiwi SRS 워크플로 v1.1`로 생성/교체된다.
- `npm run typecheck`, `npm run lint`, `npm test`, `npm run release:check`가 통과한다.

## 13. 용어집

| Term | Meaning |
|---|---|
| Active Target | 현재 작업 대상 version을 가리키는 `00.index.md` metadata 값이다. 빈 값은 target 미선택을 뜻한다. |
