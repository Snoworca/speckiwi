## 5. Target naming — the convention the user set

**A target is never named by a bare version.** Use `{version}-phase{n}-{feature}`:
`2.5.2-phase1-target-lifecycle`, `2.6.0-phase1-kiwi-orchestrator`,
`2.6.0-phase2-parallel-lanes`.

The reason is concrete: when a target is named by its release version, splitting the work forces a new
release number to be invented as a side effect. That happened once in this session — a committee cut a
scope and "v2.7.0" appeared in the write-up, a release nobody had decided on. With phase targets, both
phases can still ship in one version, and that stays a separate decision.

Historical targets (`v2.3.0`, `v2.4.0`, `v2.5.1`, …) keep their names. They are released; renaming
them would rewrite history.

## 7. Traps — every one of these was paid for

**Verification and agents**

- **A failed agent is not an agent that found nothing.** This bit twice: a loop's dry-run detector
  counted rate-limited agents as "0 findings" and reported convergence that was never observed. The
  workflow now records an incomplete round and stops. Always check the failure list before believing a
  clean result.
- **A subagent's final turn text does not reach the main session.** Instruct it to `SendMessage` to
  `main`, and to send an interim report rather than lose everything.
- **A subagent worktree is created at the session's starting HEAD** and cannot see uncommitted work.
- **Instructions do not constrain scope; an exact string does.** A pass told "change numbers only"
  expanded 10 of its 28 edits anyway. A pass given exact replacement strings produced a diff
  containing exactly the authorised hunks and nothing else — and correctly *refused* two items whose
  strings did not match rather than reconstructing them. Use exact strings for corrective passes.

**Tests that look like tests**

- **`expect(command.opts().exitCode).not.toBe(0)` is vacuous.** Delete the assignment and the option
  is never set, so `undefined !== 0` passes while the defect is present. Use
  `expect(await main([...], io)).toBe(5)` — `main()` returns the real exit code.
- **`expect(help).not.toContain("a, b, or c")` is vacuous** when commander wraps the help at ~80
  columns. Collapse whitespace and assert positively.
- **A mutation probe that does not match removes nothing.** One probe reported the guard "not held"
  because its replacement string never matched; the file was unchanged. Print the removed byte count
  or check the built output before believing a probe.
- **Derive expected vocabularies from the rules document**, never restate them in the test. Adding a
  row to the table put five tests red with the runtime untouched — that is the mechanism working.

**Mechanics**

- **Never run `node -e "…"` with backticks inside double quotes.** Bash command-substitutes them and
  the tokens vanish silently. Use the Edit tool or a `.mjs`/`.cjs` file. This has now cost time in
  three separate sessions.
- **The MCP server holds the build it started with.** After changing `src/`, MCP calls run the old
  code; use `node bin/speckiwi` for anything that must exercise the change.
- **Always `npx vitest run --no-file-parallelism`.**
- **`add_requirement` rejects a free-text `changeNotes`** — omit it and the tool writes the Created row.
- **`set_target_goal` caps the goal at 500 characters.** Measure before sending.
- **Trace-link rows are addressed by `rowIndex`, not `rowId`** — only verification evidence has ids.
- **A `verified` requirement refuses granular edits.** Demote to `in_progress`, amend, add a change
  note, re-check the criteria, re-verify.
- The hermeticity guard fails any test that writes init/skill output into the repository root, deletes
  the evidence, then throws; it journals to `%TEMP%/speckiwi-hermeticity/pollution.log`.

## 8. One habit worth keeping

Every audit run in this session found something behind a green suite — the per-AC mutation audits, the
count-claim audit, the release review, and the review of the review's own fixes. The last of those
found a hollow assertion **written earlier in the same session while fixing a different hollow
assertion**. Green is not evidence. Break the implementation, watch the named test fail for the right
reason, restore, and only then believe it.
