`2.13.0-lifecycle` 에서 범위 밖으로 남긴 것도 둘 있다:

- **`install --reinstall`** — "스킬이 깨져 다시 깔고 싶다"를 `remove` 로 풀게 두면 중간 상태가 *스킬 없음*이다. 도구가 지금 "remove that directory to reinstall" 이라 안내하며 사용자를 2단계로 몬다.
- **doctor 의 폐기 전역 스킬 보고** — drift 루프가 소스 집합만 순회해 소스에 없는 이름은 검사 대상에 없다. 다만 프로젝트 `remove` 가 전역 잔여를 보고하므로 도달 경로는 있다.

**보고만 하고 고치지 않은 것 하나** (`2.13.0` 작업 중 발견): `classifyExistingDestination` 은 identity 만 보고 내용이 다르면 `update` 를 내며, `executeOne` 은 성공 시 백업을 지운다. 즉 **사용자가 수정한 스킬은 다음 `speckiwi init` 한 번에 복구 불가능하게 사라진다.** `remove` 의 checksum 게이트는 이걸 고치지 못한다. 2026-08-19 에 전역 스킬을 갱신하지 않기로 한 근거가 이것이다.

## 4. 이 저장소에서 절대 하지 말 것

- **`speckiwi init`(특히 `--force`), `speckiwi skills install`, `speckiwi upgrade`, `speckiwi remove` 를 이 저장소 대상으로 실행하지 않는다.** `--force` 는 `docs/spec/00.index.md` 를 템플릿으로 덮어써 요구 인덱스를 파괴한다(무증상). `speckiwi skills mirror --write` 는 허용되며 `.agents/skills/**` 의 유일한 정당 writer 다.
- **`git checkout` / `restore` / `stash` / `clean` / `reset --hard` 금지.**
- 검증 서브에이전트가 `C:\Users\beom\.claude` 나 `.codex` 에 쓰지 않게 한다.
- `npm install` 을 맨으로 돌리지 않는다 — 셸에 `NODE_ENV=production` 이 걸려 devDependencies 가 정리되고 빌드가 깨진다. 빌드/pack 은 `NODE_ENV=development`, 테스트는 `NODE_ENV=test`.
- 커밋 메시지에 어떤 시그니처도 넣지 않는다(`Co-Authored-By`, `Generated with/by`, `[bot]`, `🤖` …). 커밋 직후 `git log -1 --format="%B"` 로 0 건을 확인한다. 제목에 `Phase {n}` 같은 진행 표식도 넣지 않는다.

## 5. 값을 치른 교훈

**새 요구를 쓰기 전에 기존 요구를 검색한다.** `FR-NODE-193` 이 기존 요구 **셋**과 충돌했다 — `FR-NODE-021` 이 `verified` 상태로 "trailing LF **enforcement**"를 *거부*로 규정하고 있었고, `FR-NODE-125` 의 존재 이유 자체가 이번에 고친 결함이었다. 스위트 5 건이 깨진 뒤에야 알았다. 회귀가 아니라 **모순**이었다.

**뮤테이션 없이 "테스트가 지킨다"고 말하지 않는다.** 공허하게 통과한 테스트를 **다섯 개** 잡았다:
- 부트스트랩 테스트가 락을 거치지 않는 함수를 겨눠 **수정 전에도 통과**
- `error` 차단 경로가 도달 불가능(필터를 비워도 green)
- `kiwi/` 디렉터리 존재만 비교(init 이 이미 만들어 놓아 차이 없음)
- 쓰기 실패 픽스처가 읽기 단계에서 먼저 걸려 **예외가 발생하지 않음**
- 사용자 훅을 엉뚱한 이벤트에 넣어 요구가 명시한 케이스를 미검증

**"기존 결함"이라 부르기 전에 원인을 확인한다.** 세션 내내 기존 결함으로 넘긴 `FR-NODE-125 AC-4` 는 결함이 아니라 **검사가 과거 시점을 표현하지 못한 것**이었다. 코드는 옳았다.

**도구가 보고하는 `updated` 는 내용 차이가 아닐 수 있다.** 전역 스킬 갱신을 돌리기 전에 설치본과 소스를 바이트 비교했더니 34 개 `updated` 보고와 달리 **차이 0** 이었다. 파괴적 경로는 보고가 아니라 실측으로 판단한다.

**함정 목록:**
- `skills/**` 와 `src/core/skills/install-skill.ts` 는 **CRLF**. 개행을 포함한 치환/앵커 패턴은 조용히 빗나가고, 뮤테이션 SKIP 을 RED 로 오인하기 쉽다.
- CLI 는 `node bin/speckiwi` 로 부른다. `node dist/cli/index.js` 는 **출력 없이 exit 0**.
- 셸에서 백틱 포함 문자열을 `node -e` 로 넘기면 **명령 치환**된다. 파일로 써서 실행할 것. 윈도우 경로가 든 문자열도 마찬가지로 `node -e` 에 인라인하지 말 것 — 백슬래시가 이스케이프로 먹힌다.
- Windows 경로는 JSON 안에서 `\\` 로 이스케이프된다. 직렬화된 페이로드에 raw 경로로 `toContain` 하면 정상 동작을 실패로 읽는다.
- 전체 스위트는 `npm test` 로 돌린다(`--no-file-parallelism` 포함). 맨 `npx vitest run` 은 timeout 이 쏟아진다. 출력을 `tail` 로 자르면 실패 목록이 사라진다.
- 검사를 쓸 때 **부정문을 위반으로 읽지 않는지** 확인한다 — 토큰 동시출현은 주장과 그 부정을 구별하지 못한다.
