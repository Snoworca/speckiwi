## 1. What this work is, and why

The target ships **kiwi-orchestrator phase 1**: a skill that carries work from an unclear intent to
merged, verified code — intake, wave decomposition, English handoff documents for coding agents,
per-task parallelisability analysis, and scale/scope routing. Execution is serial at the host root;
concurrent lane execution is `2.6.0-phase2-parallel-lanes` and is deliberately out of scope.

**The character of the work on this branch is not "build the remaining features".** The features were
built; 103 requirements are `verified`. What this branch has been doing for several sessions is
closing the gap between *what a requirement claims* and *what the code does* — and that gap has had a
recognisable shape every single time:

- **The predicate is correct, it is tested, and nothing calls it.** Seven kernels with no caller.
  `scanProse` with no caller. `computeRunProgress` with no caller.
- **The criterion is ticked and the assertion behind it cannot fail.** Found four times now:
  `FR-NODE-108` AC-2, `FR-NODE-164` AC-1 and AC-5, and the `@ts-expect-error` census.
- **The comment asserts a mechanism that is not there.** `prose-gate.ts` claiming a caller;
  `pinning.ts` claiming a §13 row; `computeRunProgress` naming a discriminator its code did not use.

Every remaining item in §5 is one of those three shapes. Expect that, and attack the claim rather
than the code.

- **Item 4's blocker was solved by taking the branch the item itself offered.** It said to scope
  `denominator-mismatch` to terminal verdicts, then immediately noted that doing so loses the

### 4.1 What the next session should do first

**Dispatch the verification passes before starting any new item.** Two lenses per requirement, both
given unbiased inputs — the requirement, the diff, the commit sha — and *not* the author's reasoning:

1. **Evidence carriage.** For each ticked criterion: is there an assertion that can actually fail if
   the stated property is violated? Prove it by mutation — change the product, never the test, and
   restore bytes exactly. Report vacuity: assertions passing because a collection is empty, a glob
   resolved to nothing, or the environment happens to hold.
2. **Behaviour regression.** Does the change alter anything beyond the paths it names? Census every
   consumer. Check for set-equality comparisons, counts, and enumerations that a growth or narrowing
   would move.

Every requirement above records its own measurements in its evidence rows, including which criteria
were **green from the first run** and were therefore evidenced by mutation rather than by red-first.
A verifier should attack those hardest — they are where a vacuous assertion would hide.

## 6. Constraints that bind the next session

Each has a recorded incident behind it. The first eleven are carried forward; 12–14 are new this
session.

1. **TDD, test-first.** Write the failing test, observe it fail, then implement. Work written
   implementation-first is discarded and redone.
2. **Verification goes to a subagent.** Never verify your own judgment calls. Objective counts are
   exempt; "does this evidence carry this criterion" is not.
3. **The subagent spawn cap is 200 per session.** Budget for it and spend it on §4 first. If it is
   hit, say so in the report rather than silently self-verifying.
4. **`grep -a`, never plain `grep`, for any source census.** Four files under `src/` carry literal NUL
   bytes (`conflict.ts` 1, `handoff.ts` 2, `resume.ts` 2, `parser/workspace-parser.ts` 1); plain grep
   prints `Binary file … matches` and the census both under-reports and counts that notice as a hit.
5. **Every probe must assert its own guard held.** `assert old in s` before writing, `assert new != old`
   after, and compare sha1 before and after the restore.
6. **A non-vacuity guard must not depend on incidental state.** A guard that passes because of the
   environment rather than the property is not a guard. Worked example from this session:
   `needsFinalVerify` is *also* false when the wave map is empty, so asserting it false after an
   append proves nothing unless the baseline is pinned first.
7. **No signature of any kind in commit messages** — no `Co-Authored-By`, no "Generated with", no
   `[bot]`, no 🤖. Verify with `git log -1 --format="%B"` after every commit. No `Phase {n}` /
   `Step {n}` / `TASK-XXX` in commit **titles**.
8. **Never run `speckiwi init`, `speckiwi skills install` or `speckiwi upgrade --apply` against this
   repository as the target root.**
9. **`docs/spec/` is the only source of truth.** No behaviour ships without a requirement; nothing is
   marked `verified` without evidence; no bulk-archive or bulk-finalize tooling.
10. **When a line number decides an argument, print the heading above it.** An earlier session
    asserted `SKILL.md:1037` was `§V.verify-design`'s gate line; it belongs to `§V.freeze-design` at
    `:1034`.
11. **Author the requirement before the code.** Every behaviour change this session went
    requirement → red test → implementation, and the requirement is where the rejected alternatives
    and their measurements are recorded.
12. **Apply a probe patch from a script file, never a shell heredoc, when the patch contains
    backslashes.** This session's heredoc collapsed doubled backslashes and injected a literal
    backspace (U+0008) instead of a word-boundary assertion, which reported 18 and 19 red where the
    truth was 6 and 6. The wrong number was three times the real blast radius and would have gone
    into an evidence row.
13. **`docs/next/*.md` is checked out CRLF.** A multi-line anchor written with `\n` will not match.
    Normalise in and out, or anchor on single lines.
14. **When a fixture and the product disagree, suspect the fixture first.** Three of this session's
    fixtures were refused by `truncated-residual` during a green pass; the rule was right and the
    fixtures were wrong. Fixing the product there would have disabled a live completeness check.
