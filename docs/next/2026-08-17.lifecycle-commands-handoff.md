## 2. 설계에서 절대 흔들면 안 되는 것

1. **`docs/spec/` 은 어떤 플래그로도 열리지 않는다.** 옵션이 존재하는 순간 그것을 켜라고 조언하는 문서나 에이전트가 생긴다 — `init --force` 가 doctor 안내를 타고 요구사항을 지운 경로가 정확히 그것이다.
2. **`-g` 는 생성 명령에서 가산, 파괴 명령에서 배타.** 이 CLI 는 이미 두 의미를 쓰고 있었다(`init -g` 가산, `skills install -g` 선택자). 파괴 쪽은 오해했을 때 덜 지우는 의미를 택한다.
3. **맨 `speckiwi remove` 는 거부한다.** 규칙: *맨 명령이 재실행으로 되돌릴 수 없는 상태를 파괴할 수 있으면 기본값을 두지 않는다.* 이 규칙이 `init`/`upgrade`(기본값 있음)와 `skills mirror`/`remove`(없음) 세 선례를 모두 설명한다.
4. **모드 게이트를 안전 근거로 계상하지 마라.** 주 소비자는 에러가 지목한 플래그를 붙여 재시도하는 에이전트다. 실제 안전은 홈-루트 가드 · 마커 검증 · drift skip 이 진다.
5. **전역 목적지 해석은 `resolveSkillDestinationRoot` / `resolveGlobalSkillContext` 로만.** IR-CLI-086 이 세 진입점 불일치를 기록했고, remove 가 어긋나면 **아무것도 못 지우고 성공을 보고**한다.

## 3. 검증 2축이 잡은 것 — 전부 수정·뮤테이션 확인

두 축이 **독립적으로 같은 CRITICAL** 을 찾았다.

### 가드는 있었는데 발화하지 않았다 (CRITICAL)

`resolveProjectRoot` 는 루트를 `realpath` 로 정규화하는데 홈은 `HOME`/`USERPROFILE` 원문이다. 문자열 비교라 **같은 디렉터리가 두 문자열**이 되어 가드가 통과시켰다. junction 홈과 대소문자만 다른 홈 양쪽에서 **전역 스킬이 실제로 삭제됐고**, `ok:true`·`complete:true`·exit 0 으로 보고됐다.

요구의 Rationale 이 그 시나리오를 정확히 적어두고 설계한 가드였다. **위험을 알고도 비교 한 줄에서 틀렸다.**

기존 테스트가 못 잡은 이유가 더 중요하다 — **루트와 홈에 같은 문자열을 넘겼다.** 그런 테스트는 문자열 비교만 하는 구현에서도 통과한다. 지금은 두 스펠링을 쓰는 케이스가 있다.

### 공유 미러는 소유를 증명하지 않고 지웠다 (HIGH)

`_shared/kiwi` 정리에 스킬 디렉터리를 지키는 4중 판정이 **하나도** 적용되지 않았다. 전역에서 사용자 파일까지 삭제됐다. **참조되지 않음은 소유되지 않음과 다른 사실이다.** 이제 번들 소스가 같은 상대경로에 같은 바이트를 가질 때만 지운다.

### 파괴 후 예외가 보고를 삼켰다 (HIGH)

읽기 전용 설정 파일이 34개 디렉터리 삭제 후 실행을 중단시켰고, 호출자는 `removed` 도 `kept` 도 없는 에러 봉투를 받았다. **`kept` 는 손으로 처리할 목록인데 그것이 필요해지는 순간 사라졌다.** 단계별 격리로 수정.

### 나머지

거짓 "removed" 보고(인식 못 하는 훅 형태), 중복 관리 블록 미제거, `-g` 가 프로젝트에 락 파일 생성, CRLF 를 "편집했다"로 오인, 빈 훅 이벤트 임의 삭제 — 전부 수정·테스트 부착.

## 4. 뮤테이션이 내 테스트 3개의 공허한 통과를 잡았다

기록해 둘 가치가 있다. 셋 다 **다른 단언이 우연히 만족돼** green 이었다.

1. **matcher 그룹 케이스 부재** — 사용자 훅을 `Stop`(다른 이벤트)에 넣어, 요구가 명시한 "같은 그룹 안의 사용자 명령"을 한 번도 검증하지 않았다.
2. **`kiwi/` 존재만 비교** — init 이 이미 만들어 놓아 락을 잡든 말든 같았다. 내용 비교로 교정.
3. **쓰기 실패 픽스처가 읽기에서 걸렸다** — 파일 자리에 디렉터리를 놓으니 `readFile` 이 먼저 실패했고, 그 경로는 이미 예외 없이 처리된다. `chmod 0o444` 로 교정.

**교훈: 뮤테이션 없이는 "테스트가 지킨다"를 말할 수 없다.** 셋 다 검증 없이 넘어갔다면 무방비인 게이트를 지켜진다고 보고했을 것이다.

CRLF 함정도 재발했다 — `install-skill.ts` 가 CRLF 라 개행을 포함한 앵커가 조용히 빗나갔고, **SKIP 을 RED 로 오인할 뻔했다.** 뮤테이션 스크립트는 단일 줄 앵커만 쓰고 `no tests`/파싱 실패를 INVALID 로 분리한다.

## 6. 범위 밖으로 남긴 것 (보고만)

- **`install --reinstall`** — "스킬이 깨져 다시 깔고 싶다"는 remove 로 풀 문제가 아니다. 도구가 "remove that directory to reinstall" 이라 안내하며 사용자를 2단계로 몰고 중간 상태가 *스킬 없음*이다.
- **install/update 경로의 checksum 부재** — `classifyExistingDestination` 은 identity 만 보고, `executeOne` 은 성공 시 백업을 지운다. 즉 **사용자가 수정한 스킬은 다음 `init` 한 번에 복구 불가능하게 사라진다.** remove 의 checksum 게이트는 이걸 고치지 못한다.
- **doctor 의 폐기 전역 스킬 보고** — drift 루프가 소스 집합만 순회해 소스에 없는 이름은 검사 대상에 없다. 다만 프로젝트 remove 가 전역 잔여를 보고하므로 도달 경로는 있다.
