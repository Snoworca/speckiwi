# Part B — Decided work: `speckiwi upgrade`

## B.1 The problem, measured

Running the new `init` against a simulated old-version consumer project upgraded most things and left two gaps. Both were reproduced, not reasoned about.

**What `init` already upgrades** (verified in a temp project seeded with v1.0.0 rules, a Korean v1.6 agent block, and decade-numbered scope documents):

- `docs/rule/` → both 2.5.0 documents installed, both v1.0.0 documents reported in `removed`
- the index `| Rules |` row → raised to 2.5.0, surgically, one line
- the agent block → the Korean v1.6 block replaced in place with v1.9; exactly one block; zero Hangul; the consumer's own `# Consumer Agent Notes` and `# My Own Section` preserved byte-identical
- next scope document → `11.reporting.srs.md`, one above the existing `10.`, and the existing document was not renamed

**Gap 1 — a reference to a pruned rules document is not repaired.** The simulated project's `AGENTS.md` line 3 read `For rules read [SRS-MD-Rules-v1.0.0.md](docs/rule/SRS-MD-Rules-v1.0.0.md)`. After init that file no longer exists and the line is unchanged: a dangling link on the first instruction a reader meets. This is not hypothetical — this repository's own `CLAUDE.md` and `AGENTS.md` carried exactly that line and had to be fixed by hand in `a849d12`, and three shipped skills carried the same defect, fixed in `24dd1fe`.

**Gap 2 — a missing `| Rules |` row is never inserted.** `src/core/bootstrap/init-project.ts:361` guards with `if (!line.startsWith("| Rules |") || line.includes(BUNDLED_SRS_RULES_FILENAME)) return line;` — it only ever *replaces* an existing row. A project whose index has no Rules row therefore keeps none, and `doctor` warns forever. The remediation string at `src/core/health/doctor.ts:176` admits it: "Add a Rules row to docs/spec/00.index.md pointing at …". Reproduced: after init, the index still had zero Rules rows and doctor reported `cannot determine the installed rules version; bundled is v2.5.0`.

## B.2 Why this is a new command and not more `init`

Both gaps require **editing author-owned content**. That `init` does not do so is a contract, not an oversight: `--force` silently deleted requirements — the CRITICAL that opened this whole line of work — and `FR-NODE-085` closed it by dividing the world into tool-owned artifacts (the rules documents, the managed agent block, the index Rules row) and author-owned ones (the index body, the scope SRS documents, the appendix, the step state). Widening `init` to rewrite author files re-opens the same failure mode.

So `upgrade` is an explicit, opt-in migration that **defaults to dry-run**, in the shape `repair requirement-id-collisions` already established (`src/cli/commands/repair.ts`, sub-commands `diagnose` / `plan` / `apply`). The user sees the plan and approves it.

> **SUPERSEDED 2026-08-06 — the default is now the other way.** `IR-CLI-088` discarded `IR-CLI-076`: `speckiwi upgrade` performs the migration and `--dry-run` prints the plan, matching `init`. `--apply` is still accepted and asks for the same performed run. What follows in §B.2 and §B.3 is the v2.5.1 design as it was decided and shipped; it is kept as a record, and the current contract is `IR-CLI-088`.

## B.3 Surface

```
speckiwi upgrade            # print the plan, write nothing (default)  ← SUPERSEDED: now performs
speckiwi upgrade --apply    # perform it                               ← still accepted, same run
speckiwi upgrade --json     # the standard mutation result envelope
speckiwi upgrade --dry-run  # ← IR-CLI-088: this is what prints the plan now
```

Behaviour:

1. **Tool-owned refresh** — delegate to `initProject` rather than reimplementing it. That covers the rules documents and their prune, the index Rules row when present, the agent block, the skills, and the hook scaffold.
2. **Insert a missing `| Rules |` row** into the index metadata table, surgically, positioned like the template's (`renderIndexRulesRow()` is the single source for the row text).
3. **Repair references to a rules document that no longer exists.** Rewrite to the bundled filename and report every change as `file:line`. Scope the search deliberately — `AGENTS.md`, `CLAUDE.md`, `agents.md`, and `docs/**/*.md` excluding `docs/spec/**` (a requirement body must never be rewritten by this command). Match both spellings, because only matching the first is the exact bug that shipped in `a849d12`: the path form `SRS-MD-Rules-v1.0.0.md` **and** the prose form `SRS-MD Authoring Rules v1.0.0`.
4. **Report a stale hook, never overwrite it.** Hooks stay untouchable; the plan says which one is old.
5. **Print what it will not do**, so a reader does not assume more: it never renumbers a scope document, never edits a requirement body, never touches the Target Map.

`doctor` diagnoses; `upgrade` performs the subset of those diagnoses that is safe to automate. Keep that division — it is the reason both commands stay comprehensible.

# Part C — Do not re-open

- **`upgrade` is separate from `init`, and dry-run by default.** The reason is in B.2: `init` not touching author content is what closed the `--force` data-loss CRITICAL. Folding these gaps into `init` undoes that.
- **Existing scope documents are never renumbered.** A project numbered by tens is valid; its next document is one above its highest. `upgrade` inherits this — it must not "tidy" numbering.
- **Requirement bodies are out of scope for reference repair.** `docs/spec/**` is excluded deliberately. A requirement that cites an old rules version is a governance edit, not a migration.
- **Both spellings must be matched.** Path form and prose form. Matching only the path form is the bug that shipped in `a849d12` and had to be fixed in `24dd1fe`.
- **Sequential numbering, first document `01`.** Settled with the user; the tool, the rules document §5.2, the three skill variants and the injected agent block all state it identically now.
- **The tool's own sidecars do not drive allocation.** Counting `90.appendix.md` would push a project's second scope document to `91`.
- **Nothing is promoted to `verified` without a per-AC mutation audit.** The v2.5.0 pass found a checked-`[x]` AC that was factually false and four assertions that passed with the text they pinned deleted. A green suite is not evidence on its own.
