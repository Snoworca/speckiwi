## 3. 다음 작업 — MCP per-call worktree root

### 3.1 목적

사용자는 **대부분 워크트리에서 작업하는데 세션은 메인 세션**이다. MCP root 는 서버 프로세스 cwd 에 결속돼 세션 도중 옮길 수 없으므로, 워크트리의 plan·세션 상태·저널에 도구가 닿지 못한다.

**사용자 판정(2026-08-16)**: 기동 인자 금지는 타당하나 **메서드 인자까지 금지하는 것은 잘못이다.** 요구를 물리고 바꾼다.

### 3.2 조사 결론 (상세는 research 18)

100개 도구 중 **필요한 것은 53개**, 47개는 필요 없다.

| 군 | 수 | 판정 |
|---|---|---|
| **A. SRS 계열** | 47 | **열지 않는다.** worktree-lane 계약(`FR-FLOW-122`)이 "모든 SRS mutation 은 호스트 소유"로 못박음. 열면 요구 ID 가 두 곳에서 발급돼 `SRS-E002` 중복 |
| **B. `workflow_*`** | 26 | **연다.** `docs/plans`·`.kiwi/sessions`·`kiwi/pipeline.jsonl` 은 워크트리 지역 상태 |
| **C. `orchestrate_*`** | 27 | **연다** — 단 `replay_apply`(호스트 전용) · `preflight`(위상 판정 게이트) 예외 |

**핵심**: `workflow_*` 26개는 **이미 `path` 인자를 받는다.** 문제는 인자 부재가 아니라 **해소 기준** — `artifacts.ts:119/:286` 이 전부 `path.join(root, …)` 로 MCP root 에 접합한다. 이 작업은 "인자 추가"가 아니라 **경로 해소를 root 고정에서 호출자 지정으로 여는 것**이다.

### 3.3 착수 차단 — 반드시 이것부터

> **선행조건 (c) 조사**: `pinning.ts` 의 `ls-tree --full-tree` 가 워크트리에서 **어느 최상위 기준**으로 경로를 내는지 실측.

워크트리는 git common dir 을 호스트와 공유한다. 이 확인 없이는 나머지가 안전한지 판정할 수 없다. **다른 단계보다 먼저 한다.**

### 3.4 작업 순서

| # | 작업 |
|---|---|
| 0 | **선행조건 (c) 조사** ← 착수 차단 |
| 1 | **SRS** — `REL-MCP-004` supersede. AC-4(기동 금지) 계승 + AC-3(per-call 금지) 철회 + 안전 게이트 셋 + envelope 확장 |
| 2 | **경로 해소 seam** — `path.join(root, …)` 호출부를 단일 resolver 로 모음 (동작 무변경 리팩터) |
| 3 | **게이트 구현** — git common dir 대조, SRS 경로 fail-closed, 진단 코드 3종 |
| 4 | **B군 26개** — `workspaceRoot` 노출, resolver 경유 |
| 5 | **C군 25개** — 동일, 예외 2개 별도 처리 |
| 6 | **문서** — README §5, `worktree-lane.md`, agent instruction |

### 3.5 설계 요지

```
workspaceRoot?: string   // 절대 경로. 생략 시 현행 동작(MCP root)
```

- 이름은 `root` 아닌 `workspaceRoot` — envelope 이 이미 그 이름을 쓴다(진입점 하나 원칙)
- **절대 경로만.** 상대를 허용하면 "무엇에 대한 상대인가"가 다시 모호해진다
- 안전 게이트: git common dir 이 MCP root 와 **같아야** 함(sibling 저장소 거부), SRS 경로는 fail-closed
- `rootSource` 에 `per-call-workspace-root` 추가 → 호출자가 어느 루트에서 답을 받았는지 항상 확인 가능

### 3.6 왜 5회 거절과 다른가 — 반드시 이해할 것

다중 root 는 **5회 거절**됐다(2026-05-26 / 07-06 / 07-27 / 07-31 / 08-07). 그러나 **범위가 다르다**:

- 과거 안 = SRS 포함 **전면** 다중 root → 요구 ID 충돌·인덱스 분기가 거절 사유
- 이번 안 = SRS 를 호스트에 **고정**한 채 run/plan 상태만 개방 → 거절 사유가 **구조적으로 발생 불가**

재개봉 선행조건 셋 중 (a)는 오히려 정렬, (b)는 A군 제외로 원천 차단, **(c)만 미해결**.

`REL-MCP-004` 는 `user-directive` 태그다. 2026-07-06 사용자 지시로 도입, 2026-08-16 사용자 지시로 부분 철회 — **두 지시 모두 change note 에 남겨** 이력이 끊기지 않게 할 것.

## 5. 표준 지침 (이 저장소에서 반드시 지킬 것)

### 5.1 금지

- **`speckiwi init` 절대 금지** — 특히 `--force` 는 `00.index.md`·`90.appendix.md`·`steps/state.md`·`.claude/settings.json`·`.codex/hooks.json`·번들 훅 러너 둘을 덮어써 요구 인덱스가 사라진다
- `speckiwi skills install` · `speckiwi upgrade` 금지. `speckiwi skills mirror --write` 는 **허용**(`.agents/skills/**` 의 유일한 정당 기록자)
- `git checkout` · `restore` · `stash` · `clean` 금지
- 커밋 메시지에 **어떤 시그니처도 금지**(`Co-Authored-By`·`Generated with`·`🤖` 등). 커밋 후 `git log -1 --format="%B"` 로 0건 검증
- 커밋 **제목**에 `Phase {n}` · `Step {n}` · `TASK-XXX` 금지
- `npm install` bare 금지 — 셸이 `NODE_ENV=production` 을 물고 있어 devDependencies 를 prune 한다. 빌드는 `NODE_ENV=development`, 테스트는 `NODE_ENV=test`

### 5.2 필수

- **TDD test-first.** 구현 선행 시 그 구현을 **버리고** 처음부터 다시
- **모든 판단 검증은 서브에이전트에게** 편향 없는 입력만 주어 위임. 자기검증 금지(객관 PASS/FAIL 카운트만 예외)
- `docs/spec/` 가 요구의 유일한 SSOT. 증거 없이 `verified` 금지, bulk-archive/finalize 도구 금지
- 소스 census 는 **`grep -a` 필수** — `src/` 밑 네 파일에 NUL 바이트가 있어 일반 grep 이 조용히 건너뛴다
- 사용자 결정은 **5인 결정위원회 자동결정**. `AskUserQuestion` 사용 금지

### 5.3 이번 세션의 교훈 — 다음 세션이 반복하지 말 것

**내 수정문이 새 결함을 들여온 것이 8건**이었다:

1. 존재하지 않는 명령을 문서화(`orchestrate journal tail`)
2. 깨진 앵커 2개 도입
3. 개수 주장 오류 — `workflow` 하위명령을 30이라 썼는데 실제 29, 감사자는 28. **세 값이 갈렸다**
4. 훅 분기 누락 — 두 갈래 중 하나만 서술
5. **배포 스킬이 명시적으로 부인하는 거짓 주장** — "lane 이 동시 실행된다"고 썼으나 스킬 본문에 *"phase 1 이 그것을 가졌다고 주장하지 않는다"*
6. 닫힌 개수 "넷" 이 실제 7개 대상을 배제
7. 문법적 부착 오류 — 사실은 맞게 조사했는데 **문장 구조가 그 사실을 뒤집음**
8. 한국어 문체 혼용 + 영문에만 있는 부정문

**대응**: 개별 지적을 좇지 말고 **호출부 전수 census** 로 전환하라. 개수 주장은 되도록 쓰지 말고, 쓰면 실행으로 확인하라. 검증자에게 **"가장 새 텍스트를 가장 의심하라"** 고 명시해 넘겨라.

또한 검증 중 `npx` 가 `speckiwi` 를 **자기 자신의 의존성으로** `package.json`·lock 에 주입한 오염이 있었다. 세션 종료 전 `git diff package.json` 으로 확인할 것.
