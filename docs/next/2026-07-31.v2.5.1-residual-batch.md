## 2. What the audits found behind a green suite

Four independent per-AC audits ran in isolated worktrees, one probe per acceptance criterion. Every
group found something, and in three groups the finding was in work that already had passing tests.

- **CRITICAL** — the corrected §14.2 sentence was itself false. It claimed `update_status` writes
  whatever status it is given; the runtime refuses `planned -> verified` with `MUTATION_DENIED`. A
  too-strict false statement had been replaced with a too-permissive one. §14.2 now lists what each
  transition actually does at the write, and `status-transition-gates.fr-node-096.test.ts` pins it by
  executing the calls — a document-string assertion cannot catch this class, which is the lesson.
- **HIGH** — `init` hardcoded the scope document number `1` and was the one caller that never went
  through the allocator. A project holding its own `01.glossary.md` got a colliding
  `01.<slug>.srs.md`, which the validator then reported as `SRS-W072`. The new test greps every
  `scopeDocumentName` call site for a literal number and caught a second hardcoded site the audit had
  not reached. `FR-NODE-088` AC-1 was amended through demote → amend → evidence → re-verify.
- **HIGH ×2** — `FR-MCP-056` AC-3 passed with the entire `register_scopes` core call replaced by
  `ok: true`, and AC-4 passed with `scaffold_scope`'s only dry-run line deleted, because the test
  called `dryRun` without `apply`. Both now assert observable outcomes.
- **HIGH** — `IR-CLI-080` ignored `CODEX_HOME`, so for a user who sets it the check reported on a
  directory nobody installs into and returned `ok` over a genuinely stale install. That is the exact
  blind spot the requirement exists to remove, reproduced inside it.
- **MEDIUM** — `IR-CLI-079` AC-3 asserted against `toolSchemas`, a static literal, while its comment
  claimed it read the instantiated server; a tool named `repair_rules_references` on the live server
  passed all four cases.
- **MEDIUM** — `FR-PARSE-035` AC-1's line was unverified: hardcoding line 2 passed.
- **MEDIUM** — `FR-NODE-092`'s "every requirement" plurality was untested; `findings.slice(0, 1)` left
  every case green, and the real repository case was five requirements.

All fixed and re-probed red.

## 3. Still open, deliberately

### 3.1 A bare path in `Related Docs` is never link-checked — MEDIUM

`markdownLinks()` in `src/core/query/links.ts` matches only `[text](target)`. A cell holding
`docs/research/nope.md` with no Markdown link produces zero broken entries. Two requirements in this
repository use exactly that form today (`REL-ARCH-003` and `FR-PARSE-035`, both pointing at
`docs/next/2026-07-30.numbering-and-2.5.0-residuals.md`, which exists), so nothing dangles now — but
`FR-PARSE-036`'s own motivating defect class stays open for the bare-path spelling, and AC-4's
self-conformance claim is partly vacuous for those two rows.

Not fixed here because widening the matcher changes `links check` semantics for every consumer and
needs its own requirement: a cell can hold `-`, free text, or a comma-separated mixture, so "treat a
bare path as a link" needs a definition of what counts as a path before it is safe.

### 3.2 `specDocuments` is required on `SrsFileSet` but optional on `ParsedWorkspace` — LOW

`src/core/types.ts` marks it optional so hand-built test workspaces need not supply it, and the rule
reads `workspace.specDocuments ?? []`. A workspace constructed without the field silently disables
`SRS-W072` — the same shape as the dead-code failure `FR-PARSE-037` AC-6 exists to guard against, moved
to the type boundary. Making the field required end-to-end would close it; the cost is every hand-built
workspace literal in the suite.

### 3.3 `register_scopes` and `scaffold-scope` write different Scope Map rows — LOW

For the same document, `scaffold-scope` writes `| Billing | [11.billing.srs.md](./11.billing.srs.md) |
BILL | Billing |` and `register_scopes` writes `| BILL | ./11.billing.srs.md | BILL | - |`. The second
infers only from requirement ids and never reads the document's `Scope Name`. Pre-existing
(`FR-NODE-064`), asserted as-is rather than as it arguably should be.

## 4. Decisions not to re-open

- **The retraction reasons live on `FR-NODE-095`, not in the shipped rules document.** Naming a
  retracted code there collides with the existing contract that the document cites no code the registry
  lacks (`FR-NODE-086` AC-2, `FR-NODE-087` AC-9), and that contract is what keeps the retraction honest.
  It was left intact rather than exempted.
- **`SRS-E009` was retracted, not implemented.** `SRS-E010` already fires for a verified requirement
  with any unchecked criterion, so the "hole" the earlier analysis assumed did not exist.
- **`SRS-W006` and `SRS-W007` were retracted on measurement, not taste.** The ten discouraged
  expressions match eighteen occurrences in this repository and every one is ordinary English; the tag
  ceiling is a recommendation whose enforcement would fail this repository's own `--fail-on-warning`
  gate with no sanctioned repair for a verified requirement's tags.
- **`SRS-W044` and `SRS-W045` were registered rather than renamed.** They are emitted, they are in the
  `SRS-` namespace, and `explain` reported them unknown. The `SDS-` and `STEP_` advisories stay
  unregistered because the `SRS-` contract does not reach them.
- **`UPGRADE_REFRESH_FAILED` is unreachable, not untested.** `initProject` returns only a success
  result and upgrade skips the lock, so the branch is a type obligation. A seam to drive it would put
  test-only indirection in the command; the two facts that make that safe are pinned instead.
- **Allocation skips an occupied number but a sidecar never raises the starting candidate.** Counting
  `90.appendix.md` as the highest would push a project's second scope document to `92`, which is what
  the numbering decision exists to prevent.

## 5. Traps for the next session

- **A background subagent's final turn text does not reach the main session.** Instruct it to deliver
  the report with `SendMessage` to `main`, and to send an interim report rather than risk losing
  everything. Two audits died on API 529 and had to be relaunched; a failed audit is **not performed**,
  never assume its result.
- **A subagent worktree is created at the session's starting HEAD**, not at your latest commit, and it
  does not see uncommitted work. Every auditor had to mirror the checkout. Commit first, and tell the
  agent which commit holds the work.
- **`vitest` used to collect the test copies inside `.claude/worktrees`**, so another agent's in-flight
  probe was reported as a failure in this checkout. `vitest.config.ts` now excludes them.
- **Give concurrent auditors disjoint file ownership**, and tell each which files another agent owns.
  Two auditors correctly reported ACs they could not probe because the file belonged to someone else —
  that is the right outcome, better than a silent gap.
- **Do not write TypeScript regex literals through a bash heredoc.** `\r?\n` was mangled into a real
  newline twice, producing a parse error. Use the Edit tool or a `.mjs` script file.
- **Always `npx vitest run --no-file-parallelism`.**
- **`add_requirement` acceptance criteria must not carry an `AC-N:` prefix** — the tool adds it.
- **`edit_requirement_table_rows` needs lowercase column keys.**
- **Adding an MCP tool touches four places** plus the hand-written `EXPECTED_KINDS` map.
- **CLI names differ from the MCP tool names**: `add-evidence`, `check-ac`, `update-status`.
