## 2. 착수 전에 반드시 알아야 할 것

### 2.1 Phase 0 게이트 대체안은 검증받지 않았다

`00.index.md` §4.1 의 3조건은 **팀리드가 자기 게이트를 무너뜨리고 스스로 낸 대체안이며 아무에게도 검증받지 않았다.** Phase 0 착수 전에 독립 검토를 받는다.

무엇이 문제였는지는 그 절에 적혀 있다 — 초판 게이트("검사가 C1~C4 를 발화시킨다")는 **검사가 잡을 답을 계획서가 미리 알려 주므로** 그 넷만 하드코딩해도 통과한다.

### 2.2 P0-3 는 반드시 파생 방식이어야 한다

대상 상수 목록을 하드코딩하면 **P2-3 이 세 번째 번들 상수를 추가할 때 조용히 무효화된다.** 무효화된 사실을 아무도 모른다. 이것이 게이트 3번 조건이자 `P0-3 → P2-3` 의존이다.

### 2.3 검토 5축을 전부 팀리드가 인수했다

서브에이전트 5기가 **두 번씩 실패**해 자력 완주가 0기였다. 연구 라운드까지 합치면 **10기 중 0기**다. 인수분이 전부 기계 측정이었고 결과가 계획에 불리하게 나왔다는 게 완화 요인이지만, **자기 계획을 자기가 검토한 것**이며 지침 §5 가 금지하는 형태다.

두 번째 라운드는 첫 번째의 교훈을 전부 적용했는데도 같았다 — 축 분리, 방법 지정, 반환 형식, 분량 상한, 부풀리기 금지. **반환 규약은 이 문제의 해법이 아니다.** 원인을 따로 조사해야 하며, 그 사실을 `05.phase-4-skills.md` P4-2 에 적었다.

관측된 것 하나: **재요청할 때 항목을 좁히고 방법을 지정하면 응답률이 올랐다.**

## 3. 이 저장소에서 절대 하지 말 것

- **`speckiwi init`(특히 `--force`) · `skills install` · `upgrade` · `remove` 를 이 저장소 대상으로 실행하지 않는다.** `--force` 는 `docs/spec/00.index.md` 를 템플릿으로 덮어써 요구 인덱스를 무증상으로 파괴한다. `skills mirror --write` 는 허용되며 `.agents/skills/**` 의 유일한 정당 writer 다.
- **`git checkout` · `restore` · `stash` · `clean` · `reset --hard` 금지.**
- **`.claude/` · `.codex/` · `.mcp.json` · `docs/spec/steps/` 를 커밋하지 않는다.**
- 검증 서브에이전트가 `C:\Users\beom\.claude` 나 `.codex` 에 쓰지 않게 한다.
- **커밋 메시지에 어떤 시그니처도 넣지 않는다.** 커밋 직후 `git log -1 --format="%B"` 로 0건을 확인한다. 제목에 `Phase {n}` 같은 진행 표식도 넣지 않는다.
- **커밋에 `docs/research/**` 와 `docs/next/**` 를 섞지 않는다.** P0-1 이 이것을 게이트로 만들기 전까지는 손으로 지킨다.

## 4. 도구 함정 (전부 이번 세션에 실제로 밟았다)

- **`rg` 재귀 검색이 조용히 빈 결과를 낸다.** 다섯 파일이 의도적 NUL 바이트를 담고 있다. `readFileSync` 로 읽는다. P0-5 (4) 가 이 원인을 없애려 한다.
- **인라인 `node -e` 에 정규식 이스케이프를 넣지 않는다.** 셸을 거치며 `\b` 가 워드 경계에서 백스페이스 문자로 바뀌어 **아무것도 매치하지 않은 채 결과를 낸다.** "CLI 60개 중 59개 미사용"이라는 거짓 보고가 두 번 나왔다. 스크립트를 파일로 쓴다.
- **heredoc 에 백틱이 들어가면 셸이 깨진다.** Write 도구로 파일을 만든다.
- **명령에 NUL 문자를 넣으면 도구가 거부한다.** 스크립트 안에서 `charCodeAt` 으로 검사한다.
- `npm install` 을 맨으로 돌리지 않는다. 셸에 `NODE_ENV=production` 이 걸려 devDependencies 가 정리된다. 빌드·pack 은 `NODE_ENV=development`, 테스트는 `NODE_ENV=test`.
- 전체 스위트는 `npm test` 로 돌리고 출력을 `tail` 로 자르지 않는다. 실패 목록이 사라진다.
- CLI 는 `node bin/speckiwi` 로 부른다. `node dist/cli/index.js` 는 **출력 없이 exit 0**.
- `bin/speckiwi` 를 spawn 하는 테스트는 `dist/` 를 실행한다. `src/` 만 고치고 재빌드하지 않으면 변경이 보이지 않는다.
- `git log --format=COMMIT` 은 유효하지 않다. `--format=%x00%H` 같은 형태를 쓴다.

## 5. 값을 치른 교훈

**기준을 쓰고 그 기준으로 목록을 거르지 않았다.** 계획 P3-3 에 판정 기준 셋을 적어 놓고 — 3번이 "다른 살아 있는 명령의 유일한 되돌리기 경로" — 목록에 적용하지 않았다. `restore` · `set-supersede` · `supersede` · `uncheck-ac` 가 전부 폐기 목록에 있었고 `check-ac` 는 남아 있었다.

**"도달 0" 실사는 되돌리기 명령을 우선적으로 잡아낸다.** 되돌리기는 원래 드물게 쓰이니 스킬이 언급하지 않고, 그래서 도달 0으로 잡히고, 그래서 폐기 목록에 오른다. **실사 결과를 폐기 목록으로 그대로 옮기면 안 된다.**

**자기 실측이 옳아도 그것이 무엇의 척도인지는 틀릴 수 있다.** 표류 42쌍 측정은 정확했으나, 그것이 재는 것은 *모순의 발생*이 아니라 *찾는 비용*이었다. 이력 24건이 순수 표류를 3건으로 정정했다.

**측정 방법의 편향은 결론에 유리한 방향일 때 가장 위험하다.** 산문·사이드카 포함률을 JSON 전체 부분 문자열로 쟀더니 평균 7%p 과대 계수였고, 그 방향이 "산문은 중복이다"라는 결론을 강화하는 쪽이었다. 엄격 기준으로 다시 재서 순위가 유지되는 것을 확인하고서야 결론을 남겼다.

**재현되지 않는 수치는 근거가 아니다.** `kiwi-orchestrator` 변종 비교에서 `comm` 은 731/42/44 를, `Set` 차집합은 733/40/42 를 냈다. 계획에서 절대 수치를 빼고 "약 89%"만 남겼다.
