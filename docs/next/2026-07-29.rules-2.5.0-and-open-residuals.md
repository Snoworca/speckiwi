## 3. Open residuals

Each item states what was measured and why it matters. None of these are speculative.

### 3.1 The installed rules forbid syntax the tool itself writes — CRITICAL

Closed by §1. Recorded here because it is the reason §1 exists.

`update-status <id> discarded` rewrites the heading to `### ~~FR-…~~ [DISCARDED]` and `update-stability <id> draft` appends `[DRAFT — pending decision]`. The bundled v1.0.0 document forbids heading emphasis (`§6.3`, `§10.3`) and never mentions the markers. A consumer following the installed rules would revert the markers by hand and break the marker-to-status coupling the mutations maintain.

### 3.2 Running init in this repository deletes its own dogfood rules — measured

While implementing `FR-NODE-086`, an agent ran `node bin/speckiwi init --no-skills --no-mcp` in this repository and observed:

- `docs/rule/SRS-MD-Rules-v1.1.0.md` and `SRS-MD-Rules-v3.0.0.md` **deleted** by `pruneStaleRulesDocuments`
- `docs/spec/00.index.md` Rules pointer downgraded v3.0.0 → v1.0.0

Both were reverted. §1 dissolves this: once 2.5.0 is canonical those two files are genuinely obsolete and the index pointer moves to 2.5.0 legitimately.

### 3.3 CLAUDE.md carries one sentence the renderer does not — MEDIUM

`agents.md` is byte-identical to `renderAgentInstructionSnippet()` output. `CLAUDE.md` differs on one line inside the managed block: the renderer writes "Completed Work Log is a read-only summary…" while the file writes "The Completed Work Log — inline in `docs/spec/00.index.md` §7 and its split history file `docs/spec/91.completed-work-log.md` — is …".

This is pre-existing drift: it was present at HEAD before this session and `git diff HEAD -- templates.ts` shows no corresponding change. `test/release/cwl-history-split-rules.test.ts` (FR-FLOW-022) pins that sentence, so it cannot simply be reverted.

Init will never repair it, because `upsertAgentInstruction` skips when the block version matches. Two ways to close it: put the sentence into the shipped snippet (which raises `AGENT_INSTRUCTION_VERSION` again), or move the FR-FLOW-022 anchor outside the managed block. The first is more truthful — the sentence is accurate and `add_completed_work` really does write to `docs/spec/91.completed-work-log.md`.

### 3.4 Init's version-match skip makes any in-block drift permanent — MEDIUM

The general form of §3.3. `upsertAgentInstruction` skips whenever `block.version === AGENT_INSTRUCTION_VERSION` and the end marker is present, and it does not accept a force argument. Any hand edit inside the block therefore survives every future init. Consider comparing content rather than version, or giving the function a force path.

### 3.5 FR-NODE-051 is `implemented` with zero checked ACs and zero evidence — MEDIUM

`docs/spec/50.nodejs-implementation.srs.md:3871`, target `v2.3.0.1`, `Stability=evolving`.

Its acceptance criteria were pinned to a version snapshot (`# SpecKiwi SRS 워크플로 v1.4`) and had already been unsatisfiable before this session, since the shipped version was `1.6`. This session revised them to reference the shipped constants instead of literals, so they are now checkable — but they were deliberately **left unchecked**, because checking an AC without verifying it is the exact thing the workflow forbids.

The behaviour they describe is covered by `test/core/bootstrap/init-project.test.ts`. An evidence pass should verify each AC against that suite and register evidence.

### 3.6 Rules documents outside the bundle still contain Korean — informational

### 3.7 The rules document's heading grammar is looser than the runtime's — LOW

The document's recommended regex allows a `[A-Z]{2,5}` prefix while `REQUIREMENT_HEADING_RE` fixes an eleven-member enumeration, and the document's regex has no marker slot. A consumer trusting the looser form would write a heading the parser does not recognise. Pre-existing; the translation did not touch that line.

## 4. Decisions already made — do not re-open

- **Unattended cost and integration gates are not auto-granted.** `--auto` alone does not pass `kiwi-coder`'s `cost-warning-large-task` or `integration-test-user-consent`; each needs its own explicit option, reachable through the pass-through chain and stated in the orchestrator's §7.1. Auto-granting would approve, once per wave, integration runs and ten-minute costs the user never consented to, which voids the gates. `FR-FLOW-059 AC-1` was revised to match.
- **`FR-NODE-076 AC-2`'s never-overwrite clause is superseded** by `FR-NODE-085`, recorded as a `supersedes` trace link rather than by editing that requirement — it is `verified`, and the tool correctly refuses granular edits to verified requirements.
- **The Korean sentinel recognition is wired to the strict path only** — heading and end marker must pair. Attaching it to the loose fallback would swallow prose mentions and marker-less headings, destroying consumer content.
- **`v3.0.0` is not a destination.** See §1.1.
