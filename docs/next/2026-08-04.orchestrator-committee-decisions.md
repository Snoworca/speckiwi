## 0. Three settled positions the committees killed

**These are the entries to read if you read nothing else.** Each was recorded as decided, and each is
now measured to be wrong.

### 0.1 The §1.5 round line's converged shape breaks two requirements

`2026-08-03…md` §1.5 records the converged line as *"`status: "in_progress"` on every per-round line
whatever the verdict"*. Two members reproduced, independently, that this is unsafe:

- **A loop-F round record would discharge the run's final verification.** `FR-NODE-161`'s own evidence
  says the loop-F round record is excluded *"because a round record asserts no status"*. Give round
  records a status and that footing is gone. Measured on `FR-NODE-161`'s own fixture: statusless gives
  `needsFinalVerify=true, runComplete=false`; with `status: "in_progress"` it gives
  `needsFinalVerify=false, runComplete=true`. **`FR-NODE-161` AC-1 turns red.**
- **A round line after a wave's `complete` reopens the wave.** Measured:
  `waveStatuses=[[1,"complete"]]` becomes `[[1,"in_progress"]]`, `firstIncomplete` becomes 1. That is
  verbatim the failure `waves-journal.ts:75-81` already records as measured, and the `assertsStatus`
  discriminator does not prevent it.

`FR-NODE-159` and `FR-NODE-161` both rest on round records being statusless. **A status may be given
to loop-P round lines only, and loop F needs a stronger discriminator first.**

### 0.2 Projecting the whole `Round` into `verification` validates vacuously

`2026-08-03…md` §1.5 says to project *"the **whole** `Round`"*. `Round` is camelCase
(`frozenDenominator`, `baselineFailingTests`, `residual[].reasonClass`); the validator reads
snake_case. The same dishonest round, measured both ways:

```
snake_case: ["unapproved-damage","new-regression","denominator-mismatch","truncated-residual","reason-class-outside-vocabulary"]
camelCase : []
```

A whole-`Round` dump is a `verification` object that satisfies every rule by being unreadable. The
projection must be an explicit snake_case mapping, and it must carry `residual` **and**
`axis_b.open` — `waves-validate.ts:238` is `if (terminal && open && residual !== null)`, so dropping
either key silently disables the completeness rule.

### 0.3 `wave` derived from `scope` must strip `-post`, or no wave can complete

Loop P's scope is `wave-{n}-post`; `waveNumber` is `/^wave-(\d+)$/`.

```
waveNumber('wave-1')      = 1
waveNumber('wave-1-post') = null
round line wave="wave-1"        COMPLETES
round line wave="wave-1-post"   REFUSED ["complete-without-latest-pass"]
```

## 1. Committee A — the round line (§1.5)

### 1.1 `fail-residual` — the map is not a function of the round verdict

Split as reported: B (`in-progress`) 2, B-plus-a-terminality-input 1, "neither" 1, A 1. **The
convergent finding is stronger than either option as posed**, and three members reached it
independently: the journal verdict depends on a bit the round verdict does not carry — *is this the
loop's last round*.

Measured exhaustively over **55,296 input points**:

```
VERDICT COUNTS: { pass: 1488, invalid: 27648, pass-with-residual: 1488, fail-cap: 11368, fail-residual: 13304 }
fail-residual rows that are terminal (cap exhausted / unreachable):  0 of 13304
min capRemaining on a fail-residual verdict:                         1
fail-residual rows carrying an EMPTY residual list:               6652 of 13304
```

So kernel `fail-residual` ⟹ non-terminating, with zero counterexamples — and in half its cases the
round has **no unresolved findings at all**; it means only "did not pass yet". Against that,
`waves-event.md:105` defines the journal's `fail-residual` as *"상한 전에 미해소 finding 을 남기고
**끝낸** 경우"* — terminated. `kiwi-wave-master/SKILL.md:274` names the harm outright:
*"`fail-residual` 을 쓰면 재개가 도는 루프를 실패로 읽는다"*.

**Decision: map to `in-progress` by default; the terminal `fail-residual` is written only when the
caller supplies an explicit terminality signal**, exactly as `mode` is already caller-supplied and for
the reason `verification-gate.ts:27-30` already states. Its real producer is the oscillation stop
(`verify-loop.md:104`), which is **unimplemented** — do not later reach back for the round-record
mapping to supply it.

**The cost of option B, stated honestly** (the dissenting member's strongest point):
`waves-validate.ts:237` is `terminal = verdict !== "in-progress"`, and `terminal` gates
`truncated-residual`. Under `in-progress` that residual-completeness check is switched off. Measured:

```
verdict=fail-residual  ["truncated-residual"]
verdict=in-progress    []
```

That is the contract's intent — `residual` is defined as the full enumeration *at termination* — but
it compounds with §1.5's own `denominator-mismatch` exemption, so **two** completeness rules end up
scoped away from `in-progress`. Whoever implements this must say so in the requirement.

### 1.2 Loop P's phase — `wave-verify`, 5 of 5, and it was never an open question

The premise in `2026-08-03…md` §1.5 (*"`wave-{n}-post` maps to no declared `phase` member"*) conflates
two orthogonal vocabularies: `wave-{n}-post` is a **scope** token
(`05.orchestrator-design.md:1144`), not a phase candidate. All six loops map onto declared
`WAVE_PHASES` members with nothing left over:

| loop | phase | verb | source |
|---|---|---|---|
| D | `design` | `verify-design` | `SKILL.md:1030` |
| W | `wave-design` | `verify-wave-design` | `:1063` |
| H | `handoff` | `verify-handoff` | `:1107` |
| L | `lane` | `verify-lane` | phase 2 |
| **P** | **`wave-verify`** | `post-merge-verify` | `:1125` |
| F | `final-verify` | `final-verify` | `:1153` |

Measured, `integrate` is not a weaker alternative but an **unsafe** one:

```
W pass under wave-verify, P FAIL under phase=integrate -> complete => completeAccepted=true
```

A failing loop-P round does not block the wave's `complete`, because the gate reads loop W's earlier
pass. Under every candidate except `wave-verify`, `complete-without-latest-pass` fires on every wave
forever.

### 1.3 Also measured on the same verb

- The closed `{scope}` vocabulary (`05:1144-1145`, six values, *"`freeze`/`round record` reject an
  out-of-vocabulary scope"*) exists **nowhere in `src/`**. `Round.scope` is a bare `string`; `loop` is
  a closed union in the same interface, so the file demonstrably knows how to close a vocabulary and
  did not close this one. Executable: `"design"`, `"wave-2"`, `"TOTALLY-BOGUS-SCOPE"`, `""`, `"$$$$"`
  all return `{"verdict":"pass"}`.
- `verification-without-status` is emitted for **two different defects** — a missing status
  (`waves-validate.ts:147`) and an out-of-vocabulary verdict (`:270`). A reader cannot tell which
  fired. The second needs its own code.
- A loop-F round record cannot be written through `appendWavesLine` at all today —
  `verification-without-status` refuses it. `FR-NODE-161`'s fixture is written straight to disk and so
  never exercised that path. Latent, and it surfaces the moment loop F is wired.

## 2. Committee B — the prose gate (§1.3)

**Decision: do not wire it now.** Four members said `freeze design`, one said do-not-wire; the
do-not-wire case rests on measurements the other four did not take, and two members converged on them.

### 2.1 The gate has two evaluation points, of different kinds

`Phase 1.e / 3.a` (`SKILL.md:67`, `05:5170`). **1.e is the freeze** — `05:736`'s phase map names the
step `freeze-design`, and `SKILL.md:1034-1037`'s `§V.freeze-design` carries the gate. **3.a is a
round** — `§V.verify-wave-design` (`:1065`), loop W. The module docblock naming `orchestrate freeze
design` is therefore *incomplete*, not contradictory.

The heterogeneity follows from what the gate protects. At 1.e the freeze **produces** `design_items[]`
(`freeze.ts:137`), so the check belongs at the producer. At 3.a the wave's denominator is a *slice* of
the already-frozen array, so there is no freeze to hang it on.

**`orchestrate freeze design` therefore covers at most half the declared gate.** Wiring it alone
converts a visible gap into an invisible one.

### 2.2 The predicate is not fit to refuse

Two members measured `scanProse` over the repository's real design prose. **9 of 13 files fire; all 7
`unmarked-normative-prose` findings are false positives**, in three structural classes:

| class | instance |
|---|---|
| markdown tables | `05:8295-8329` — one `MUST` in a cell flags a 35-line table as one finding |
| inline quotation | `04:548` quoting `CLAUDE.md`; rule 6 excludes `>` blockquotes, not `*"…"*` |
| use vs mention | `05:4891` *"The skill states this as a MUST"* |

Plus a real latent defect: the hedge scan uses `includes()` where the normative scan uses `\b`, so
`"thoroughly"` matches the hedge token `roughly` and `"maybelline"` matches `maybe`. And `hedge` is a
`PROSE_RULES` member with **no gate id** — any wiring must filter to `unmarked-normative-prose` or it
refuses with an id that does not exist.

Honest caveat carried from both members: the gate is scoped to `design/00.design.md` and
`waves/wave-{n}/design.md`, and `find -name "design.md"` returns **zero** files repo-wide. These are
proxies, not the population.

### 2.3 The precondition, and the non-vacuous test

```ts
// Corpus fitness — the gate may not refuse until it is clean on documents already accepted.
it("raises no unmarked-normative-prose finding on any design document in the repo", () => {
  for (const file of designCorpus()) {
    const findings = scanProse(readFileSync(file, "utf8")).findings
      .filter((f) => f.rule === "unmarked-normative-prose");
    expect(findings, `${file}: ${findings.map((f) => f.lines[0]).join(",")}`).toEqual([]);
  }
});
```

**RED today**, 7 findings across 4 files. This is the gate's admission ticket.

### 2.4 What to do instead, in order

1. **Fix the three stale comments** — `prose-gate.ts:1`, `:119`, and the test comment at
   `kiwi-orchestrator-body.fr-flow-074.test.ts:146`. All three assert wiring that does not exist, and
   they are the sole origin of this proposal. Free.
2. Fix the hedge word boundary. A real defect regardless of wiring.
3. Land the corpus-fitness test and fix the three false-positive classes.
4. Only then wire 1.e, under a new `FR-NODE` requirement, evidenced at the CLI layer. Zero verb rows,
   zero demotions; the text is already in hand (`pinning.ts:583-589` returns `text`, held at
   `orchestrate.ts:931`), so it is zero new I/O.
5. `round record` is the only candidate site for 3.a, and it is **not viable today**: `scope` is an
   open string with no declared path convention, the kernel is declared file-free, and the verb
   refuses 100% of invocations. Revisit after §1.5 lands.

A new read-only verb was rejected by every member: it demotes `IR-CLI-082` (*"exactly the twenty-one
phase-1 verb rows"*, `verified`), `IR-MCP-003` via its exact-set assertion, and takes expansion
pressure on `FR-NODE-137` AC-1's closed enumeration of gate verbs.

## 3. Committee C — the gate table's evaluator distinction (§1.1)

**Decision: neither a fourth column nor a hand-written constant. The label must be derived from
runtime emission, and the cheap real fix is the one three members converged on independently.**

### 3.1 The authoritative census

| bucket | count |
|---|---|
| `GATE_IDS` (in `src/core/orchestrator/auto-gate.ts:25`, **not** `journal-schema.ts`) | 61 |
| emitted — reaches a `refuse()`, including the 8 indirect paths | **18** |
| referenced in `src/` but never emitted | 8 |
| absent from `src/` entirely | 35 |

A literal-only `refuse("id")` scan reports 10 and under-reports by 44%: eight gates reach `refuse()`
through a variable (`state.blocking`, `error.gate`, `error.code`, a `GATE_IDS`-filtered
`violations[0].code`). **Zero false positives in the absent bucket** — each of the 35 was tested
against four spellings plus its distinctive tail.

The shipped table declares **54** rows (plus a second 4-row severity table = 58 ⊂ 61), byte-identical
across all four renderings. The three in no table are named in prose at `SKILL.md:109` as deliberately
not transcribed.

### 3.2 Why both proposals fail

- **A census-derived label is a tautology** (it asserts the census equals itself) **and factually
  inverted for at least 8 ids**: `partition-review-unrecorded`, `serial-unit-failed`,
  `unmarked-normative-prose`, `unallocated-req-id`, `cross-lane-duplication-unresolved` and others have
  a kernel in `src/` with **zero callers**. A scan certifies them `tool`. Making a wrong label
  machine-checked freezes it at green — worse than a visibly unenforced table.
- **A hand-written label is defeated by relabelling.** Nothing constrains which gates may be called
  `agent`, so flipping a broken `tool` gate to `agent` goes green in a one-word diff.
- **`agent` currently means nothing.** For **0 of 61** gates does any machine confirm an agent
  evaluated anything. `critical_halts` has zero occurrences in `src/`; the journal has no `gate` field
  (deliberately — a test asserts `WAVES_EVENT_FIELDS.optional` does **not** contain `gate`); the one
  persisted case, `route-proposal`, transcribes a JSON file the agent itself writes.
- **A fourth column deletes four shipped assertions**, including
  `kiwi-orchestrator-body.fr-flow-074.test.ts:97` (`row.width !== 3` must be `[]`) and
  `tool-signature-parity.test.ts:315`. Its only path forward is weakening a check, which is itself the
  signal. It also demotes `FR-NODE-122` (`verified`) and deviates from `auto-option.md`'s three-column
  shape, which `kiwi-tdd` and `kiwi-wave-master` also carry.

### 3.3 The one non-tautological assertion

> The set of gate values observed at exit 2 across a fixture-driven execution of the `orchestrate`
> CLI equals exactly the subset of `GATE_IDS` labelled `tool`.

The left side is **process output, not source text**, so a literal in an uncalled kernel never appears
there. Deleting a refusal goes red; relabelling a broken gate to `agent` makes the sides diverge and
goes red. It honestly asserts nothing about `agent` gates, which is correct until something records an
agent evaluation.

### 3.4 The fix to land first — converged 3 ways, cheap, immediately red

Two gate ids reach `refuse()` at exit 2 while being **outside `GATE_IDS` and absent from every
variant's table**:

- `handoff-pin-untrusted` — `pinning.ts:68`, emitted `orchestrate.ts:933`
- `lane-plan-incomplete` — `lane-plan.ts:82`, emitted `orchestrate.ts:1029`

Both compile because `refuse()` is typed `gate: GateId | string` (`orchestrate.ts:296`). Every
existing assertion runs `declared ⊆ GATE_IDS`, so the **emitted** vocabulary is unchecked in that
direction. **Drop `| string`.** The compiler then forces both to be resolved. Cost: admit both to
`GATE_IDS` (61 → 63) and update the one length literal at `tool-signature-parity.test.ts:307`; no AC
pins 61, and `FR-NODE-122` AC-3 is deliberately set *inclusion*, so two more undeclared members are
within it.

Also worth raising separately: `design-not-frozen` is raised only inside the freeze action on a
malformed body, so the freeze-before-implement ordering §13 describes is **unenforced**, and the same
gate id carries two unrelated rules.

## 4. Committee E — the abort field (§1.6)

Three members (the session hit its subagent cap at 200 before the other two could be spawned).
**Unanimous on all three questions.**

- **Name: `abort_gate`.** `gate` is unusable — `waves-event-parity.fr-node-129.test.ts:325-326`
  asserts `WAVES_EVENT_FIELDS.optional` does **not** contain it, and renaming to `gate` would turn a
  green assertion red and drag `FR-NODE-129` AC-5 with it. `abort_reason` re-imports the accident:
  "reason" is already spent three times in this schema.
- **Value space: `GateId`.** The brief's "mixed space" premise is **false** — all four aborts the
  skill names are `GATE_IDS` members. `budget-exhausted` is a `verification.residual[].reason_class`
  value describing how a *loop* closed, not an abort reason. The real gap is the opposite: the two
  budget aborts name **no id at all**, and until a gate exists for them those paths cannot honestly
  call `run abort`.
- **Enforcement: refuse, candidate-scoped.** `05:5139` — *"declaring a gate whose machinery does not
  exist is worse than omitting it"* — bites the current field twice: it is named after a closed
  vocabulary and enforces nothing. The rule must be **error on the line being appended, warning on
  history**, or a run holding one non-conforming line cannot even be aborted and its lock never
  releases.

**One regression is certain and already measured**: `orchestrate-deferred-halves.test.ts:110` passes
`--reason budget-exhausted`. The collision has already reached a test fixture. `FR-NODE-131` AC-5's
wording stays true, so this is a fixture swap plus an evidence re-measurement — no demotion.

**Cheapest honest path: two new requirements, zero amendments, zero demotions.** One `FR-NODE` to
declare `abort_gate` additively in `waves-event.md` v1.4.0 §2.2 across all four copies plus
`WAVES_EVENT_FIELDS.optional`; one `IR-CLI` for the refusal. Do **not**: bump the document to v1.5.0
(turns `FR-FLOW-104` AC-1 false — a `verified` row), name the field `gate`, declare a thirteenth
closed vocabulary, extend `FR-NODE-127` or `IR-CLI-082`, or add an unclaimed bullet to §2.3.
