## 5b. The wiring gap is systemic, and it is the finding of this session

Four independent AC-mapping audits converged on one shape: **the pure kernels are correct, tested, and
called by nothing in `src/`.** This is not two instances. Measured by repo-wide grep over `src/`,
excluding each module's own file and its tests:

| Function | Declared in | Production callers |
|---|---|---|
| `resumeRung`, `checkRouteDrift` | `route-lock.ts` | **0** |
| `selectPlanCandidate`, `derivePlanProbe`, `countOrderedSections`, `deriveScopes`, `deriveScopeRequirementIds` | `route-probe.ts` | **0** |
| `evaluateSerialUnitGate`, `evaluatePartitionReviewGate` | `unit-gate.ts` | **0** |
| `scanProse`, `countNormativeTokens` | `prose-gate.ts` | **0** |
| `classifyLaneDisposition`, `evaluatePriorStagesIntegrated`, `hasMergeWitness` | `lane-state.ts` | **0** |

`issue-ledger.ts` is the counter-example and shows what wired looks like: all five predicates are
called from `orchestrate.ts` at `:1052`, `:1065`, `:1087`, `:1105`, `:1138`.

**Three of those unwired predicates sit behind declared `critical_gates[]` ids** —
`serial-unit-failed`, `partition-review-unrecorded` and `unmarked-normative-prose` are all members of
`GATE_IDS`, and `orchestrate freeze design` calls `freezeLock`, not `scanProse`. So the gate table
names three gates that **cannot fire**, which is exactly the failure `M-03` states in the abstract:
*a gate whose predicate can never fire is indistinguishable, from the table, from a gate that never
fires because nothing is wrong.* The session recorded that sentence about the design and then shipped
three instances of it.

**A second, quieter one: `test/**` is never type-checked.** `tsconfig.json` sets `rootDir: "src"` and
`include: ["src/**/*.ts"]`; `vitest.config.ts` declares no `typecheck` block; the eslint config sets no
`parserOptions.project`. So `FR-NODE-108`'s stated proof mechanism — *"a field the declaration omits is
a compile error here"* — **is executed by no build, test or lint command in the repository.** AC-1,
AC-2 and the type half of AC-6 rest on a compiler that never runs. That is its own requirement, and it
is worth more than most of the rows above it.

**A third: `resume.ts:179-188` is a second, weaker copy of `lane-state.ts`'s classification**, and it
computes `merged` from `ancestorOfIntegration` — a lane branch — while its own comment records that
phase 1 creates no lane branch, so that value is structurally always `false`.

**Do not promote a criterion whose behaviour is one of these.** A pure predicate that no caller reaches
satisfies a unit test and not the requirement, and `planned` is the honest status for it. The rows
affected are named in the audits; the next session's first decision is whether phase 1 wires them or
whether the design intends the *agent* to be the caller — which for the probe producers is a real
question, not an oversight, since their inputs are MCP calls the CLI cannot make.

## 5a. Two wiring gaps found by the evidence audits, and they are not evidence problems

Both were found by auditing *which test asserts which criterion*, which is why they survived a green
suite: the pure kernels are correct and tested, and nothing calls them.

**`frozen.route` is written by nothing and read by nothing.** `resumeRung` and `checkRouteDrift`
(`route-lock.ts:169`, `:174`) have **zero callers in `src/`**. `FrozenBlock` declares no `route`
field — it rides the index signature. `computeResumeState` never reads `frozen.route.rung` and
`DriftInputs` carries no probe-digest field. So `FR-NODE-113` AC-5's *"a resumed session reads the
rung"* and AC-6's *"raises `run-invariant-drift`"* exist as **pure predicates and not as session
behaviour**, and `invariant_digest` covers the route only inside the tests' own fixtures. A fix is
under way; until it lands, those two criteria must stay unticked.

**The probe's producers are unwired.** `selectPlanCandidate`, `derivePlanProbe`,
`countOrderedSections`, `deriveScopes` and `deriveScopeRequirementIds` are exported from
`route-probe.ts` and referenced nowhere else in `src/`. `orchestrate route probe` **consumes** a probe
document; nothing produces one from these kernels, and the SKILL.md states the S2/S4/S7 rules in prose
for the agent to execute instead.

That second one is a **design question, not a bug**, and it should be answered before anyone "fixes"
it: `09` §3.2 gives each probe field a named producer that is an MCP call or a subagent artifact, which
the CLI cannot make — so the agent may be the intended assembler and these kernels may be the wrong
shape rather than merely unwired. Deciding it needs a requirement either way. What is not acceptable
is leaving five verified pure functions that no caller reaches and no requirement says who should.

**D7 records the wrong `observed` on one branch** (`route.ts:288`): it fires on
`!activeTarget || blockedStability.length > 0` and always records `blockedStability`, so an
empty-active-target firing records `[]`. `FR-NODE-110` AC-3 wants the value it fired on. Same class as
the D4 defect already fixed.

## 6. Design defects the implementation found — `NOTES.mechanical-findings.md` M-02..M-05

Recorded because they are the design's, not the code's:

- **Two stale counts** in §15.1's summary lines that §22.16's audit corrected everywhere else.
- **Three declared input sets one member short of their own consumers** — and two of them made a
  closed-enum member **unreachable**. One, `tdd-pair`, sits behind `tdd-pair-split`, a declared
  `critical_gates[]` row. **A gate whose predicate can never fire is indistinguishable, from the
  table, from a gate that never fires because nothing is wrong.**
- **`non-code-write-set-refused` was unsatisfiable on real data** — it fires for 11 tasks in one
  pinned sidecar, and is incompatible with `E7` AC-3, which requires a plan over those same fixtures.
- **`^\d+\s*단계\b` can never match `## 1단계`** in JavaScript: `\b` after a non-word character does
  not match there, so the marker the rule exists to accept is the one it rejects.
- **D4 recorded the wrong `observed`** in §3.6's own code block — always `orderedSections`, so a
  removal caused by `taskListGroups` reached `route.lock.json` as *"D4 observed 0"*.
- **§3 of `waves-event.md` has no enforcement requirement** (M-05). A `complete` after a `failed` is
  not refused. That is a gap needing a requirement, **not** something to implement silently.

## 7. Traps this session paid for

- **A red suite may be another agent's live mutation probe.** Two failure counts I read as cross-file
  pollution were one probe sampled twice. Re-read after the probe window before calling it a finding.
- **`npm install` from this shell prunes the dev tree.** `NODE_ENV=production` makes npm set
  `omit=dev`; `node_modules/.bin` emptied and every agent's `npx vitest` died. Repair:
  `NODE_ENV= npm install --include=dev`.
- **`vitest run --exclude '<glob>'` *replaces* the config's exclude array** rather than adding to it,
  dropping `**/.claude/worktrees/**` and picking up worktree copies of the whole suite — 114 phantom
  failures, seen.
- **A probe whose replacement string matches zero times removes nothing.** One agent's runner refused
  such a probe rather than reporting "guard not held". Do that.
- **A test that survives its own probe is not proof.** One agent's byte-change test tampered with
  `rung` and passed the probe that strips the content address — because `rung` is copied into
  `frozen.route`, so the digest moved anyway. It now tampers with a field the digest does not copy.
- **`toEqual` accepts a restated literal; `toBe` does not.** Two enum re-exports were asserted by
  identity for exactly this reason, and one of them had already drifted — `REASON_CLASSES` carried six
  values against the contract's eight, so the two values the orchestrator's own stops write were being
  diagnosed as invalid.
