## 2. 이번에 측정으로 드러난 것 (가설 아님)

1. **고지문이 인용을 깨뜨렸다.** `FR-FLOW-137` 이 44개 문서를 각 **+4줄** 밀었고, `00.charter.md` 의 `speckiwi init` 금지 조항을 가리키던 **주석 6개**가 4줄 위(TDD·검증 규칙)를 가리키게 됐다. **전체 스위트는 green.** 이것이 `FR-FLOW-141` 의 근거다.
2. **인용은 이미 썩어 있었다.** 전환 중 `auto-gate.ts` 의 인용 **4개 중 3개가 틀린 절**을 가리켰고, 하나(`kiwi-planner/SKILL.md:744`)는 **대상 문서의 끝을 넘은 줄**이었다.
3. **요구가 요구와 충돌했다.** `FR-FLOW-142` 가 **verified 였던 `FR-FLOW-023`** 의 AC-2(소진 종료)·AC-5(문서 수 × 3 팬아웃)와 정면 충돌. 우회하지 않고 재개봉→개정→재검증했다.
4. **그 과정에서 기존 테스트가 계약의 역에도 green 이었음이 드러났다.** AC-5 단언이 `문서 수`·`× 3`·`--max` **토큰 동시출현**만 봐서, "문서 수와 무관하게 3개"라는 **정반대 문장이 세 토큰을 모두 포함해** 통과했다. 단언을 강화해 함께 고쳤다.

> 토큰 동시출현은 주장과 그 부정을 구별하지 못한다. 이 세션에서 같은 계열의 결함이 나온 것은 이번이 네 번째다.

## 2.5 손대지 않은 더 큰 비용원 — 사용자 판단 필요

독립 조사 두 건이 **이번 변경 밖**에서 더 큰 비용을 지목했다. 둘 다 의도적으로 건드리지 않았다.

**(가) `kiwi-coder` 의 Sonnet×4 TDD 검증이 task 마다 무조건 뜬다.** 스킬 자신이 "모든 모드 공통 … 모드 변경 영향 없음"이라고 명시하며, `--mini`/`--loops N` 으로도 줄지 않는다. **task 20개짜리 plan 이면 80개 서브에이전트**가 고정비다. 이번에 없앤 `kiwi-srs` 의 "문서 수 × 3" 팬아웃보다 실무에서 훨씬 자주·크게 발생한다. 문서 수가 아니라 **task 수**로 곱해지기 때문이다.

**(나) 같은 REQ 하나가 구조적으로 최대 4개의 독립 루프를 순차 통과할 수 있다.**

| 루프 | 라운드 상한 |
|---|---|
| `kiwi-srs` §11.2 | Normal 5 / `--max` 15 |
| `kiwi-srs-feasibility` §9.2 | Normal 5 / `--max` 15 |
| `kiwi-planner` §6.5 | 상한 미명시 |
| `_shared/kiwi/verify-loop.md` §5 | 5 / 8 / 3 |

상한 없는 루프는 **없다**(전수 확인). 문제는 상한이 아니라 **루프의 개수**다. 다만 "실제로 한 REQ 에 넷이 모두 발동한 실행 기록"은 찾지 못했다 — 구조적 가능성은 사실, 실사례는 미확인.

**(다) SRS 산문 품질을 직접 겨냥하는 축은 셋뿐이고, 셋 다 실제 결함을 잡은 기록이 0건이다** (`kiwi-srs` axis 9 `internal_coherence`, `kiwi-srs-sync` A4 `ac_text_quality`, `kiwi-planner` A10). 그럼에도 **제거하지 않았다**: repo `CLAUDE.md` 가 2026-08-17 사용자 결정으로 **"SRS acceptance criteria" 를 완화 대상에서 명시적으로 제외**했기 때문이다. axis 9 는 "AC 검증" 이 아니라 "AC 문장이 모호한가" 라는 별개 축이라 그 제외가 반드시 보호한다고 보기는 어렵지만, **standing 사용자 결정과 부딪히므로 확인 없이 뒤집지 않는다.** 없앨 경우 "모호 어휘·AC 간 모순" 탐지는 대체 기계 검사가 없어 공백이 된다(확인됨).

## 4. 표준 지침 (반드시 지킬 것)

### 4.1 금지
- **`speckiwi init` 절대 금지** — 특히 `--force` 는 `00.index.md` 를 템플릿으로 덮어써 요구 인덱스를 파괴
- `speckiwi skills install` · `speckiwi upgrade` 금지. **`speckiwi skills mirror --write` 는 허용**(`.agents/skills/**` 의 유일한 정당 기록자)
- `git checkout` · `restore` · `stash` · `clean` · `reset --hard` 금지
- 커밋 메시지에 **어떤 시그니처도 금지**. 커밋 후 `git log -1 --format="%B"` 로 0건 검증. 제목에 `Phase {n}`·`Step {n}` 금지
- `npm install` bare 금지 — 셸이 `NODE_ENV=production` 을 물어 devDependencies 를 prune. 빌드 `NODE_ENV=development`, 테스트 `NODE_ENV=test`

### 4.2 필수
- **TDD test-first.** 통과해버린 기준은 **구현 전에 강화하고 red 재확인** — 이번에 부정 목록(denylist) 단언 두 벌이 대상이 없어 공허하게 통과했고, 존재 단언을 넣어야 red 가 됐다
- **판단 검증은 서브에이전트에게.** 자기검증 금지(객관 PASS/FAIL 카운트만 예외)
- 소스 census 는 **`grep -a` 필수** — `src/`·`test/` 밑 다섯 파일에 NUL 바이트
- **전체 스위트는 단독으로 돌린다.** 이번에도 서브에이전트 2개와 동시 실행해 **`Test timed out in 5000ms` 39건**이 났다. 실패 21파일 중 실제 단언 실패는 4건뿐이었다
- CLI 는 **`node bin/speckiwi`** 로 부른다 — `node dist/cli/index.js` 는 아무 출력 없이 exit 0 이다

### 4.3 배포 게이트
`build` → `version:check` → `release-check --strict` → `release:acceptance` → 전체 스위트. 버전 범프 시 `package-lock.json` 의 version 필드 2곳도 함께.
