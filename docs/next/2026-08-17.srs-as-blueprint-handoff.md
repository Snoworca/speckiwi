## 1. 다음 할 일

### 1.1 즉시 — 조사 3축 결과 회수

**주석 검증 비용** 조사를 서브에이전트 3개로 띄웠고, compact 시점에 **아직 도는 중이었다.** 결과가 유실됐다면 재실행해야 한다. 축과 질문은 `docs/research/20` §2.3 에 있고, 브리프 요지는:

| 축 | 질문 |
|---|---|
| A | 무엇이 주석을 검증 대상으로 만드나 · 실제 주석 결함이 **치명적이었나 미용이었나** · 지금 틀린 주석이 몇 개인가 |
| B | 기계 검사 가능한 주석 주장 vs **금지해야 할 주장 유형**. 최고가치 미검사 유형을 프로토타입해 **실제 실행** |
| C | 지시가 어디 있나 · 정책과 스킬이 **모순인가** · 없애면 무엇을 잃나 · 최소 수정안 |

A·C 에는 반드시 **"증거가 없으면 없다고 말하라"** 를 넣을 것. 주석 리뷰가 치명적인 것을 잡은 기록이 없다면 그 부재가 결론이고, 유지할 명분을 지어내면 안 된다.

**C 축은 회수 완료. 가설 둘 다 확정됐다** — 결과는 `docs/research/20` §2.5 에 있고, 그것이 이 작업의 실행 계획이다. 요약:

- `CLAUDE.md:23` 은 "주석은 라운드로 검토하지 않는다" 인데, `skills/{claude,codex,etc}/kiwi-coder/SKILL.md:470` 이 **주석 표현·서식을 LOW 로 두고 improve loop 에서 최소 1라운드 재작업**시킨다(`:435`). 스킬이 13일 더 오래됐고 스킬이 실제 동작을 지배한다.
- `test/skills/kiwi-coder-comment-claim-axis.fr-flow-120.test.ts` 가 그 행을 **정확 문자열 일치**로 4개 사본에 고정한다. **지시를 지우면 스위트가 red** 가 되므로 정책만 고쳐서는 아무것도 안 바뀐다.
- **표현 재작업이 방어한 결함은 어디에도 기록이 없다.** 반면 **축 8(주석 주장 진위, 닫힌 4종)은 유지**한다 — 표현이 아니라 사실을 보고, 비용이 `existsSync`/`grep -c` 수준이며, 인용된 근거가 있다.

**A(결함 전수조사)·B(주장 유형 분류)는 미회수.** 재실행 시 축·브리프 요지는 아래 표와 `docs/research/20` §2.3 참조. **A·B 가 C 의 결론을 뒤집을 수 있으므로**, 실행 전에 회수하거나 재실행할 것.

`docs/research/20` §2.5 는 C 축만의 결과임이 문서 안에 명시돼 있다. **A·B 결과를 미리 지어내 채우지 말 것** — 조사 없이 쓴 주장이 요구로 넘어가는 것이 이 저장소의 반복된 실패다.

### 2.2 새로 생긴 정책 — 검증 강도

repo `CLAUDE.md` "Verification intensity policy" (사용자 승인 2026-08-17):

- **산문(README)**: 기계 검사 → 변경분 델타 **1라운드**로 종료. LOW 잔존 허용. 파괴적 명령 문단만 예외
- **에이전트 지시(SKILL.md)**: 드리프트 기계 검사 + 델타 **≤2라운드**. 안전 경계·계약 게이트 섹션은 제외
- **주석**: 라운드 검토 없음. `@req` 실재성 + 안전 게이트 why-주석만. 재서술 주석은 **삭제 대상**
- **코드·계약·SRS AC·안전 경계는 완화 없음** — TDD·per-AC 뮤테이션·CRITICAL/HIGH 0 유지
- 정지 기준은 **라운드 수가 아니라 증거 완결성**

### 2.3 이 세션의 지배적 교훈

**산문 리뷰는 코드를 실행하지 않으므로 코드에 관한 주장을 검증할 수 없다.** `research 19` 가 수치 셋과 아키텍처 결론 하나를 틀린 채 요구까지 넘겼는데, 구현자가 코드를 돌려 몇 분 만에 전부 잡았고 **오류의 실제 비용은 0** 이었다. 그것이 `FR-FLOW-137`(연구 미검증)과 `FR-FLOW-139`(구현자가 요구를 반박)의 근거다.

**검사가 자기 결함을 잡은 사례 셋** — 이 방향이 작동한다는 가장 강한 증거:
- 도구 토큰 정규식이 `workflow_*` 를 매칭 못 해, prefix 분기가 실제 README 에서 **아무것도 검사하지 않은 채 전 테스트 green**. 실제 문서 단언을 넣어서야 red
- `@req` 픽스처의 가짜 ID 리터럴이 **진짜 미해소 인용을 심음** → 이스케이프 해치의 존재 이유
- 전체 스위트가 **두 구현의 자체 테스트도 어떤 리뷰 라운드도 못 잡은 것**을 잡음 — 장부 CLI 동사가 레지스트리를 우회해 명령 이름이 두 곳에 존재(`FR-ARCH-006` 양방향 실패)

**요구가 틀렸던 8건**은 `docs/research/20` §1.4 에 유형별로 있다. 전부 구현자가 잡았다.

## 4. 표준 지침 (반드시 지킬 것)

### 4.1 금지

- **`speckiwi init` 절대 금지** — 특히 `--force` 는 `00.index.md` 를 템플릿으로 덮어써 요구 인덱스를 파괴
- `speckiwi skills install` · `speckiwi upgrade` 금지. **`speckiwi skills mirror --write` 는 허용**(`.agents/skills/**` 의 유일한 정당 기록자)
- `git checkout` · `restore` · `stash` · `clean` · `reset --hard` 금지
- 커밋 메시지에 **어떤 시그니처도 금지**. 커밋 후 `git log -1 --format="%B"` 로 0건 검증
- 커밋 **제목**에 `Phase {n}` · `Step {n}` · `TASK-XXX` 금지
- `npm install` bare 금지 — 셸이 `NODE_ENV=production` 을 물어 devDependencies 를 prune. 빌드 `NODE_ENV=development`, 테스트 `NODE_ENV=test`

### 4.2 필수

- **TDD test-first.** 구현 선행 시 버리고 다시. 통과해버린 기준은 **구현 전에 강화하고 red 재확인**
- **판단 검증은 서브에이전트에게** 편향 없는 입력만. 자기검증 금지(객관 PASS/FAIL 카운트만 예외)
- 소스 census 는 **`grep -a` 필수** — `src/`·`test/` 밑 다섯 파일에 NUL 바이트
- 사용자 결정은 **5인 결정위원회 자동결정**. `AskUserQuestion` 금지
- **전체 스위트는 단독으로 돌린다.** 동시 실행이 이 세션에서 측정을 세 번 망쳤다. 결과를 `tail` 로 잘라 저장하지 말 것 — 실패 상세가 유실돼 50분을 다시 썼다
- 구현 브리프에 반드시 넣을 것: **"요구가 틀릴 수 있다. 우회하지 말고 보고하라"** — 이것이 요구 결함 8건을 만들었다

### 4.3 배포 게이트

`build` → `version:check` → `release-check --strict`(ready) → `release:acceptance`(16/16) → 전체 스위트. 버전 범프 시 `package-lock.json` 의 **version 필드 2곳**도 함께 고쳐야 `version:check` 가 통과한다.
