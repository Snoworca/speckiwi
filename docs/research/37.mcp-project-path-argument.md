# SRS 조회 도구의 프로젝트 경로를 필수 인자로, MCP 루트 설정 제거 — 조사

제안 원문: "srs 탐색 도구의 선택 인자가 아니라 기본 인자로 프로젝트 경로를 입력 받도록 하는 것은 어떨까요? mcp 에 루트 경로 설정을 제거합시다."

조사일 2026-10-21, 브랜치 `feat/2.3.0.1`(HEAD 6a7f7c1), 측정은 `dist/` 빌드로 했다. 저장소 파일은 고치지 않았다.

## 0. 결론 먼저

1. **지금 MCP 에는 사용자가 정하는 "루트 경로 설정"이 없다.** `--root` 는 거부되고(`src/cli/commands/mcp.ts:11-13`, `:25-29`), 환경 변수도 없으며(`src/` 전체에서 `process.env.*ROOT` 0건), `.mcp.json` 실행 항목에도 경로가 없다(`src/core/bootstrap/mcp-registration.ts:30`, `:33`). 루트는 **서버 프로세스의 cwd 하나**에서 나온다(`src/mcp/server.ts:584-603`). 그래서 "설정 제거"는 실제로는 **서버가 자기 프로젝트를 갖지 않게 하는 것**이고, 그러면 모든 도구가 호출마다 경로를 받아야 한다.
2. 그 형태(아래 선택지 (i))는 **한 서버가 호출마다 아무 프로젝트나 섬기는 구조(A)**다. 다섯 번 거절된 다중 root 호스팅의 여섯 번째 개봉이며, 쓰기 도구의 안전 근거(요구 ID 카운터·SRS 잠금이 root 별이라는 점, `FR-FLOW-122` 의 "SRS 변이는 호스트 소유")와 정면으로 부딪힌다. **권하지 않는다.**
3. 그러나 제안이 겨냥한 실제 고통은 있다. 가장 확실한 것은 **cwd 가 홈이거나 SRS 가 없는 곳에서 MCP 가 뜨면 그곳에 `init` 을 자동 실행한다**는 점이다. 이번에 실행으로 재현했고(§4.2), 사용자 PC 의 홈에도 그 흔적이 남아 있다.
4. 권고: **(iii) 축소판** — per-call `workspaceRoot` 는 지금처럼 선택 인자로 두고, **기동 시 auto-init 을 없애** SRS 가 없는 cwd 에서 뜬 서버는 "미결속" 상태로 모든 호출을 구조화된 거절과 복구 안내로 돌려준다. 필수 인자화와 서버 루트 제거는 하지 않는다.
5. 시기: **4.1.0 에는 넣지 않는다.** 4.1.0 의 목표는 SDS opt-in 이다(`docs/spec/00.index.md:88`, `:118`). 권고안은 4.1.0 뒤의 별도 작은 target 으로 등록한다(§5.3).

### 2.3 시작 root 가 없으면 무엇이 "정당한 프로젝트"를 보증하나

지금 보증은 하나다: 후보가 **시작 root 와 같은 git common dir** 을 쓰는가(`workspace-root.ts:119-127`, REL-MCP-005 AC-5 `:4253`, AC-7 `:4255`). 시작 root 를 없애면 이 비교의 한쪽 변이 사라진다. 남는 후보는:

1. **경로 자체에서 얻는 검사만**: 절대 경로·실존·git 최상위·`docs/spec/00.index.md` 존재(`workspace-root.ts:95-118`, `:139-142`). 이것은 "아무 저장소나 받는다"와 같다 — REL-MCP-005 AC-7 이 금지하는 "시작 root 의 저장소가 아닌 저장소를 읽거나 변이"가 정상 동작이 된다.
2. **첫 호출 고정**: 첫 `workspaceRoot` 의 common dir 을 세션 기준점으로 삼고 이후 호출을 그것과 대조. 새 상태(세션별 기억)가 생기고, 첫 호출자가 틀리면 그 세션 전체가 틀린다.
3. **주 워크트리 판정**: 변이는 linked worktree 가 아닌 주 체크아웃에서만 허용(`src/core/orchestrator/worktree-topology.ts:129`, `:159-160` 에 같은 판정이 이미 있다). FR-FLOW-122 의 "호스트 소유"를 구조로 지키지만, 서로 다른 저장소를 막지는 못한다(그 저장소들의 주 체크아웃은 모두 통과).

어느 것도 지금의 "서버를 띄운 곳이 곧 대상"보다 강하지 않다.

## 3. 이것은 거절된 다중 root 호스팅인가

### 3.1 두 해석

- **(A) 한 서버가 호출마다 주어진 아무 프로젝트를 섬긴다.** 시작 root 없음, 기준점은 경로 자체. 제안 문구("mcp 에 루트 경로 설정을 제거")를 문자 그대로 읽으면 이쪽이다.
- **(B) 서버당 프로젝트는 하나, 경로만 명시.** 서버가 여전히 자기 프로젝트를 알아야 경로를 대조할 수 있다. 그런데 그 "자기 프로젝트"를 아는 방법이 지금은 cwd 뿐이므로, (B) 는 결국 지금 구조 + 인자 필수화다. 서버 루트를 없애고 (B) 를 하려면 §2.3 의 2번(첫 호출 고정)이 필요하다.

(A) 는 `docs/spec/00.index.md:210` 의 v2.4.2 목표가 범위 밖으로 적은 "multi-root runtime hosting" 그 자체이고, 다섯 번 거절됐다(2026-05-26 / 07-06 / 07-27 / 07-31 / 08-07, `docs/research/15.orchestrator-run-root-multi-module-research.md:170-181`, REL-MCP-005 Rationale `40.mcp-stdio-interface.srs.md:4242`). 연구 15 는 이것을 "도구 개선이 아니라 제품 범위 결정"이라고 적었다(`:181`).

### 3.2 재개봉 선행조건 세 가지와 현재 코드

| 조건 | 현재 상태 | (A) 에 대한 판정 |
|---|---|---|
| (a) FR-FLOW-043 AC-2/AC-5 재정의 | AC-5 는 정지된 run 의 pipeline 이벤트 경로를 "run 자신의 cwd 기준 1회, MCP root 로는 절대 해소하지 않음"으로 정한다(`docs/spec/60.workflow-release.srs.md:3267` 블록 AC-5) | 서버 root 가 없어지면 "MCP root 로 해소하지 않는다"는 자동으로 지켜진다. 충돌은 없다. 다만 FR-FLOW-042 의 MCP root ↔ git root 대조는 비교 대상 하나가 사라져 요구를 다시 써야 한다 |

정리: (c) 는 이미 풀렸고 (a) 는 문면 재작성으로 풀 수 있으나, **(b) 는 변이를 여는 순간 다시 생긴다.** 그리고 (A) 는 선행조건과 별개로 범위 결정이 남는다.

## 4. 제안이 풀려는 실제 고통 — 증거

### 4.1 워크트리 분열 (이미 해소된 부분)

- 같은 세션에서 `EnterWorktree` 후에도 `mcp_workspace_info` 는 호스트(`v2.4.1`)를, 워크트리 cwd 의 CLI 는 워크트리(`v2.3.0.1`)를 보고했다(`docs/research/12.kiwi-wave-master-worktree-isolation-research.md:50-66`). CLI 와 MCP 의 root 해석 방향이 반대다(`:120-130` 부근 T5).

### (ii) 조회 도구만 필수, 변이는 서버 root

- 판정: 비용 대비 이득이 가장 작다.

### (iii) 선택 인자 유지, auto-init 제거 — 미결속 상태로 실패 (권고)

- 내용: 기동 탐색이 index 를 찾지 못하면(홈 포함) 서버는 뜨되 root 를 결속하지 않는다. 모든 도구가 구조화된 거절을 돌려준다: 검사한 cwd, "이 디렉터리에는 SRS 가 없다", 복구는 "프로젝트에서 `speckiwi init` 을 실행하거나 프로젝트 디렉터리에서 MCP 를 띄우라". 파일은 하나도 만들지 않는다. per-call `workspaceRoot` 는 미결속 상태에서도 거절한다 — 기준점이 없으므로(§2.3).
- 고치는 것: §4.2 의 홈·타 프로젝트 오염. 제안의 직접 동기는 아닐 수 있으나, "루트 설정이 엉뚱한 곳을 가리킨다"는 고통 중 실측된 유일한 미해소 사례다.

REL-MCP-002 AC-4(`:1299`)는 이미 사라진 `--root` 를 말하므로 같이 정리한다.
- 테스트: `test/mcp/root-source-auto-init.rel-mcp-005.test.ts`, `test/mcp/startup-cwd.test.ts` 의 AC-2 사례 개정, 미결속 거절 테스트 신규. 관리 지침 템플릿 6항(`templates.ts:540`)의 `auto-init` 언급 수정.
