## 1. Executive Summary

The v2.3.0 tool-improvement goal is valid and source-backed. The current codebase already has strong SRS parser, mutation, CLI, MCP, and release-readiness foundations, but agent-facing tool reliability breaks down in five places:

1. Existing SRS mutation adapters do not expose the same safe behavior across core, CLI, and MCP.
2. Target creation and Active Target defaulting are documented and partially modeled but not implemented.
3. Read and diagnostic tools are too heavy or too weak for low-token agent operation.
4. Kiwi planner, PM, coder, and pipeline artifacts have no official compact readers, validators, or safe mutators.
5. Packaging and MCP preflight checks do not prove that installed tools are usable before skills depend on them.

`OPS-FLOW-001` is a verified research requirement, not a behavior contract for implementation. Code changes must target canonical v2.3.0 Requirement IDs, not research-only `CAND-*` labels.

## 6. Decision Rules

1. Fix existing trust blockers before adding broad new workflow mutators.
2. Build resolver and JSONL parser before any plan/pipeline/session command.
3. Build read-only plan/pipeline/session tools before `get_next_work_order`.
4. Build validators before guarded checklist/task-status mutation.
5. Build logical delete only after shared workflow mutation envelopes and validators exist.
6. Migrate Kiwi skills only after official tools exist and tests prove parity.
7. Treat numeric token reduction as a hypothesis until fixture measurements print before/after payload sizes.
