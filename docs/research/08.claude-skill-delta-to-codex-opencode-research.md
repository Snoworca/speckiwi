## Content Findings

### Shared `--auto` Policy

`skills/claude/_shared/kiwi/auto-option.md` defines:

- activation channels for explicit `--auto` input;
- sub-agent decision topology;
- `--auto --max` merge behavior;
- confidence thresholds;
- `critical_gates[]` interfaces;
- child-skill propagation;
- decision logs and artifacts;
- migration notes for existing Kiwi skills.

This is the highest-leverage reusable concept, but also the highest conversion risk.

For Codex, it needs replacement of Claude-specific `Skill(...)` / `Agent(...)` syntax, model names, and Plan-mode clarification semantics.

For OpenCode/Hermes, it needs a deeper rewrite because the current `--auto --max` topology uses parallel decision agents and a merge agent. `MIG-FLOW-002` requires the etc local-LLM profile: default `--max`, no multi-worker fanout, one delegated worker/evaluator at a time, and three consecutive clean evaluations.

### High-Risk Semantics

`kiwi-pm` changes are behaviorally significant: `business-decision` changes from automatic halt to sub-agent decision with confidence threshold, except for explicit critical gates. This must be carefully translated and tested because it affects user-consent boundaries.

`kiwi-coder` adds automatic follow-up to `kiwi-review-fix-loop --close-reqs --auto`. This crosses from implementation to verification closure and must remain compatible with the repository rule that requirements cannot be bulk-finalized without per-requirement evidence and stability gate checks.

`kiwi-review-fix-loop --close-reqs` is intentionally powerful. In Codex and etc variants it must require `speckiwi mcp`, evidence creation, requirement-by-requirement checks, and no bulk-archive or bulk-finalize behavior.

`kiwi-hot-fix` includes stability-gate bypass language for urgent repair with later SRS sync. This must be reconciled with AGENTS.md draft/deprecated blockers and `FR-FLOW-012` MCP-first governance before implementation.

`kiwi-coder` currently removes the top `Kiwi MCP rule` line in the working-tree diff and changes a recorded `speckiwi` version value from `2.2.3` to `2.2.2`. Both should be treated as anomalies until confirmed intentional.

## Conversion Rules

### Claude to Codex

| Claude pattern | Codex target rule |
|---|---|
| lowercase `skill.md` | use uppercase `SKILL.md` |
| long monolithic `SKILL.md` | keep entrypoint concise and move long procedures to `references/extended-workflow.md` |
| `Skill(...)`, `/kiwi-*` | use Codex skill references such as `$kiwi-*` or neutral "run the kiwi-* workflow" wording |
| `Agent(...)`, `Task(...)`, `subagent_type` | use Codex-neutral delegation wording; avoid executable Claude pseudo-tool syntax |
| `AskUserQuestion` | use direct user clarification; mention `request_user_input` only when Plan mode provides it |
| `Opus`, `Sonnet`, `Haiku` | rewrite to role/cost tiers such as senior reviewer, standard reviewer, lightweight evaluator, or lower-cost mode |
| `~/.claude`, `.claude`, `CLAUDE.md` as sole authority | rewrite to repository-relative paths and `AGENTS.md`; mention `CLAUDE.md` only as compatibility input |
| raw `mcp__speckiwi__...` calls | describe SpecKiwi MCP tool use without Claude-specific function-call syntax |

### Claude to OpenCode/Hermes `skills/etc`

| Claude/Codex pattern | etc target rule |
|---|---|
| `--mini`, `--squirrel` as active mode controls | remove or isolate as legacy notes; etc defaults to `--max` |
| parallel sub-agent or evaluator fanout | collapse to one delegated worker/evaluator at a time |
| `--auto --max` multi-agent merge | replace with sequential single-evaluator decision and three clean evaluations |
| Codex/OpenAI metadata | do not copy `agents/openai.yaml` into etc |
| Codex/Claude invocation syntax | use Open Agent Skills-neutral wording |
| normal CLI mutation fallback | prohibit; CLI is diagnostics/remediation only |
| direct normal SRS Markdown edits | prohibit; normal SRS operations require `speckiwi mcp` |
