## 1. 문제 — tdd 추적성 이중 공백

sdd 경로(kiwi-coder)는 프로덕션 코드에 `// @req <REQ-ID>` 주석(FR-FLOW-020 관례)을 붙이고 `add_trace_link(type=code)`로 SRS Trace Links(Code anchor)도 기록한다. tdd 경로(kiwi-tdd)는 Phase 4(green)에서 프로덕션 코드를 작성하지만 **@req 코드 주석도, SRS Trace Links도 둘 다 지시하지 않는다** → tdd로 승격된 요구는 코드 추적성이 이중으로 빈다.

## 2. 조사 확정 사실 (invest-req)

- **promote_step_requirement는 요구 블록을 byte-for-byte 복사(재할당 없음)** — 최종 body REQ ID는 Phase 6(요구 블록 저작) 시점 확정·불변. Phase 4 구현 코드는 그 이전에 작성되어 그 시점엔 canonical ID가 없다.
- claim_step은 ID를 mint하지 않음(`--touches-req`는 기존 REQ 참조·충돌 게이트 입력). synthesize도 canonical ID를 allocate하지 않음.
- `@req`는 **순수 grep 보조**(FR-FLOW-020: "gates nothing … purely informational breadcrumb"), SSOT는 `add_trace_link`. 부패 허용, 어떤 게이트도 검증 안 함. 테스트 파일은 부착 면제.
- **FR-FLOW-020(관례 SSOT, implemented)**은 sdd(REQ-ID)·vibe(task-name)만 스코프하고 **tdd는 미포함**. AC-2가 이미 "REQ가 아직 없을 때 task-name 태그 → synthesis 때 귀속" 기계를 정의 — tdd의 post-hoc 사례와 동형.
- kiwi-coder §0.17은 kiwi-coder 전용 구조(worklog enum·게이트 면책·ZERO TOLERANCE·Sonnet×4·sidecar type)에 결합 → 복제 시 실체 없는 참조가 박힘.

## 3. 결정 (위원회)

- **Q1 = A (5:0)**: kiwi-tdd Phase 6(promote로 body ID 확정 후)에 Phase 4 구현 코드의 태그를 최종 REQ-ID로 **reconcile**한다. FR-FLOW-020의 vibe-mode 기계(Phase 4엔 task-name 태그 → 확정 후 reconcile)를 재사용해 drift를 구조적으로 제거. §0.17은 **형식·면제 규약(단일라인 형식·테스트 면제·부착 위치)만 참조**하고 kiwi-coder 운영 훅은 수입 금지. 최소 골자 ~15줄로 자기충족 못 하면 D(미부착)로 폴백.
- **Q2 = Yes (5:0)**: kiwi-tdd Phase 6에 `add_trace_link(type=code, relation=implements, 구현 파일 경로)`를 추가해 승격 REQ에 Code anchor(SSOT) 복원. **단 sdd와 동일하게 비차단(non-gating)** — code trace link 부재가 promote를 막지 않으며 EVIDENCE_REQUIRED 게이트(§0.6)와 분리.
- **Q3 = FR-FLOW-020 확장 + 신규 REQ**: 관례 규칙(tdd 태그·reconcile)은 SSOT인 **FR-FLOW-020에 tdd 스코프 추가**; 스킬 행위(kiwi-tdd Phase 6 reconcile + add_trace_link)는 **신규 FR-FLOW REQ**(v2.4.0). verified인 **FR-FLOW-037 재개봉 반대**(감사상 닫힌 기록).

## 4. 위원회 조건 (구현 계약)

1. **비차단**: Trace Links·@req 둘 다 promote를 막지 않음(FR-FLOW-020 "gates nothing" 계약 상속).
2. **검증은 콘텐츠 테스트만**: 스킬 텍스트 단언으로 검증하고 프로덕션 코드를 스캔하는 게이트를 만들지 않음.
3. **계층화**: Trace Links = 권위 의무(SSOT), @req = 보조 breadcrumb.
4. **타이밍**: 부착·링크는 Phase 6(body ID 불변 확정) 이후에만 — Phase 2/4 부착은 stale·중복 ID 회귀 유발(금지).
5. **파일 추적**: Phase 4에서 touched 프로덕션 파일을 기록해 Phase 6가 정확한 경로를 add_trace_link에 인용.
6. **§0.17 참조 한정**: 형식·면제만 인용, 운영 훅(worklog enum·게이트 면책·ZERO TOLERANCE) 수입 금지.

## 5. 구현 REQ 구성

- **FR-FLOW-020 확장**: Requirement 텍스트에 tdd 모드(post-hoc 승격 → green 시 task-name 태그 → synthesis/promote 때 REQ-ID로 reconcile) 추가 + AC-4 신설. (target v2.3.0.1, implemented 유지)
- **신규 FR-FLOW-041**(v2.4.0): kiwi-tdd Phase 6 추적성 스텝 — @req reconcile + add_trace_link(code) 비차단, 콘텐츠 테스트 검증. 3변형.
