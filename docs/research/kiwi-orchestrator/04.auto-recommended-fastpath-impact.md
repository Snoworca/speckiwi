# 04 — Blast radius of the `--auto` recommended-option fast path

Date: 2026-07-31
Branch: `feat/2.3.0.1` (HEAD `031c4ec`), working tree clean at survey time
Status: read-only survey. Nothing was edited.

Scope: what the proposed change to the `--auto` decision contract touches.

Proposal under assessment:

1. When a user-decision gate presents options and one is **marked recommended**, `--auto` adopts
   it immediately, convening no committee.
2. When no option is marked recommended, a **3-member committee decides by simple majority**;
   the unanimity requirement and the 3 → 5 escalation ladder are removed.
3. Out of scope for this version: any gate that judges *why* an option carries a recommendation.

## 2. Question 2 — does a "recommended option" concept exist today?

**No. It would have to be introduced.** There is no field, no label convention, and no reader.

### 2.1 What exists

**One structured option schema, in one place.** `kiwi-pm` defines the NEEDS_USER question payload
at `skills/claude/kiwi-pm/SKILL.md:468-482` (codex `:474-488`, etc `:464-478`,
`.agents/skills/kiwi-pm/SKILL.md:474-488`):

```
"options": [
  { "key": "A", "label": "...", "consequence": "..." },
  { "key": "B", "label": "...", "consequence": "..." }
],
"default_if_auto": "A | null"
```

`options[]` has exactly three fields — `key`, `label`, `consequence`. No recommendation marker.

**The nearest existing concept is `default_if_auto`, and it is a sibling of `options[]`, not a
property of an option.** Its semantics are already a committee bypass:

- `skills/claude/_shared/kiwi/auto-option.md:283` — "`default_if_auto: <X>` → 해당 default 값을
  `severity=clarification` confidence=1.0 결정으로 채택 (서브에이전트 우회 가능 — fast path)".
- `…:126` — dispatch priority 3: if `decision == default_if_auto`, run that branch.
- `skills/codex/_shared/kiwi/auto-option.md:193` — "may be applied directly for low-risk
  clarification gates". `skills/etc/…:202` narrows it to "only for low-risk clarification".

Differences from the proposal that matter:
1. `default_if_auto` is scoped to `severity=clarification`. The claude copy's dispatch rule is
   unscoped but §6 forces `severity=clarification`; the etc copy says "only for low-risk
   clarification". The proposal's recommended fast path is **severity-agnostic** — it would fire on
   `business-decision` gates too.
2. `default_if_auto` is authored by the *child skill* declaring the gate; a "recommended" mark is
   a property of an option a *presenter* sets. The two can disagree.
3. It is declared in exactly **one** skill's payload schema (`kiwi-pm`); 14 other skills have no
   equivalent field. `default_if_auto` occurs at 4 lines in `skills/claude/kiwi-pm/SKILL.md`
   (`480`, `669`, `734`, `763`) and 2 in `auto-option.md` (`126`, `283`) — 6 sites in the canonical
   rendering.

**An informal, ad-hoc `(권장)` annotation exists in prose option labels at exactly 3 sites**, all in
`kiwi-pm`, and nothing reads it:

- `skills/claude/kiwi-pm/SKILL.md:553` — "(A) HALT — kiwi-srs-feasibility 실행 후 재시도 (권장)"
- `skills/claude/kiwi-pm/SKILL.md:643` — the same option inside a NEEDS_USER options array
- `skills/claude/kiwi-pm/SKILL.md:836` — "(a) `{plan_id}.checklist.md` 자동 생성 (권장)"

These are human-readable hints embedded in label strings. `auto-option.md` never parses them.
Notably, `:553` / `:643` recommend **HALT** — a recommended-option fast path reading that label
would auto-adopt a halt, which is benign, but it shows the annotation was never written with
machine consumption in mind.

### 2.2 What would have to change, and at how many sites

**Contract layer (4 bundled + 2 installed copies of `auto-option.md`):**

1. Add `recommended: true|false` (or equivalent) to the §2.1 subagent-input `options[]` description
   (claude `:44`) and to the §2.3 committee prompt template (claude `:85-86`).
2. Add a new dispatch tier above §2.4.1 priority 1 (claude `:122-127`) — "recommended option
   present → adopt, no committee".
3. Rewrite §2 sizing table (claude `:29-34`) and §3 ladder (claude `:143-159`).
4. Reconcile with §6 read-time replace (claude `:283`) — decide whether `default_if_auto` remains a
   separate mechanism, becomes an alias for `recommended`, or is retired. Leaving both creates two
   fast paths with different severity scopes and no stated precedence.
5. Extend the §10 log schema (claude `:329-359`) — `merge_method` currently enumerates
   `unanimous` / `plurality` / `tie-break-lead`; a `recommended-fastpath` rule with zero
   `committee_votes` needs a shape, or the audit trail silently loses every fast-pathed decision.
6. Update §4 severity table (claude `:181-190`) to say whether the fast path applies to
   `business-decision` and `rollback-confirmation`, and whether §4.1 confidence adjustment
   (claude `:192-222`) applies at all when no committee ran (it cannot — there is no `confidence`).

### 3.4 Internal inconsistencies the change creates inside `auto-option.md`

These are not test failures; they are contradictions the rewrite must resolve or the document
becomes self-refuting.

1. **§4.1.2 confidence cross-check (claude `:209-212`, codex `:137-141`, etc `:144-148`)** is built
   entirely on the escalation ladder: on a confidence spread ≥ 0.3 a non-terminal committee
   escalates one rung and re-votes *even when unanimous*. With no rungs below the terminal size in
   non-max mode, this rule has nowhere to go — every non-max low-confidence disagreement becomes an
   immediate critical HALT. That is *more* conservative than today, and it interacts badly with
   simple majority: a 2-1 split with a wide confidence spread would decide 2-1 by the new rule and
   halt by §4.1.2. Precedence is undefined.
2. **§3.1 quorum (claude `:165`, codex `:105-109`)** — after dropping a failed member, proceed

   plurality → immediate HALT" would forbid the recommended fast path as written, since a
   fast-pathed decision is neither.
5. **§8 (claude `:313`)** restates the `--max` ladder inline.

## 4. Question 4 — the safety question, stated neutrally

Under the current contract a 2-1 split at a 3-member committee **escalates** to 5 and re-decides;
if the 5 are not unanimous, a 3-2 decides. Under the proposal a 2-1 **decides**. Separately, a gate
carrying a recommended option is decided by **no deliberation at all**.

### 4.1 Which gates change hands

`critical_gates[]` gates are unaffected — ~95 declared rows across 15 skills halt regardless. The
population that changes is **everything else**: `auto-option.md` §4 (claude `:190`) classifies any
gate with no declared severity and no `critical_gates[]` row as `business-decision`, which
`--auto` auto-decides at confidence ≥ 0.7. That default is the reason the affected set is open-ended
rather than enumerable — `test/skills/kiwi-wave-continuity-r3-content.test.ts:1368-1408` and
`kiwi-wave-continuity-r2-content.test.ts:715` were written precisely because undeclared gates fall
through to the committee.

- A wrong `Closes #N` closes someone else's GitHub issue. `kiwi-commit-auto-push` §11.10 already

immediately and universally the moment the contract text changes, including to the commit/PR gates

about the gate; (a) buys it everywhere including where nobody has.
