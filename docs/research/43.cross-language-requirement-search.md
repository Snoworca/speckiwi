## 0. 요약

1. **앞선 보고서의 권고만으로는 "한 언어로 물어 다른 언어 AC 를 찾기"가 풀리지 않습니다.** 도구 쪽 장치(2-gram + 한→영 용어집)만 쓰면 한→영 Recall@10 이 0.48~0.51 이고, 영→한은 0.375 입니다. 초안 B 의 AC-5("한글이 없는 질의는 용어집 없이 처리")가 영→한 확장을 막기 때문입니다.
2. **영→한이 이 기능의 주된 방향입니다.** 새 요구는 영어로 쓰이고(FR-NODE-086), 중복 · 충돌 후보로 찾아야 할 기존 요구 가운데 한글 AC 를 가진 살아 있는 요구 110개 중 108개가 `verified` 입니다. 앞선 보고서는 한→영만 측정했습니다.
3. **가장 효과가 큰 것은 에이전트가 두 언어를 함께 넣는 것입니다.** 에이전트가 원문에 번역을 붙인 한 문자열로 검색하면 R@10 이 0.82~1.00 입니다. 질의 재작성은 코퍼스를 보지 않은 별도 서브에이전트가 했습니다.
4. **앞선 보고서의 초안 A 와 초안 E 는 그대로 합치면 서로 충돌합니다.** 초안 A 의 "질의어 절반 이상 일치" 규칙에서는 두 언어 질의의 한쪽 절반이 늘 맞지 않습니다. 그래서 용어집 없이 두 언어로 검색하면 한→영(KX) R@10 이 0.000 으로 무너집니다. 이 규칙을 **문자 종류(한글 / 그 밖)별로 따로 세도록** 바꾸면 0.821 로 돌아오고, 한 언어 질의의 성적은 그대로입니다.
5. **임베딩은 이 저장소에서 이득이 비용을 넘지 못합니다.** multilingual-e5-small 은 R@10 0.02~0.34 로 BM25 보다 낮았습니다. bge-m3 는 에이전트 도움 없이도 R@10 0.75~0.87 을 냈지만, 모델 560 MB, 색인 476 초, 메모리 5.4 GB 가 듭니다. 디스크 색인이 필요해 FR-MCP-064(검색은 아무것도 쓰지 않는다)와도 충돌합니다. 같은 수준의 품질을 에이전트의 두 언어 검색이 비용 없이 냅니다.
6. **권고: 문자 종류별 일치 규칙(초안 A 수정) + 대칭 이중 언어 검색 지침(초안 E 확대, 도구 설명문 포함).** 용어집(초안 B)은 5.2.0 에서 뺍니다. 에이전트가 두 언어로 검색할 때 용어집이 더하는 효과는 R@10 +0.00~+0.14 입니다. 반면 정확도가 낮고(표본 추정 약 28%), speckiwi 자신의 어휘만 덮고, 역방향으로 쓰면 영어 질의의 MRR 을 0.946 에서 0.885 로 낮춥니다.

## 3. 방법별 실측

### 3.1 공통 조건

엔진은 앞선 보고서의 하이브리드 구성입니다. 1단은 현재와 같은 구문 일치이고, 2단은 핵심 필드 BM25F(`id` 3, `title` 3, `tags` 2, `requirement` 1.5, `acceptanceCriteria` 1)입니다. 한글은 단어 안 2-gram 으로 나누고, 같은 단 안에서 DISCARDED 는 맨 뒤로 보냅니다. 용어집은 앞선 보고서에서 누설이 없던 `mined + blindNoEx` 입니다. 역방향 용어집은 그것을 뒤집은 영어 토큰 → 한글 단어 963항목입니다. 지표는 Recall@10, MRR, 10위 안에 정답이 없는 질의 수(miss), 평균 결과 수(avgN)입니다.

"절반 규칙"은 앞선 보고서 초안 A 의 AC-2 입니다. 질의 단어의 절반 이상이 맞아야 2단에 들어옵니다. "문자 종류별 규칙"은 이 연구에서 시험한 변형입니다. 한글 단어의 절반 이상이 맞거나, 한글이 아닌 단어의 절반 이상이 맞으면 들어옵니다.

### 3.3 읽는 법

- **도구 쪽 장치만으로는 절반을 놓칩니다(2행).** 한→영 R@10 0.48~0.51 이고, 영→한은 용어집 효과가 없어 0.375 에 머뭅니다. 0.375 를 만든 것은 용어집이 아니라 한글 AC 안에 섞인 영어 단어와 영어 제목입니다(§1.3).
- **영→한은 역방향 용어집으로 0.375 → 0.813 이 됩니다(3행).** 그러나 초안 B 의 AC-5 가 바로 이것을 금지합니다. 게다가 역방향 확장은 영어로 영어 요구를 찾는 대다수 질의의 순위를 흐립니다. 앞선 보고서의 영어 · 식별자 질의 23개에서 MRR 이 0.946 → 0.885, R@10 이 0.887 → 0.873 으로 내려갔습니다(`xbench-reg.json`).
- **에이전트가 번역을 붙이면 0.82~1.00 이 됩니다(6~15행).** 번역만 보낸 6행이 MRR 이 가장 높습니다. 다만 에이전트는 SRS 가 어느 언어로 쓰였는지 모르고, 번역만 보내면 원문의 식별자와 영어 용어를 잃습니다. 예: EX06 은 "lease holder" 를 "임대 보유자" 로 옮겨 10위 밖으로 밀렸습니다. 원문을 남기는 두 언어 한 문자열이 더 안전합니다.
- **절반 규칙은 두 언어 질의를 망가뜨립니다(7행).** 두 언어 한 문자열에서 영어 요구는 영어 단어만 맞습니다. 한국어 단어 수가 더 많으면 절반을 채우지 못합니다. 그래서 KX 는 정답을 하나도 찾지 못했고 평균 결과 수가 2건이었습니다. 앞선 보고서에서 두 언어 질의가 MRR 0.773 을 낸 것은 용어집이 한국어 단어를 "맞은 것"으로 세어 주었기 때문입니다(8행). **초안 E 의 효과가 초안 B 에 숨어서 기대고 있었던 것입니다.**
- **문자 종류별 규칙이 이 결합을 끊습니다(10행).** 용어집 없이도 KE 0.839, KX 0.821, EX 1.000 입니다. 한 언어 질의에서는 거의 같은 결과를 냅니다. 앞선 보고서의 한→한 18개가 R@10 0.944 / MRR 0.949(절반 규칙 0.944 / 0.944)이고, 영어 · 식별자 23개가 0.887 / 0.946(절반 규칙과 같음)입니다(`xbench-reg.json`, 용어집 없음). 한글 질의에 `MCP` 같은 영어 단어 하나가 섞인 경우에만 결과가 늘어납니다(앞선 KE, 용어집 사용 시 R@10 0.511 → 0.448).
- **용어집의 남은 기여(10행 → 11행):** KE +0.034, KX +0.143(놓친 질의 2개 → 0개), EX 0. 10행에서 놓친 두 질의는 KX06(18위)과 KX11(11위)이고, 용어집이 7위와 9위로 올렸습니다.
- **넓은 필드는 해롭습니다(4행).** Change Notes · 근거 · 증거를 더하면 한→영이 0.51 → 0.33 으로 떨어지고 결과 수만 두 배가 됩니다. 영→한은 그대로입니다. 같은 요구 안의 다른 필드를 연결점으로 쓰는 효과는 핵심 필드(제목 · 태그 · 본문 · AC)를 한 레코드로 색인하는 것만으로 이미 다 얻고 있습니다.
- **두 번 검색해서 합치는 방법(14 · 15행)은** R@10 은 비슷하지만 MRR 이 낮습니다. API 를 하나 더 만들어야 하는 데 비해 얻는 것이 없습니다.

## 5. 질의 확장을 에이전트에게 맡기기

- 검색을 부르는 쪽은 MCP `search_requirements` 를 쓰는 LLM 에이전트입니다. 에이전트는 두 언어를 모두 알기 때문에, 질의를 넓히는 일은 도구보다 에이전트 쪽이 더 잘합니다. §3.2 의 6 · 10 · 11행이 그 증거입니다.
- **지침이 들어갈 곳 [사실]:**
  - MCP 도구 설명문 `src/mcp/schemas.ts:256` 입니다. 이 설명은 speckiwi 스킬을 쓰지 않는 에이전트를 포함해 모든 MCP 클라이언트에 전달되므로, 지침이 닿는 범위가 가장 넓습니다.
  - 에이전트 지침 블록(`src/core/bootstrap/templates.ts`, 이 저장소의 `AGENTS.md` · `CLAUDE.md` 가 그 산출물입니다).
  - 검색을 부르는 스킬입니다. 지금은 kiwi-bug-repro 하나뿐입니다(`skills/claude/kiwi-bug-repro/SKILL.md:70`, codex `:72`, etc `:73`). 5.1.0 에서 kiwi-srs · kiwi-srs-feasibility · kiwi-srs-sync 가 "후보 요구를 먼저 좁히는" 단계를 넣으면(`CLAUDE.md` Releases 절) 이 스킬들도 부르는 쪽이 됩니다.
- **지침은 대칭이어야 합니다.** 앞선 보고서의 초안 E 는 "사용자가 한국어로 요청할 때 영어 단어를 더한다"로 한쪽 방향만 정했습니다. 그러나 중복 · 충돌 검사에서 질의는 새로 쓰는 영어 요구에서 나오고, 찾아야 할 기존 요구의 18%(검증된 계약 108개)는 한글 AC 를 갖고 있습니다(§1.2). 질의가 어느 언어로 쓰였든 다른 언어의 단어를 함께 넣어야 합니다.
- **API 를 늘리지 않습니다.** 문자열 하나에 두 언어를 넣는 방식(10행)이 `queries: [...]` 같은 다중 질의 인자(14 · 15행)보다 순위가 좋거나 비슷합니다. 진입점은 지금의 `query` 하나로 둡니다.
- **에이전트가 지침을 빠뜨리거나, 사람이 CLI 에 한국어만 넣는 경우 [사실]:** 1행처럼 한→영 R@10 이 0.02~0.05 로 떨어집니다. 이 빈틈은 용어집이 없으면 남습니다. 적어도 `speckiwi search --help` 와 MCP 설명문에 두 언어 예제를 넣어, 사람이 따라 할 수 있게 합니다.

## 6. 임베딩 · 벡터 검색

### 6.1 측정 방법

`@huggingface/transformers` 4.3.2(ONNX Runtime)를 scratchpad 에 설치하고, 양자화(q8) 모델로 CPU 에서 측정했습니다(`emb-bench.mjs`). 측정 단위는 두 가지입니다. "레코드" 는 제목 + 본문 + AC 를 한 문서로 만든 것이고, "AC 줄" 은 제목 + AC 한 줄을 한 조각으로 만들어 요구마다 가장 높은 조각 점수를 쓴 것입니다(4,811조각). DISCARDED 는 점수에서 1을 뺐습니다.

### 6.4 판정

- 품질만 보면 bge-m3 는 사람이 CLI 에 한국어만 넣는 경우까지 푸는 유일한 방법입니다. 하지만 같은 품질을 에이전트의 두 언어 검색이 비용 없이 냅니다.
- 색인을 호출마다 만들 수 없습니다(e5-small 60 초, bge-m3 476 초). 그래서 색인을 디스크에 두어야 하는데, 이는 `search_requirements` 가 아무것도 쓰지 않는다는 계약(FR-MCP-064)과 충돌합니다. 별도의 색인 명령과 그 무효화 규칙이 새로 필요해집니다.
- 런타임 의존성이 셋(`@modelcontextprotocol/sdk`, `commander`, `zod`)에서 네이티브 바이너리와 수백 MB 모델로 늘어납니다. "오프라인 · 빠른 로컬 CLI" 조건과 맞지 않습니다.
- 검색을 부르는 에이전트 자신이 질의 시점에 더 나은 다국어 의미 처리를 공짜로 해 줍니다(§3.2 의 6 · 10행).
- **결론: 5.2.0 에서 하지 않습니다.** 다시 꺼낼 조건은 두 가지입니다. 사람이 에이전트 없이 CLI 로 교차 언어 검색을 하는 일이 실제로 잦다는 근거가 생기거나, 수천 개 규모의 한국어 SRS 를 가진 프로젝트가 생기는 경우입니다.

## 8. 권고안

### 8.1 조합

**문자 종류별 일치 규칙을 넣은 하이브리드 검색(초안 A 수정) + 모든 검색에 두 언어를 넣으라는 대칭 지침(초안 E 확대)** 을 권고합니다. 지침은 도구 설명문, 에이전트 지침 블록, 검색을 부르는 스킬에 넣습니다. 용어집(초안 B)은 5.2.0 에서 뺍니다.

- 근거: §3.2 의 10행입니다. 데이터 파일 없이 R@10 이 KE 0.839, KX 0.821, EX 1.000 이고, 한 언어 질의의 성적은 변하지 않습니다.
- 버리는 것: 용어집이 더해 주는 KX +0.143 · KE +0.034 와, 사람이 CLI 에 한국어만 넣을 때의 교차 언어 검색입니다. 사람에게는 도움말 예제로 대신합니다.

### 8.2 5.2.0 요구 초안(등록하지 않음)

#### 초안 A′: 코어 랭킹 검색(구문 일치 우선, 한글 처리, 문자 종류별 일치) — 앞선 초안 A 를 대체

- 유형 · 범위: FR, NODE(`src/core/query/`)
- 제목: Ranked requirement search that keeps exact-phrase matches first and matches Korean and English query words separately
- Statement: The requirement search core SHALL return every record whose searched text contains the whole query ahead of records that match only some of the query's words, SHALL order each group by a field-weighted BM25 score with the requirement ID as tie-breaker, SHALL index Hangul text as in-word character bigrams, and SHALL judge word coverage separately for the Hangul and the non-Hangul words of the query so a query that carries both languages still reaches a record written in one of them.
- AC
  - AC-1: WHEN the whole query occurs case-insensitively in a record's searched fields, THE SYSTEM SHALL include that record and rank it ahead of every record that matches by words only.
  - AC-2: WHEN a record does not contain the whole query but matches at least half of the query's Hangul words, or at least half of the query's other words, in its ID, title, tags, statement or acceptance criteria, THE SYSTEM SHALL include it after the phrase matches, ordered by descending BM25F score, with equal scores ordered by ascending requirement ID.
  - AC-3: WHEN a query or a record contains Hangul, THE SYSTEM SHALL split each run of Hangul syllables into its in-word character bigrams (a one-syllable run stays whole) for both indexing and querying, so that a query differing from the record only by attached particles or by spacing (for example "저장소의 루트를" or "저장소루트" for "저장소 루트") still matches it.
  - AC-4: WHEN the query `리뷰 루프를 끄는 옵션은 무시하지 않고 거부한다 an option that turns off the review loop is rejected, not ignored` is searched on this repository's SRS, THE SYSTEM SHALL return FR-FLOW-135 within the first ten results, and WHEN `no database setup is needed to use it in a new repository 새 저장소에서 쓰는 데 데이터베이스 설정이 필요 없다` is searched, THE SYSTEM SHALL return CON-ARCH-002 within the first ten results (회귀 고정용 대표 질의. 측정 결과: 문자 종류별 규칙에서는 각각 2위와 1위이고, 절반 규칙에서는 각각 FR-FLOW-135 가 빠진 2건과 0건이다. 그래서 규칙을 절반 규칙으로 되돌리면 이 AC 가 실패한다. 구현할 때 KX · EX 에서 3~5개로 늘린다).
  - AC-5: WHEN a matching record is DISCARDED, THE SYSTEM SHALL rank it after every non-discarded record of the same group.
  - AC-6: WHEN a record is returned, THE SYSTEM SHALL report its match kind (`phrase` or `terms`), the query words it matched and its score beside the existing fields, and every snippet SHALL contain a matched term.
  - AC-7: WHEN the caller asks for exact matching, THE SYSTEM SHALL return only the phrase matches in requirement ID order with no default limit, identical to the result before this requirement.
- 앞선 초안 A 와의 차이: AC-2 의 일치 판정을 문자 종류별로 나눴고, 두 언어 회귀 질의(AC-4)를 더했습니다. 나머지는 같습니다.

#### 초안 E′: 대칭 이중 언어 검색 지침 — 앞선 초안 E 를 대체

- 유형 · 범위: FR, FLOW(MCP 도구 설명문, 에이전트 지침 블록, 검색을 부르는 스킬)
- 제목: Every requirement search an agent sends carries the query's words in both Korean and English
- Statement: The `search_requirements` tool description, the agent instruction block, and every shipped skill that tells an agent to search requirements SHALL tell the agent to keep the words it would search for and add their equivalents in the other language (Korean for English, English for Korean) in the same query string, whatever language the request or the draft requirement is written in.
- AC
  - AC-1: WHEN an MCP client lists the tools, THE `search_requirements` description SHALL state that one query string carries both the original words and their equivalents in the other language, and SHALL give one example that pairs Korean and English words.
  - AC-2: WHEN the agent instruction block or a shipped skill tells the agent to call `search_requirements` or `speckiwi search`, THE SYSTEM SHALL state the same rule in the same place, for both directions (a Korean request gains English words; an English request or an English draft requirement gains Korean words).
  - AC-3: WHEN `speckiwi search --help` runs, THE SYSTEM SHALL show one example query that carries Korean and English words together.
  - AC-4: THE SYSTEM SHALL keep that rule's wording identical across the skill renderings that carry it (기존 미러 · 드리프트 검사 대상에 넣는다).
- 앞선 초안 E 와의 차이: 방향을 대칭으로 넓혔고, 지침이 닿는 범위가 가장 넓은 도구 설명문과 CLI 도움말을 넣었습니다.

### 8.4 구현 때 확인할 것

- AC-2 의 "한글 단어" 는 질의를 앞선 보고서의 단어 경계 규칙(`[A-Za-z0-9_][A-Za-z0-9_\-./]*` 또는 연속 한글)으로 나눈 단위입니다. 영어 불용어만 남은 단어는 세지 않습니다. 이 정의를 테스트로 고정합니다.
- `--zzz-no-such-flag-anywhere` 는 문자 종류별 규칙에서도 166건을 돌려줍니다(`xbench-reg.json` 의 `absentFlag`). 앞선 보고서 §9.4 의 IR-CLI-100 AC-5 처리(테스트 질의 교체, verified 요구 하향 → 수정 → Change Notes → 재승격)가 그대로 필요합니다.
- 두 언어 질의는 결과 수가 늘어납니다(평균 44~143건, §3.2 10행). 초안 C 의 기본 상한 20 이 함께 들어가야 합니다.

## 9. 한계

- KX · EX 질의는 본 연구자가 AC 를 읽은 뒤 썼습니다. 정답 AC 의 단어 쪽으로 치우쳤을 수 있습니다. 에이전트 재작성은 코퍼스를 보지 않은 서브에이전트가 했지만, 한 모델이 한 번 만든 결과입니다. 표본이 50개이므로 0.05 안팎의 차이는 잡음으로 봐야 합니다.
