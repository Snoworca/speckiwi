## 1. Purpose

SpecKiwi는 Git 저장소 안의 Markdown SRS 문서를 요구사항의 원본으로 사용하고, Node.js 기반 CLI와 stdio MCP server를 통해 요구사항 검색, 검증, 상태 갱신, evidence 연결, target summary를 제공하는 개발 workflow 도구다.

SpecKiwi v1.0.0의 제품 경계는 다음과 같다.

- 요구사항 원본은 `docs/spec/**/*.srs.md` Markdown 문서다.
- YAML front matter, YAML 요구사항 파일, YAML export를 사용하지 않는다.
- 별도 데이터베이스나 요구사항 서버를 사용하지 않는다.
- CLI와 MCP server는 동일한 core parser, validator, query, mutation service를 사용한다.
- MCP는 v1.0.0에서 stdio transport를 지원한다.
- 구현은 Node.js LTS 기반 TypeScript ESM 패키지로 진행한다.

### Target: 2.5.2-phase1-target-lifecycle

**Goal:** Make the tool honour the target lifecycle its own shipped rules define. The type vocabulary is stated once and matches the rules document's six values. A target that is finished can be recorded as completed or released rather than silently demoted to planned when the active target moves, and the eleven rows this repository already carries in that false state can be repaired.

### Target: 2.6.0-phase1-kiwi-orchestrator

**Goal:** Ship kiwi-orchestrator phase 1 and the --auto contract change it exercises. The skill carries work from an unclear intent to merged, verified code: intake that deepens a thin design, wave decomposition, English handoff documents written for coding agents, per-task parallelisability analysis produced in full, and scale/scope routing across R-PLAN, R-STEP and R-ORCH. Execution is serial at the host root; concurrent lane execution is 2.6.0-phase2-parallel-lanes.

### Target: v2.5.1

**Goal:** Give an existing project one command that brings it fully current. `speckiwi init` refreshes tool-owned artifacts only, by contract, so two upgrade gaps survive it: a reference to a rules document this release pruned is left dangling, and an index with no Rules row never gets one. `speckiwi upgrade` closes both as an explicit opt-in migration that defaults to dry-run — it reports its plan, never renumbers a scope document, never rewrites a requirement body, and never overwrites a hook.

### Target: v2.5.0

**Goal:** Make the tool's own contract truthful and its scaffolding predictable. The bundled authoring rules move to 2.5.0 and document every syntax the runtime writes — checked_compatible and its Notes grammar, the DISCARDED and DRAFT heading markers, the Completed Work Log dual-source rules — so following the installed rules never reverts tool-written content. Scope documents are numbered one above the highest in use, starting at 01, with collisions reported.

### Target: v2.4.4

**Goal:** Make a design document alone sufficient to drive kiwi-wave-master from wave-1 to completion without avoidable stops, verified against the design itself rather than only the derived SRS, while protecting the existing architecture. Adds a design baseline and decomposition coverage gate, all-wave final verification, target registration and wave-internal resume, unattended-run continuity fixes, and existing-structure guards.

### Target: v2.4.3

**Goal:** kiwi-wave-master end-of-wave cross-verification: before a wave is marked complete, two isolated verifiers evaluate one pinned wave-evidence bundle from differentiated stances (intent realization plus process conformance; artifact quality plus cross-wave regression), cross-refute add-only, and drive a bounded remediation loop delegated to kiwi-review-fix-loop. Adds waves-event optional verification fields and a critical_gates declaration.

### Target: v2.4.2

**Goal:** Make wave/pipeline runs fail closed when the session's SpecKiwi MCP workspace root does not match the run's git root, pin wave/pipeline event journals to the run root decided at run start, and replace the non-existent `restart_mcp_server` recovery hint with actionable guidance. Scope excludes multi-root runtime hosting, MCP per-call root overrides, and any merge or disposal of the unmerged wave-master multiroot branch.

### Target: v2.4.1

**Goal:** Extend `speckiwi init` with a `--global`/`-g` option that additionally installs/updates the bundled kiwi skills into each present coding agent's global skills directory (Claude `~/.claude/skills`, Codex `${CODEX_HOME:-~/.codex}/skills`), gated per-agent by agent-home presence — an absent agent is skipped with a warning and no global dir is created. Project-scope provisioning is unchanged.

### Target: v2.4.0

**Goal:** TDD First mode: add a tdd work-mode where a step-scoped task proceeds research -> SDS (docs/spec/steps/<task>/design.md, EARS acceptance contracts) -> red tests -> green implementation -> regression -> post-hoc SRS promotion with mandatory evidence links. Gates: tdd enforcement parity with vibe (mode/vibe-gate/completion gate), promote evidence gate, agent snippet v1.5 atomic rollout, kiwi-tdd skill. Existing-body-REQ edits and large architecture changes stay in sdd mode.

### Target: v2.3.0

**Goal:** Tool improvement release. Focus v2.3.0 work on making SpecKiwi tools more reliable, ergonomic, diagnosable, and safer in real project use before expanding non-tool surface area.

### Target: v2.2.3

**Goal:** Govern Kiwi skill install/migration. All Kiwi skills require working speckiwi mcp for normal SRS read/mutation/validation/status/evidence flows. CLI installs Codex, Claude, OpenCode, Hermes skills with --global/-g. OpenCode/Hermes local-LLM variants use skills/etc, not skills/llm; default --max, single subagent/evaluator, stop after 3 clean evaluations.
