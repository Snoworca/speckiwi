## 1. Scope Overview

이 문서는 SpecKiwi v1.0.0의 Node.js LTS 기반 TypeScript ESM 구현 구조, core module, patch engine, testing, package scripts를 정의한다.

## 2. Scope Boundaries

### In Scope

- Node.js LTS runtime
- TypeScript ESM package
- core module layout
- line-based patch engine
- MCP SDK adapter
- CLI adapter
- test fixtures and scripts

### Out of Scope

- 브라우저 런타임
- CommonJS dual package
- Rust/Python 구현
- 웹 서버 제품화
- 데이터베이스 저장소

## 3. Assumptions and Constraints

- Node.js 24 LTS를 권장한다.
- package metadata는 `package.json`에 둔다.
- MCP SDK 의존성은 adapter에 격리한다.

#### Requirement

SpecKiwi core는 CLI와 MCP가 공유하는 프로젝트 초기화 bootstrap service를 제공해야 한다.

#### Rationale

SRS 구조 생성은 파일 시스템을 변경하는 mutation이므로 CLI와 MCP adapter가 각자 구현하지 않고 같은 템플릿, 경로 안전성, 중복 삽입 방지 정책을 사용해야 한다.

#### Acceptance Criteria

- [x] AC-1: service input은 root를 필수로 받고 target, scope, force를 선택적으로 받는다.
- [x] AC-2: service는 root 내부의 `docs/`, `docs/spec/`, `docs/rule/` 구조를 확인하고 없으면 생성한다.
- [x] AC-3: `docs/spec/00.index.md`가 없으면 요구사항이 없는 기본 SRS index 문서를 생성한다.
- [x] AC-4: `docs/spec/90.appendix.md`가 없으면 기본 appendix 문서를 생성한다.
- [x] AC-5: `docs/rule/SRS-MD-Rules-v1.0.0.md`가 없으면 canonical SRS-MD rules 문서를 생성한다.
- [x] AC-6: service는 대문자 `AGENTS.md`와 `CLAUDE.md`를 항상 생성 또는 갱신한다.
- [x] AC-7: agent 안내 문장은 `docs/spec/` SRS 구조를 간단히 설명하고 상세 규칙 링크로 `docs/rule/SRS-MD-Rules-v1.0.0.md`를 포함한다.
- [x] AC-8: service는 동일한 SpecKiwi agent 안내 또는 rules 링크가 이미 있으면 중복 삽입하지 않는다.
- [x] AC-9: service는 `force`가 없으면 기존 파일을 덮어쓰지 않고 skipped path로 보고한다.
- [x] AC-10: service는 root 밖 경로 쓰기를 거부하고 shell command를 실행하지 않는다.
- [x] AC-11: service result는 created, skipped, updated path 목록과 diagnostics를 포함한다.
- [x] AC-12: MCP server startup은 이 service를 사용해 `docs/spec/00.index.md`가 없는 root를 자동 초기화한다.
