## 1. Scope Overview

이 문서는 SpecKiwi v1.0.0의 Node.js LTS 기반 TypeScript ESM 구현 구조, core module, patch engine, testing, package scripts를 정의한다.

## 2. Scope Boundaries

### In Scope

- Node.js LTS runtime
- TypeScript ESM package
- core module layout
- line-based patch engine
- MCP SDK adapter
- CLI adapter
- test fixtures and scripts

### Out of Scope

- 브라우저 런타임
- CommonJS dual package
- Rust/Python 구현
- 웹 서버 제품화
- 데이터베이스 저장소

## 3. Assumptions and Constraints

- Node.js 24 LTS를 권장한다.
- package metadata는 `package.json`에 둔다.
- MCP SDK 의존성은 adapter에 격리한다.

### FR-NODE-016 — Kiwi skill installation core service

| Field | Value |
| --- | --- |
| Type | functional |

| Tags | skills, install, core, utf-8, local-llm |

#### Requirement

SpecKiwi core must provide a reusable skill installation service that copies validated repository-managed Kiwi skill trees from canonical source roots into agent-specific project or global skill directories while preserving UTF-8 content, relative resources, safe paths, dry-run diagnostics, and conflict controls.

#### Rationale

The CLI and future MCP or automation surfaces should not each implement their own skill-copy logic. A shared core service keeps install paths, safety checks, dry-run behavior, and validation consistent while allowing the repository to maintain separate canonical source trees for Codex, Claude, and OpenCode/Hermes local-LLM variants.

#### Acceptance Criteria

- [x] AC-1: The service accepts an explicit target agent value at minimum for Codex, Claude, OpenCode, and Hermes, and resolves the canonical source root for each supported target.
- [x] AC-2: The service treats `skills/etc` as the canonical source root for OpenCode and Hermes local-LLM Kiwi variants and must not create or require a `skills/llm` source root.
- [x] AC-3: The service supports project-local installation, global installation, and a safe custom destination root, with global paths resolved per target agent, Hermes global installs scoped by category, and no reliance on locale-dependent path handling.
- [x] AC-4: The service validates each selected skill directory before copying, including required `SKILL.md` or an explicitly supported legacy source entrypoint normalization to installed `SKILL.md`, frontmatter name matching the directory, UTF-8 readability, and referenced `scripts`, `references`, or `assets` that must remain reachable after install.
- [x] AC-5: The service reports a deterministic dry-run plan that includes source root, destination root, operation (`install`, `update`, `skip`, or `conflict`), copied files, skipped files, removed stale files, conflicts, and an MCP preflight status of `satisfied`, `missing`, or `not_checked`.
- [x] AC-6: The service treats an existing valid same-identity destination skill as an `update`, treats a byte-identical destination as `skip`, refuses unsafe or non-skill destination conflicts, and conflict results must not partially copy a skill.
- [x] AC-7: The service rejects path traversal, absolute-path injection inside skill names, unsupported target names, and non-directory skill sources before any file mutation.
- [x] AC-8: The service preserves executable helper scripts and relative resource layout without rewriting skill content unless a separate migration or documented install-time entrypoint normalization step explicitly owns that transformation.
- [x] AC-9: The distributed package includes the canonical bundled skill source roots required by the installer (`skills/codex`, `skills/claude`, and `skills/etc`) or returns a structured source-unavailable error before planning any destination mutation.
