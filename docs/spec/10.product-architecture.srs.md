## 1. Scope Overview

이 문서는 SpecKiwi v1.0.0의 제품 경계, Markdown-only 원본성, local-first architecture, CLI와 MCP의 공통 core 구조를 정의한다.

## 2. Scope Boundaries

### In Scope

- Markdown SRS source of truth
- YAML 미사용 정책
- 별도 DB 없는 저장소 로컬 동작
- CLI와 MCP가 공유하는 core service
- 최소 변경과 안전한 mutation 원칙

### Out of Scope

- 구체적인 CLI 명령별 option semantics
- 구체적인 MCP tool input schema
- Node.js package file layout 세부 구현

## 3. Assumptions and Constraints

- 요구사항 원본은 Markdown 문서다.
- JSON 출력은 파생 결과다.
- Node.js package metadata는 `package.json`으로 관리할 수 있다.

## 4. Requirements

#### Requirement

SpecKiwi는 요구사항 원본 저장 형식으로 `docs/spec/**/*.srs.md` Markdown 문서만 사용해야 한다.

#### Rationale

팀원이 별도 데이터 저장 형식이나 변환 규칙을 학습하지 않고 Git에서 직접 요구사항을 읽고 수정할 수 있어야 한다.

#### Acceptance Criteria

- [x] AC-1: 요구사항 원본 파일은 `.srs.md` 또는 `00.index.md` Markdown 문서로 존재한다.
- [x] AC-2: 요구사항 원본으로 YAML 파일, YAML front matter, YAML export 파일을 생성하지 않는다.
- [x] AC-3: 요구사항 상태, target, evidence는 Markdown Requirement Block 안에서 관리된다.

#### Requirement

SpecKiwi는 요구사항을 저장하기 위해 별도 데이터베이스, 서버 저장소, 동기화 저장소를 요구하지 않아야 한다.

- [x] AC-3: MCP 서버는 세션 중 in-memory index를 만들 수 있지만 이를 영속 저장소로 사용하지 않는다.

### FR-ARCH-002 — 저장소 루트 자동 탐지

| Field | Value |
| --- | --- |
| Type | functional |
| Target | v1.0.0 |
| Status | verified |
| Priority | high |
| Tags | root-detection, git, local |
| Risk | medium |
| Stability | stable |
| Verification Method | test |
| GitHub Issue | - |
| Related Docs | - |

#### Requirement

SpecKiwi는 명령 실행 위치에서 상위 디렉터리로 탐색하여 Git 저장소 루트 또는 `docs/spec/00.index.md`가 있는 프로젝트 루트를 자동 탐지해야 한다.

#### Rationale

사용자는 매번 `--root`를 지정하지 않고도 저장소 내부 어디서든 명령을 실행할 수 있어야 한다.

#### Acceptance Criteria

- [x] AC-1: 현재 디렉터리부터 상위로 `.git` 또는 `docs/spec/00.index.md`를 탐색한다.
- [x] AC-2: `--root`가 지정되면 자동 탐지보다 우선한다.
- [x] AC-3: 일반 CLI 조회/변경 명령은 루트를 찾지 못하면 exit code `2`와 명확한 오류 메시지를 출력한다.
- [x] AC-4: `speckiwi mcp`도 `--root`가 없으면 server process의 현재 작업 디렉터리에서 같은 root 탐지를 수행한다.
- [x] AC-5: MCP server startup에서는 루트를 찾지 못한 빈 작업 디렉터리를 현재 디렉터리 root로 간주하고 SRS 기본 구조를 자동 생성한다.
- [x] AC-6: MCP server startup에서 명시적 `--root`가 주어지면 해당 경로는 존재하는 디렉터리여야 하며, 존재하지 않는 경로를 자동 생성하지 않는다.

| Status | verified |

| Tags | safety, command-model, mutation |
| Risk | medium |

#### Requirement

SpecKiwi는 요구사항 조회 명령과 문서 변경 명령을 명확히 분리해야 한다.

#### Rationale

AI agent가 실수로 문서를 변경하는 일을 줄이려면 read-only operation과 mutation operation이 인터페이스 수준에서 구분되어야 한다.

#### Acceptance Criteria

- [x] AC-1: 조회 명령은 파일을 변경하지 않는다.
- [x] AC-2: 쓰기 명령은 변경 대상 Requirement ID를 필수로 받는다.
- [x] AC-3: 쓰기 명령은 실패 시 문서를 변경하지 않는다.
- [x] AC-4: MCP tool metadata에는 read-only 여부가 구분되어야 한다.
