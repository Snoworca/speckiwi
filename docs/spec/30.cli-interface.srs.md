## 1. Scope Overview

이 문서는 `speckiwi` Node.js CLI의 명령, 옵션, 출력, mutation behavior, exit code 정책을 정의한다.

## 2. Scope Boundaries

### In Scope

- CLI entrypoint
- init, validate, extract, list, show, targets, scopes
- status, AC, evidence, trace mutation 명령
- summary, links check, mcp launcher
- exit code와 output format

### Out of Scope

- 웹 UI
- 대화형 TUI
- 원격 서버 API
- YAML export/import

## 3. Assumptions and Constraints

- CLI는 Node.js package bin으로 제공된다.
- CLI는 core service를 호출한다.
- 쓰기 명령은 최소 변경 원칙을 따른다.

SpecKiwi는 `speckiwi init` 명령으로 새 저장소에 SRS와 rule 기본 구조를 생성해야 한다.

#### Rationale

새 프로젝트 적용 시 사용자는 수동으로 모든 문서와 agent 규칙을 만들지 않아야 한다.

#### Acceptance Criteria

- [x] AC-1: `speckiwi init`은 project root의 `docs/`, `docs/spec/`, `docs/rule/` 구조를 확인하고 없으면 생성한다.
- [x] AC-2: `docs/spec/00.index.md`가 없으면 요구사항이 없는 기본 SRS index 문서를 생성한다.
- [x] AC-3: `docs/spec/90.appendix.md`가 없으면 기본 appendix 문서를 생성한다.
- [x] AC-4: `docs/rule/SRS-MD-Rules-v1.0.0.md`가 없으면 canonical SRS-MD rules 문서를 생성한다.
- [x] AC-5: `speckiwi init`은 대문자 `AGENTS.md`를 항상 생성 또는 갱신한다.
- [x] AC-6: `speckiwi init`은 대문자 `CLAUDE.md`를 항상 생성 또는 갱신한다.
- [x] AC-7: agent 파일에 추가되는 문장은 `docs/spec/` SRS 구조를 간단히 설명하고 상세 규칙 링크로 `docs/rule/SRS-MD-Rules-v1.0.0.md`를 포함한다.
- [x] AC-8: 동일한 SpecKiwi agent 안내 또는 rules 링크가 이미 있으면 중복 삽입하지 않는다.
- [x] AC-9: 기존 파일이 있으면 기본적으로 덮어쓰지 않는다.
