## 1. Scope Overview

이 문서는 SpecKiwi stdio MCP server의 transport, tools, resources, security boundary, 오류 응답을 정의한다.

## 2. Scope Boundaries

### In Scope

- stdio MCP server
- read-only MCP tools
- mutation MCP tools
- project initialization MCP tool
- MCP resources
- MCP safety and filesystem boundary
- structured errors

### Out of Scope

- Streamable HTTP MCP server
- OAuth 또는 원격 인증
- 외부 웹 API 호출
- shell command execution
- MCP client 구현

## 3. Assumptions and Constraints

- MCP server는 `speckiwi mcp`로 실행된다.
- stdout은 JSON-RPC MCP message 전용이다.
- stderr는 log 전용이다.
- MCP server는 core service를 사용한다.

#### Requirement

SpecKiwi는 stdio transport를 사용하는 MCP server를 제공해야 한다.

#### Rationale

AI coding agent가 별도 CLI 사용법을 외우지 않고 표준 MCP tool 호출로 SRS를 사용할 수 있어야 한다.

#### Acceptance Criteria

- [x] AC-1: `speckiwi mcp`가 MCP server process를 시작한다.
- [x] AC-2: server는 stdin에서 JSON-RPC 메시지를 읽고 stdout으로 응답한다.
- [x] AC-3: stdout에는 MCP 메시지 이외의 로그를 쓰지 않는다.
- [x] AC-4: 로그와 diagnostics는 stderr에 쓴다.
- [x] AC-5: MCP client가 `--root` 없이 server를 등록해도 server process의 현재 작업 디렉터리를 기준으로 project root를 결정한다.
- [x] AC-6: server startup 시 `docs/spec/00.index.md`가 없으면 MCP tool 또는 resource 요청을 처리하기 전에 SRS 기본 구조를 자동 생성한다.
- [x] AC-7: `.git`과 `docs/spec/00.index.md`를 모두 찾을 수 없는 빈 작업 디렉터리에서는 server process의 현재 작업 디렉터리를 project root로 삼아 자동 init한다.
- [x] AC-8: 명시적 `--root`가 존재하지 않거나 디렉터리가 아니면 자동 init 대상이 아니며 server startup은 오류를 반환한다.

#### Implementation Notes

- MCP 공식 stdio transport 규칙을 따른다.
- Streamable HTTP transport는 v1.0.0 범위 밖이다.
- `--root`가 생략되면 `process.cwd()`에서 시작해 `.git` 또는 `docs/spec/00.index.md`가 있는 상위 디렉터리를 project root로 사용한다.
- root를 찾지 못하면 `process.cwd()` 자체를 root로 삼아 `initProject` bootstrap을 실행한다.
- 명시적 `--root`는 존재하는 directory만 허용한다. 존재하지 않는 명시 root는 오타 가능성이 있으므로 자동 생성하지 않는다.
- 자동 init은 server startup에서 수행해 read-only tool handler 자체가 정상 workspace에서는 파일을 변경하지 않게 한다.

| 2026-05-09 | MCP startup 자동 init 요구 추가 | index 누락 또는 빈 작업 디렉터리에서도 첫 MCP 호출이 실패하지 않게 함 |
