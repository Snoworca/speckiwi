## 1. CLI Command Reference

### 1.1 Global Usage

```text
speckiwi <command> [options]
```

Common options:

| Option | Meaning |
|---|---|
| `--root <path>` | Project root. If omitted, SpecKiwi searches upward for `.git` or `docs/spec/00.index.md`. |
| `--json` | Print machine-readable JSON to stdout. |
| `--no-color` | Disable ANSI color. |
| `--quiet` | Reduce non-essential output. |
| `--help` | Print command help. |
| `--version` | Print package version. |

### 1.2 Commands

| Command | Mutates Files | Purpose |
|---|---:|---|
| `speckiwi init` | yes | Create SRS/rule directories, index, appendix, rules, optional agent file. |
| `speckiwi validate` | no | Validate SRS-MD documents. |
| `speckiwi extract` | no | Extract normalized requirement records. |
| `speckiwi list` | no | List requirements by filter. |
| `speckiwi show <id>` | no | Show one requirement. |
| `speckiwi targets` | no | Show target map and counts. |
| `speckiwi scopes` | no | Show scope map and counts. |
| `speckiwi add-requirement` | yes | Add a new Requirement Block to a scope SRS document. |
| `speckiwi update-status <id> <status>` | yes | Update metadata `Status` row. |
| `speckiwi check-ac <id> <ac-id...>` | yes | Mark Acceptance Criteria as checked. |
| `speckiwi uncheck-ac <id> <ac-id...>` | yes | Mark Acceptance Criteria as unchecked. |
| `speckiwi add-evidence <id>` | yes | Add Verification Evidence row. |
| `speckiwi add-trace <id>` | yes | Add Trace Links row. |
| `speckiwi summary --target <target>` | no | Print target readiness summary. |
| `speckiwi links check` | no | Check local links and requirement references. |
| `speckiwi mcp` | no by itself | Start stdio MCP server. MCP mutation tools may modify files. |

### 1.3 Command Details

#### `speckiwi init`

```text
speckiwi init [--root <path>] [--target <target>] [--scope <name:prefix>] [--agent-file <agents|claude|both|none>] [--force]
```

Behavior:

- Checks `docs/`, `docs/spec/`, and `docs/rule/`, then creates missing directories.
- Creates `docs/spec/00.index.md` as an empty SRS index when absent.
- Creates `docs/spec/90.appendix.md` when absent.
- Creates `docs/rule/SRS-MD-Rules-v1.0.0.md` from the bundled rules template when absent.
- Can create or append uppercase `AGENTS.md` and/or `CLAUDE.md`.
- Skips agent text insertion when the SpecKiwi rules link already exists.
- Does not overwrite existing files unless `--force` is set.

#### `speckiwi validate`

```text
speckiwi validate [--root <path>] [--strict] [--fail-on-warning] [--scope <scope>] [--target <target>] [--json]
```

Exit behavior:

- `0`: no errors.
- `1`: validation errors, or warnings with `--fail-on-warning`.
- `2`: invalid arguments.
- `3`: file I/O failure.
- `4`: fatal parse failure.

#### `speckiwi extract`

```text
speckiwi extract [--target <target>] [--status <status>] [--scope <scope>] [--type <type>] [--tag <tag>] [--json] [--include-markdown]
```

#### `speckiwi list`

```text
speckiwi list [--target <target>] [--status <status>] [--scope <scope>] [--type <type>] [--tag <tag>] [--format <plain|table|json>]
```

#### `speckiwi show`

```text
speckiwi show <RequirementID> [--json] [--markdown]
```

#### `speckiwi add-requirement`

```text
speckiwi add-requirement --type <Type> --scope <Scope> --target <Target> --title <Title> --requirement <Text> --ac <Text> [--ac <Text>...] [--checked-ac <Text>...] [--status <Status>] [--priority <Priority>] [--tags <Tags>] [--risk <Risk>] [--stability <Stability>] [--verification-method <Method>] [--rationale <Text>] [--implementation-notes <Text>] [--evidence <JSON>] [--trace <JSON>] [--dry-run] [--json]
```

Behavior:

- Generates the next Requirement ID from type prefix and scope prefix.
- Appends the generated Requirement Block to the end of the target scope document's `## 4. Requirements` section.
- Defaults `Status` to `planned` when omitted.
- Rejects `verified` unless every AC is checked and at least one Verification Evidence row has a non-empty reference.

#### `speckiwi update-status`

```text
speckiwi update-status <RequirementID> <Status> [--dry-run] [--reason <text>] [--json]
```

Allowed statuses:

```text
planned
in_progress
blocked
implemented
verified
discarded
```

`verified` guard:

- All Acceptance Criteria must be checked.
- Verification Evidence must contain at least one row.
- Evidence reference must not be empty.

#### `speckiwi check-ac`

```text
speckiwi check-ac <RequirementID> <AC-ID...> [--all] [--dry-run] [--json]
```

Examples:

```text
speckiwi check-ac FR-AUTH-001 AC-1 AC-2
speckiwi check-ac FR-AUTH-001 --all
```

#### `speckiwi add-evidence`

```text
speckiwi add-evidence <RequirementID> --type <Type> --ref <Reference> --covers <AC-ID|all> [--notes <text>] [--dry-run] [--json]
```

Example:

```text
speckiwi add-evidence FR-AUTH-001 --type Test --ref src/test/AuthSessionExpirationTest.ts --covers AC-1 --notes "세션 만료 API 테스트"
```

#### `speckiwi add-trace`

```text
speckiwi add-trace <RequirementID> --type <Type> --ref <Reference> --relation <Relation> [--notes <text>] [--dry-run] [--json]
```

#### `speckiwi summary`

```text
speckiwi summary --target <target> [--json] [--markdown]
```

#### `speckiwi mcp`

```text
speckiwi mcp [--root <path>] [--transport stdio]
```

Rules:

- Default transport is `stdio`.
- stdout is reserved for MCP JSON-RPC messages.
- stderr is used for logs.
- The server must not print banners or human-readable logs to stdout.

## 2. Exit Codes

| Code | Meaning |
|---:|---|
| `0` | Success |
| `1` | Validation error |
| `2` | Usage, argument, or root resolution error |
| `3` | File I/O error |
| `4` | Fatal parse error |
| `5` | Mutation denied, status transition denied, or verified guard failure |
| `6` | MCP server fatal error |

## 9. AGENTS.md / CLAUDE.md Addition

```md
# SpecKiwi SRS workflow

This repository uses SpecKiwi to maintain requirements as Git-tracked Markdown SRS documents under `docs/spec/`. The SRS document set starts at `docs/spec/00.index.md`; scope requirements live in `docs/spec/**/*.srs.md`; authoring and parsing rules live in `docs/rule/`. Read [SRS-MD Authoring Rules v1.0.0](docs/rule/SRS-MD-Rules-v1.0.0.md) and start from [SpecKiwi Product SRS Index](docs/spec/00.index.md) before creating, modifying, implementing, or verifying requirements.

Requirements are Markdown-only. Do not create YAML requirement files, YAML front matter, requirement databases, or alternate source-of-truth files. JSON output from SpecKiwi commands is a derived view, not the canonical source.

When implementing a feature, first find the relevant Requirement Block from `docs/spec/00.index.md` and the scope SRS file. A Requirement Block starts with `### {RequirementID} — {Title}` and must preserve its heading, metadata table, and fixed section names.

Use the repo-local or package CLI when available: `speckiwi init`, `speckiwi validate`, `speckiwi list`, `speckiwi show <id>`, `speckiwi add-requirement`, `speckiwi update-status <id> <status>`, `speckiwi check-ac <id>`, `speckiwi add-evidence <id>`, and `speckiwi summary --target <target>`.

If an MCP server is configured, prefer the SpecKiwi MCP tools for requirement lookup and safe updates: `init_project`, `list_requirements`, `get_requirement`, `validate_spec`, `add_requirement`, `update_status`, `check_acceptance_criteria`, `add_verification_evidence`, `add_trace_link`, and `summarize_target`. The MCP server is started with `speckiwi mcp` and uses stdio transport.

Do not rewrite entire SRS documents. Modify only the relevant Requirement Block unless broader restructuring is explicitly requested. Do not change Requirement IDs, reuse discarded IDs, invent evidence, create nonexistent links, or replace the required Markdown structure with another format.

Allowed statuses are `planned`, `in_progress`, `blocked`, `implemented`, `verified`, and `discarded`. Use `implemented` when code appears complete but verification evidence is incomplete. Use `verified` only when every Acceptance Criteria item is checked and Verification Evidence is present.

After implementation, add test, code, PR, review, analysis, demo, or monitoring evidence under `#### Verification Evidence`, update relevant Acceptance Criteria, and then update Status only if the required verification conditions are satisfied.
```
